# SDK страницы RWD (`sdk/`)

Один JS-файл, который загружает WebView приложения или H5-страница, чтобы ИИ-агент мог изучать страницу и работать с ней через шлюз RWD (`gateway/`) и MCP. Протокол: [`docs/protocol.ru.md`](../docs/protocol.ru.md); архитектура: [`docs/architecture.ru.md`](../docs/architecture.ru.md).

```html
<script src="https://cdn.jsdelivr.net/npm/remote-webview-debugger@0.2.0/dist/sdk.js"></script>
<script>
  RemoteWebviewDebugger.run("https://rwd.example.com/v1", "rwd_pk_xxxxxxxx", {
    userId: "u-42",              // необязательно
    deviceId: "…",               // необязательно; передаёт нативный хост, внедряющий SDK
    helpButton: true,            // необязательно; показать кнопку «Запросить поддержку»
    app: { name: "Shop", version: "3.2.0" },
    lang: "en",                  // необязательно; тег языка, по умолчанию из языков браузера
  }).then(({ deviceCode, status }) => console.log(deviceCode, status))
</script>
```

## Как получить SDK

Опубликован в npm как [`remote-webview-debugger`](https://www.npmjs.com/package/remote-webview-debugger); версии и изменения: [CHANGELOG](CHANGELOG.md).

| Способ | Откуда |
|---|---|
| `<script>` с CDN | `https://cdn.jsdelivr.net/npm/remote-webview-debugger@0.2.0/dist/sdk.js` или `https://unpkg.com/remote-webview-debugger@0.2.0/dist/sdk.js` (минифицированный IIFE, глобальная переменная `RemoteWebviewDebugger`; закрепите версию и, если хотите, добавьте `integrity`) |
| Сборщик | `npm install remote-webview-debugger`, затем `import { run, status } from 'remote-webview-debugger'` (ES-модуль с типами). Импортируйте его раньше своего кода, чтобы перехват начался как можно раньше. Не подключайте на той же странице ещё и версию для `<script>` |
| Ваш шлюз | `https://<gateway>/v1/sdk.js` — копия, встроенная в шлюз (доступна также по адресу, зависящему от содержимого, для SRI; его предлагает веб-консоль) |
| Нативное приложение | Встройте `dist/sdk.js` из пакета или скачайте его из любого из перечисленных источников; см. [интеграцию с нативным приложением](../docs/native-integration.ru.md) |

## API

| API | Описание |
|---|---|
| `run(gatewayUrl, appKey, opts?)` | Выводит страницу в сеть (код устройства, плашка). Возвращает `Promise<{deviceCode, status}>`; повторный вызов безвреден. Параметры — ниже. |
| `status()` | `{deviceCode, status, control, help, label, deviceId, pageId, version, lang, deviceToken, level, config, pending, logSession}`; `status` — это `idle / connecting / online / polling / stopped / rejected / quota`, `lang` — язык интерфейса (`null` до вызова `run()`), `logSession` — журнал сеанса, в который пишет эта страница (`null`, если запись не ведётся) |
| `stop()` | Отключиться и убрать интерфейс (сбор console / сетевых запросов продолжается, в ограниченном объёме) |
| `setUser(userId)` | Сменить пользователя; один раз переподключается с новым `hello` |
| `help(on)` | Запросить поддержку / отменить запрос |
| `nativeControl(nativeKey, action)` | «Перехватить» / «Вернуть ИИ» / «Завершить» из собственного интерфейса нативного хоста |
| `nativeDecide(nativeKey, requestId, value)` | При `nativeApproval` — ответ на `status().pending`: уровень доступа или `null` для запроса на подключение, `'allow'` или `null` для подтверждения чувствительного действия |
| `setLang(lang?)` | Сменить язык интерфейса во время работы (собственная настройка языка в приложении); без аргумента — вернуться к языкам браузера. См. [Языки](#языки) |
| `registerLocale(pack)` | Добавить языковой пакет или заменить пакет с тем же `id` (принимает и массив). См. [Языки](#языки) |
| `builtinLocales` | Идентификаторы встроенных пакетов |

Параметры `run()`:

| Параметр | Описание |
|---|---|
| `userId` | Вошедший пользователь; отправляется в `hello` |
| `deviceId` | Стабильный идентификатор устройства от нативного хоста (иначе он хранится в localStorage) |
| `helpButton` | Показывать кнопку «Запросить поддержку» (объединяется через ИЛИ с политикой проекта) |
| `app` | `{ name, version }` приложения-хоста |
| `lang` | Язык всего, что видит пользователь телефона (плашка, плавающее окно, нижняя панель, диалоги, всплывающие уведомления, вкладка eruda и описание чувствительного действия «AI wants to …»): тег языка, например `'ja'` или `'pt-BR'`. По умолчанию — языки браузера. См. [Языки](#языки) |
| `locales` | Дополнительные языковые пакеты, регистрируются до выбора языка (как `registerLocale`) |
| `messages` | Сообщения, которые нужно переопределить, по языкам: `{ en: { ui: { help: 'Contact support' } }, zh: { ui: { help: '联系客服' } } }` |
| `networkExclude` | Запросы, через которые агенту не нужно продираться, — шрифты, которые всегда отдают 404, аналитические маячки: `['.ttf', 'WebTracks', '*beacon*', '/\\/track\\//']`. Каждое правило сопоставляется с URL как подстрока без учёта регистра, как шаблон с подстановочным символом `*` или как регулярное выражение, если записано в виде `/…/`. Добавляется к правилам политики проекта. Подходящие запросы не попадают в список сетевых запросов и в события хронологии `net_fail`; страница всё равно их записывает, поэтому агент может запросить их через `includeExcluded` |
| `lockScreen` | `false`: не блокировать страницу, пока подключён агент (пользователь всё равно может изменить это в плавающем окне). По умолчанию `true` |
| `theme` | `'auto'` (по умолчанию, следует фону страницы), `'system'`, `'light'` или `'dark'` |
| `style` | Цвета, шрифты, радиусы скругления, z-index и положение элементов интерфейса: `{ accent: '#e11d48', radius: 12, zIndex: 1000, pill: { side: 'left' } }`. См. [Оформление](#оформление) |
| `eruda` | `true` или `{ dock, load, src, name }`: показывать Remote Debugger как вкладку внутри eruda; `load` загружает последнюю версию eruda, если её нет на странице. По умолчанию выключено; политика проекта может включить это удалённо, локальные параметры имеют приоритет для каждого поля отдельно |
| `record` | `false`: эта страница не пишет журнал сеанса (уже сохранённое не удаляется). По умолчанию `true`; политика проекта может отключить журнал для всех страниц |
| `launchId` | К какому запуску приложения относится эта страница, чтобы все WebView одного процесса приложения записывали журнал в один сеанс. Нативный хост передаёт сюда собственный идентификатор (или определяет `window.RWDLaunchId` как строку или функцию, которая её возвращает); иначе SDK определяет запуск по сессионной cookie и heartbeat |
| `nativeKey`, `deviceToken`, `nativeApproval` | Для нативных хостов: секрет для `nativeControl` / `nativeDecide`, токен устройства, который хранит хост, и вопросы о подключении / подтверждении в нативном интерфейсе |

## Языки

Встроены: английский (`en`), упрощённый китайский (`zh`), традиционный китайский (`zh-TW`, используется также для `zh-HK`, `zh-MO` и `zh-Hant`), французский (`fr`), испанский (`es`), русский (`ru`), арабский (`ar`, с раскладкой справа налево), японский (`ja`), корейский (`ko`), немецкий (`de`) и португальский (`pt`, бразильский; используется также для `pt-PT`).

**Выбор языка.** Язык пользователя телефона — это `run({ lang })`, если он задан, затем по порядку каждый из `navigator.languages`. Для каждого тега SDK пробует сам тег, а затем его более короткие формы (`pt-BR` → `pt`, `zh-HK` → `zh-TW` → `zh`), берёт первый язык, для которого у него есть пакет, а в крайнем случае — английский. Сообщения, которых нет в пакете, подставляются по той же цепочке, поэтому неполный пакет — это нормально. `setLang('ja')` переключает язык во время работы; `status().lang` — используемый пакет.

**Загрузка.** Английский и упрощённый китайский входят в `sdk.js`. Остальные пакеты загружаются по требованию, когда они впервые понадобятся странице (на это время интерфейс показывает резервный язык):

- Сборка для `<script>`: из `locales/<id>.js` рядом с `sdk.js` (путь на CDN, например `…/remote-webview-debugger@0.2.0/dist/locales/ja.js`, или `/v1/locales/ja.js` вашего шлюза), а если не получилось — со шлюза, переданного в `run()`. Чтобы избежать лишнего запроса, загрузите пакет сами, до или после `sdk.js`: `<script src="…/dist/locales/ja.js"></script>`.
- Сборка ES-модуля: динамический импорт, поэтому сборщик выносит каждый язык в отдельный чанк. Чтобы, наоборот, включить язык в бандл сразу: `import ja from 'remote-webview-debugger/locales/ja'`, затем `run(url, key, { locales: [ja] })`.

**Собственные пакеты и формулировки.** Пакет — это `{ id, name, dir?, ui?, action?, agent? }`; всё, что не указано, берётся из резервных языков:

```js
RemoteWebviewDebugger.registerLocale({
  id: 'it',
  name: 'Italiano',
  ui: { takeover: 'Prendi il controllo', end: 'Termina', help: 'Richiedi assistenza' /* … */ },
})
RemoteWebviewDebugger.run(url, key, {
  messages: { en: { ui: { help: 'Contact support' } } }, // заменить отдельные сообщения любого языка
})
```

`ui` — тексты интерфейса, `action` дополняет фразу «AI wants to …» в диалоге подтверждения, а `agent` — то, что возвращается агенту. Типы TypeScript (`LocalePack`, `Messages`, `UiMessages`, `ActionMessages`, `AgentMessages`) перечисляют все ключи; эталон — `src/locales/en.ts`.

**Две аудитории.** Пользователь телефона получает язык, выбранный как описано выше. Агент читает сообщения об ошибках RPC и сводки хронологии (нажатия, переходы внутри страницы, неудачные запросы) на языке шлюза — `welcome.agentLang` (`RWD_LANG`), а пакет для него загружается тем же способом. До тех пор, пока `welcome` не укажет иное, используется английский; последнее значение хранится в localStorage `rwd:alang`, поэтому оно применяется и к событиям, произошедшим до `welcome` следующей страницы.

Так пользователь, говорящий по-китайски, может работать с агентом, работающим на английском: диалог спрашивает `AI 想要点击「提交订单」，允许吗？`, а при отказе агент читает `The user denied this action`.

## Оформление

Интерфейс живёт в shadow root на `#__rwd` (вне `<body>`), поэтому CSS страницы до него не доходит — только через эти точки входа:

- **Пользовательские CSS-свойства** на `:root` или `#__rwd`, например `:root { --rwd-accent-rgb: 225, 29, 72; --rwd-radius: 12px; }`.
- **`run({ style })`**, который задаёт те же свойства на `#__rwd`. Цвета здесь принимаются в любом формате CSS.
- **`::part()`** для всего остального: `#__rwd::part(bar) { … }`. Части: `pill`, `window`, `bar`, `task`, `dialog`, `toast`, `button`, `cursor`, `glow`, `overlay`. Имена классов внутри не являются стабильным API.
- **`theme`**: светлое или тёмное «стекло» (по умолчанию следует фону страницы).

| Свойство | Поле `style` | По умолчанию | Что задаёт |
|---|---|---|---|
| `--rwd-accent-rgb` | `accent` | `59, 130, 246` | Кнопки, переключатели, курсор агента, подсветку и свечение по краям |
| `--rwd-danger-rgb` | `danger` | `239, 68, 68` | Кнопку «Завершить» |
| `--rwd-warning-rgb` | `warning` | `245, 158, 11` | «Запросить поддержку» и «Идёт поддержка»; состояние, когда управляет пользователь |
| `--rwd-success-rgb` | `success` | `34, 197, 94` | Индикатор «в сети»; «Скопировано» |
| `--rwd-font` | `font` | системный шрифт интерфейса (для китайского, японского и корейского — свой для каждого языка) | Весь текст |
| `--rwd-font-mono` | `monoFont` | `ui-monospace, "SF Mono", …` | Код устройства и теги |
| `--rwd-radius` | `radius` | `18px` | Плавающее окно; у диалога скругление на 2px больше, у карточки задачи и плашки — на 2px меньше, у кнопок диалога — на 6px меньше |
| `--rwd-button-radius` | `buttonRadius` | `999px` | Кнопки, нижнюю панель и всплывающие уведомления |
| `--rwd-z-index` | `zIndex` | `2147483647` | Весь интерфейс |
| `--rwd-bar-bottom` | `barBottom` | `14px` | Нижнюю панель, над нижней безопасной областью |
| `--rwd-task-top` | `taskTop` | `10px` | Карточку задачи, под верхней безопасной областью |
| `--rwd-toast-bottom` | `toastBottom` | `84px` | Всплывающие уведомления, над нижней безопасной областью |
| — | `pill: { side, top }` | правый край (левый в языках с письмом справа налево), `0.62` | Где находится плашка в состоянии покоя, пока пользователь её не перетащит; `top` — от 0 (верх) до 1 (низ) |

Цвета задаются тройками `r, g, b`, чтобы полупрозрачные оттенки менялись вместе с ними (то же соглашение, что у `--bs-*-rgb` в Bootstrap).

## Поведение на странице (протокол §6–§8, §11)

- Уровни доступа: RPC проверяются по `welcome.level` / `control.level` (`forbidden`, «Requires the … level»). Агент без уровня (от более старого шлюза) получает `interact`; если агент не подключён, никаких дополнительных проверок нет.
- Токен устройства хранится в localStorage `rwd:dtoken`, токен возобновления — в sessionStorage `rwd:resume` (привязан к pageId). Код закрытия 4401: если токен тем временем изменился (его только что получила другая вкладка устройства), сразу повторить попытку один раз; если токена нет вовсе, а deviceId собственный, сгенерированный SDK, значит, welcome с токеном потерялся, и примерно через 1,5 с SDK начинает заново как новое устройство; иначе `rejected` и повтор примерно через 10 минут; 4409: переподключиться с новым pageId; 4429: `quota`, повтор примерно через 5 минут.
- `rwd_invite` из адресной строки убирается при вызове `run()` (`history.replaceState`) и отправляется в `hello`, пока не придёт `welcome`.
- `welcome.config`: `helpButton` (объединяется через ИЛИ с параметром `run()`), `maskSelectors`, `maskPatterns` (снимок, console, URL сетевых запросов, значения хранилища, сводки хронологии), `confirmSelectors`, `networkExclude` (добавляется к правилам параметра `run()`), `sessionLog`. Последняя конфигурация хранится в localStorage `rwd:cfg` и используется, пока не придёт `welcome`, — поэтому у проекта, отключившего журнал сеанса, он остаётся выключенным с первого же момента следующей страницы, ещё до какого-либо `welcome`.
- Снимки заканчиваются разделом `[Overlays]` со списком того, что перекрывает страницу, — подложки всплывающего окна, модального окна, нижней шторки — с тегом, коротким фрагментом текста, долей перекрытой области просмотра и ref. Подложка — это пустой элемент, для которого в aria snapshot нет узла, поэтому она получает ref вида `oN` вместо `eN`; именно это позволяет агенту нажать на неё, чтобы закрыть всплывающее окно.
- Клик сначала нацелен в видимый центр элемента, затем в остальные точки сетки 3×3 внутри него, поэтому значок поверх кнопки не мешает клику. Если перекрыты все точки, RPC завершается ошибкой `not_interactable` и называет перекрывающий элемент и его ref.
- Диалоги подключения и чувствительных действий (`[data-rwd-confirm]`, `confirmSelectors`, включая отправку формы клавишей Enter) находятся в Shadow DOM, принимают только доверенные нажатия и становятся активными через 0,4 с после появления. Вкладки одного origin делятся решёнными запросами на подключение через BroadcastChannel.

Загрузка файла запускает сбор console, необработанных ошибок и сетевых запросов (XHR, fetch, WebSocket, sendBeacon, EventSource) — не более 500 записей каждого вида; при переполнении первыми удаляются обычные логи и успешные запросы. Тела ответов кешируются в пределах 5 МБ суммарно и 64 КБ на каждое. Поэтому загружайте файл синхронно и как можно раньше в `<head>`.

## Журнал сеанса (протокол §5.4)

Эти буферы — память одной страницы. Параллельно SDK пишет на устройстве **журнал сеанса** в IndexedDB (`rwd-log`), чтобы агент, подключившийся после бага, всё равно мог прочитать весь путь к нему:

- Один сеанс — это один запуск приложения, общий для всех страниц origin: `run({ launchId })`, иначе `window.RWDLaunchId`, иначе определяется по сессионной cookie `rwd_launch` и heartbeat (сеанс по cookie, молчавший больше часа, считается новым запуском). `status().logSession` — используемый идентификатор.
- Записывается: открытие страницы / переходы внутри страницы / переход на передний план и в фон / уход со страницы, нажатия, ввод, отправка форм и позиции, на которых остановилась прокрутка, интерактивные вызовы агента и `rwd.evaluate`, смены управления, console всех уровней и каждый завершённый запрос — неудачные также с очищенными от секретов заголовками и телами (по 64 КБ). Запись идёт независимо от того, доступен ли шлюз. Замаскированные поля хранятся как `••••`, `maskPatterns` применяются при записи.
- Хранится: последние 3 запуска, по 10 МБ каждый; при превышении первыми удаляются обычные логи и успешные запросы. Если квота хранилища меньше 64 МБ — только текущий запуск; без IndexedDB — ничего.
- Агент читает журнал через `rwd.log` (`observe`) и `rwd.logDetail` (`advanced`, для заголовков и тел). Иначе ничего не покидает устройство.
- Отключается через `run({ record: false })` для одной страницы или `policy.sessionLog: false` для проекта — что также удаляет уже сохранённое этим origin.

## Структура

- `src/index.ts`: публичный API, сеанс, диспетчеризация RPC, состояние управления.
- `src/transport.ts`: WebSocket страницы (нативный конструктор), таймаут heartbeat, экспоненциальная задержка повторов, а после 3 неудачных попыток — `POST /v1/presence` каждые 60 с.
- `src/ids.ts`: deviceId / pageId / openerId.
- `src/launch.ts`: к какому запуску приложения относится эта страница (`launchId`, `window.RWDLaunchId`, cookie `rwd_launch`).
- `src/pageWatch.ts`: сообщения `page` (url, title, visibility) и события хронологии (переходы внутри страницы, нажатия пользователя).
- `src/ui.ts`, `src/lock.ts`: плашка, кнопка «Запросить поддержку», блокирующий оверлей, свечение, подсветка действий и диалоги в Shadow DOM; блокирует доверенный ввод пользователя, пока подключён агент, и показывает, сколько длится подключение.
- `src/approval.ts`: одобрение подключения и подтверждение чувствительных действий (диалог на странице или нативный хост через `nativeDecide`).
- `src/i18n.ts`, `src/locales/`, `src/localeLoader*.ts`: языковые пакеты (тексты интерфейса, действий и агента для каждого языка), выбор языка и резервные языки, загрузка по требованию; `scripts/locales.mjs` собирает `dist/locales/<id>.js`.
- Движок агента находится рядом с chobitsu в `packages/chobitsu/src/engine/rwd/`: снимок, `rwd.query`, проверки готовности элемента к действию, синтетический ввод, клавиатура, буферы console / сети, скриншоты, `rwd.storage`, журнал сеанса в IndexedDB (`coldlog.ts`), обнаружение перекрывающих слоёв (`overlays.ts`), уровни доступа и правила подтверждения (`policy.ts`), тексты для агента (`i18n.ts`). Исходники Playwright, используемые для снимков, лежат в `packages/chobitsu/src/engine/vendor/playwright/`. Сборка включает их из исходников в `dist/sdk.js`.

## Сборка и тесты

```sh
cd sdk
npm ci
npm run build        # dist/sdk.js (IIFE, глобальная RemoteWebviewDebugger, ES2017), dist/index.mjs + index.d.ts (ES-модуль)
npm run typecheck
npm test             # Playwright: WebKit (iPhone 15) + Chromium (Pixel 7)
npm run gateway      # локальный mock-шлюз: http://localhost:8787/demo/platform/?key=rwd_pk_demo
```

Тесты используют `test/mock-gateway.mjs`, который реализует сторону протокола, обращённую к странице (welcome, состояние управления, RPC, presence; токены, коды закрытия, уровни доступа, удалённая конфигурация, `agentLang`, одобрение подключения), и отдаёт `/v1/sdk.js`, языковые пакеты в `/v1/locales/` и демо-магазин. Сам он уровни доступа не проверяет, поэтому тесты проверяют собственные проверки страницы. Спецификации в `test/e2e/` запускаются с браузером в `zh-CN` и `agentLang: 'zh'`, если в тесте не указано иное; английский покрывает `i18n.spec.ts`, а `locales.spec.ts` — остальные языковые пакеты, резервные языки, собственные пакеты, оформление и раскладку справа налево. Тест совместимости загружает eruda 3.4.3 и PageSpy 2.4.0 с jsdelivr, поэтому ему нужен доступ в интернет.

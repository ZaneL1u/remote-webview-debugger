# 架構

Remote WebView Debugger 讓 AI agent 檢視並操作在別人手機上開啟的網頁：行動瀏覽器或超級 App 裡的 H5 頁面，或是你自己 App 裡的 WebView。agent 透過 MCP 連到自行架設的閘道，閘道再連到在頁面中執行的輕量 SDK。手機使用者核准連線後，能看到 agent 在做什麼，並且隨時可以接管。

本文說明各個組成部分以及它們遵循的規則。確切的訊息和端點請見 [protocol.zh-TW.md](protocol.zh-TW.md)；App 整合請見 [native-integration.zh-TW.md](native-integration.zh-TW.md)；部署請見 [gateway/README.zh-TW.md](../gateway/README.zh-TW.md) 和 [deploy/platform/README.zh-TW.md](../deploy/platform/README.zh-TW.md)。

## 組成

```
  AI agent（Claude Code、Cursor 或任何 MCP 用戶端）
        │  MCP：Streamable HTTP + Bearer API 金鑰
        │  （或透過 `rwd mcp` 橋接 stdio）
        ▼
┌──────────────────────────── 閘道（單一 Go 執行檔） ─────────────────────────────┐
│  /v1/mcp      MCP 工具 ──────┐                                                  │
│  /v1/api      REST + SSE ────┼──▶ hub：裝置、頁面、控制狀態、連線核准、         │
│  /v1/page     頁面 WebSocket ┘        時間軸、RPC 轉送（記憶體中）              │
│  /v1/sdk.js   內嵌的頁面 SDK          store：SQLite 或 Postgres（持久保存）     │
│  /            內嵌的 Web 主控台                                                 │
└───────────▲──────────────────────────────────────────────▲──────────────────────┘
            │ HTTPS，cookie 工作階段                       │ WebSocket（wss://…/v1/page）
        Web 主控台                                         │ 備援：POST /v1/presence
      （客服、管理員）                                     │
                                  ┌──────────── 手機 ──────┴────────────────────┐
                                  │  H5 頁面 / App WebView                      │
                                  │    頁面 SDK：與閘道的連線、Shadow DOM 中的  │
                                  │      介面（膠囊、對話框、鎖定）             │
                                  │    引擎：快照、操作、console 和網路記錄、   │
                                  │      遮蔽、等級檢查                         │
                                  │  原生宿主（選用）：注入 SDK、真實截圖、     │
                                  │    原生對話框和按鈕                         │
                                  └─────────────────────────────────────────────┘
```

| 組成部分 | 路徑 | 職責 |
|---|---|---|
| 閘道 | [`gateway/`](../gateway) | Go 伺服器。接受頁面連線，在記憶體中維護裝置的即時狀態，提供託管的 MCP 端點、主控台的 REST API 和即時更新，並記錄稽核記錄。主控台和 SDK 都內嵌在裡面，單一執行檔就是完整的伺服器 |
| 頁面 SDK | [`sdk/`](../sdk) | `sdk.js`，由頁面載入或由 App 注入。負責連線、身分識別、頁面內的介面、授權對話框和螢幕鎖定 |
| 引擎 | [`packages/chobitsu/src/engine/`](../packages/chobitsu/src/engine) | agent 每個動作在頁面端的那一半：無障礙快照（採用 Playwright 的 aria snapshot 程式碼）及浮在其上的覆蓋層、可操作性檢查與合成輸入、console 與網路記錄（以 [chobitsu](https://github.com/liriliri/chobitsu) 為基礎）、截圖、遮蔽、等級檢查 |
| 主控台 | [`console/`](../console) | React 單頁應用程式：專案與整合程式碼片段、裝置及其時間軸、API 金鑰、成員、策略、邀請、稽核記錄 |
| 原生宿主 | 你的 App；參考 [`examples/mock-app`](../examples/mock-app) | 在每個 WebView 的 document start 時注入 SDK，保存裝置 id 和裝置權杖，提供真實截圖，並可選擇提供原生的核准對話框和按鈕 |

## 一次除錯工作階段

1. **頁面上線。** 頁面載入 `sdk.js`（或由 App 注入）。console、錯誤和網路記錄會立即開始，存在有容量上限的緩衝區裡，因此 agent 晚一點才連線也看得到之前發生的事。`run()` 向閘道建立 WebSocket 並送出 `hello`；閘道回覆這台裝置的**裝置碼**（例如 `K7Q2-9M4X`）和專案的遠端設定，頁面上的膠囊會顯示這組裝置碼。
2. **有人把裝置告訴 agent。** 使用者口頭唸出裝置碼、點「求助」（裝置會排在所有清單的最前面），或是開啟客服傳來的**邀請連結**，讓裝置一上線就處於求助狀態。
3. **agent 連線。** agent 用裝置碼呼叫 `connect_device`。除非專案另有設定，手機上會跳出「AI 請求加入」，使用者選擇等級（僅檢視、檢視並操作、進階）或拒絕。在此之前，agent 什麼都讀不到。agent 一連上，螢幕就會鎖定、擋下使用者的輸入，邊緣出現光暈，底部控制列顯示已連線的時間。
4. **agent 開始工作。** 先擷取快照取得元素的 ref，再依 ref 點擊、填寫、捲動。快照也會列出浮在頁面上的彈出視窗和遮罩，各自帶有一個 ref；如果點擊被某個覆蓋層擋住，錯誤訊息會指出擋住它的元素名稱和 ref——這樣 agent 就能直接點遮罩關掉彈出視窗，不必瞎猜。第一次操作會把裝置從 *observe* 切換到 *agent*，agent 游標會標出它操作的位置。依等級不同，它還能讀取 console、網路、儲存空間和截圖。
5. **使用者始終說了算。** 點「接管」，頁面交回使用者，agent 暫停（它的操作會以 `takeover` 失敗，直到使用者點「交還」）。點「結束」，agent 就會斷開。點擊標記為敏感的元素（送出訂單、付款、刪除）前，需要使用者在手機上確認。
6. **agent 離開。** agent 以 `disconnect_device` 離開；兩分鐘沒有任何操作時，裝置會退回 *observe*；達到專案設定的最長連線時間（預設 60 分鐘）時，agent 會被斷開。

一次操作的完整路徑：

```
agent ─ click(ref=e12) ─▶ MCP 處理
   閘道：API 金鑰有效？→ 已連線？→ 等級 ≥ interact？→ 使用者沒有接管？
         observe（已鎖定螢幕）→ agent → RPC {"method":"rwd.click","params":{"ref":"e12"}}
   ─── WebSocket ──▶ SDK：等級 ≥ interact？沒有接管？敏感元素 → 請使用者確認
                     引擎：等待元素可見、穩定、可用、點擊測試通過（最多 5 秒）
                           移動 agent 游標、醒目標示，派送 pointer/mouse/touch 事件
   ◀── {"id":…, "result":{}} ───
   閘道：稽核記錄一筆 "rpc"（方法、頁面、耗時；不記錄內容）
agent ◀─ "已點擊 e12（頁面 p2）。" + [工作階段變化]（新頁面、跳轉、錯誤、使用者接管）
```

每個操作只需要一次往返：可操作性檢查和事件派送都在頁面內完成，不經過網路。

## 裝置、頁面與 agent

**裝置。** 一個 `deviceId`：一個瀏覽器設定檔，或在原生宿主自行傳入 id 時代表一次 App 安裝。閘道會給每台裝置分配一組永久不變的裝置碼。裝置不隸屬於任何專案：同一支手機開啟兩個專案（兩把接入金鑰）的頁面，仍然是同一台裝置，頁面清單裡同時有兩邊的頁面。API 金鑰也不隸屬於專案，所以一個 MCP 伺服器就能存取所有裝置。

**頁面。** 一個分頁或一個 WebView，以 `pageId` 識別，在同一個分頁內重新整理或跳轉都不會改變。閘道依裝置為頁面編號 `p1`、`p2`…，記錄誰開啟了誰，並追蹤哪個頁面在前景。頁面斷線後，它的編號會保留兩分鐘，足夠頁面跳轉後重新連上——但同一份文件在別處再次出現時例外：WebView 被重建、帶著新的 `pageId` 連上來時，舊項目會立即被取代；已斷線的頁面若有另一個在線頁面顯示同一個 URL，1.5 秒後就會被移除。如此一來，被重建的 WebView 不會在頁面清單裡留下幽靈，agent 也會被移到真正存在的那個頁面。

**時間軸。** 每台裝置都有一條時間軸（存在記憶體中，保留最近 300 個事件）：頁面的開啟、跳轉、重新整理、回到前景和關閉；錯誤、失敗的請求和使用者的點擊；求助、核准和控制狀態變化。每個 MCP 工具結果的最後都會附上 agent 還沒看過的時間軸項目，讓它不必輪詢就能發現新頁面、錯誤和使用者接管。在**跟隨模式**（預設）下，agent 的操作開啟了新頁面，或使用者切換到另一個頁面時，agent 所選的頁面會自動跟著移過去。

**agent。** 閘道依 API 金鑰保存 agent 狀態：連接的裝置和所選的頁面。一個 agent 同一時間只連接一台裝置，一台裝置最多只有一個 agent；新核准的 agent 會取代原本的那一個。

**控制狀態。** 每台裝置處於四種狀態之一，由閘道決定並廣播給它的所有頁面：

```
                 agent 連線                    第一次互動操作
       ┌──────┐ ───────────────▶ ┌─────────┐ ─────────────────────────▶ ┌───────┐
       │ none │                  │ observe │                            │ agent │
       └──────┘ ◀─────────────── └─────────┘ ◀───────────────────────── └───────┘
           ▲     agent 離開、         │        閒置（預設 2 分鐘）         │
           │     結束、時間上限       │ 接管                          接管 │
           │                          ▼                                    ▼
           │                        ┌──────┐ ◀─────────────────────────────┘
           └─────────── 結束 ────── │ user │ ──────── 交還 ────────▶ agent
                                    └──────┘
```

在 `observe` 和 `agent` 狀態下，使用者的輸入會被擋下（使用者可以在浮動視窗裡關閉鎖定）；在 `user` 狀態下，agent 仍然可以讀取，但所有互動類呼叫都會以 `takeover` 失敗，agent 可以呼叫 `wait_for_control` 等待使用者交還。

## 授權與隱私

核心原則：**持有 API 金鑰或知道裝置碼，都不足以看到使用者的頁面。** agent 和頁面之間隔著多道彼此獨立的關卡。

| 關卡 | 作用 |
|---|---|
| API 金鑰 | 每個 MCP 請求都必須帶上一把。金鑰有最高等級、有效期限（預設 90 天）和選用的 IP 允許清單；撤銷金鑰後，它的 agent 會立即被斷開。查找裝置失敗會受到速率限制，避免裝置碼被猜中 |
| 裝置碼 | 只用來**識別**裝置，不授予任何權限 |
| 專案策略 | `approval: prompt`（新專案的預設值）要求使用者核准；`maxLevel` 限制任何 agent 能做的事。一台裝置上有多個專案的頁面時，套用最嚴格的策略 |
| 使用者核准 | 手機會顯示 agent 的名稱、金鑰提示和可選的等級，使用者選一個或拒絕。這個對話框位於 Shadow DOM 中，只回應真實（受信任）的點擊，所以 agent 無法自己核准自己。同一把金鑰被拒絕 3 次後，10 分鐘內無法再請求這台裝置。使用者可以在自己的裝置上選擇開啟自動允許。agent 自行放開裝置（斷線、切換到別台裝置、連線時間用完）後，10 分鐘內可以不再跳出對話框直接回來，等級不超過使用者先前授予的等級；使用者點「結束」、主控台成員結束工作階段、使用者拒絕請求或金鑰被撤銷，都會讓這個資格失效 |
| 等級 | `observe`（快照、截圖、console、網路清單）、`interact`（再加上點擊、輸入、捲動、跳轉等）、`advanced`（再加上執行 JavaScript、讀取請求內容和儲存空間）。實際生效的等級取 agent 要求的、金鑰的、策略的和使用者選擇的最小值。**SDK 會在頁面內再強制檢查一次**，與閘道彼此獨立 |
| 可見與可控 | agent 連線期間，頁面上一直會顯示：標示 agent 狀態的膠囊、列出計畫的任務卡片、每次操作時的 agent 游標和醒目標示、操作期間的邊緣光暈。「接管」「交還」「結束」只回應使用者的點擊；原生宿主必須出示頁面指令碼（包括 agent 自己執行的指令碼）讀不到的密鑰（`nativeKey`） |
| 敏感操作 | 點擊帶有 `data-rwd-confirm`（或符合策略中 `confirmSelectors`）的元素，或送出含有這類元素的表單時，要等使用者在手機上確認 |
| 遮蔽 | 密碼欄位、`data-rwd-mask` 元素，以及策略中設定的選擇器和文字規則（手機號碼、信用卡號、證件號碼等）**在頁面內**就會被換成 `••••`，早於任何資料離開裝置：快照、截圖、console 文字、網路 URL 和內容、儲存空間的值和時間軸摘要皆然。`Cookie`、`Set-Cookie` 和 `Authorization` 標頭一律遮蔽。策略中的 `networkExclude` 規則是另一回事：它只是把雜訊（老是 404 的字型、分析用的 beacon）擋在 agent 讀取的清單之外，agent 仍然可以要求查看被隱藏的請求，所以它不是隱私控管手段 |
| 不受信任的內容 | 交給 agent 的頁面內容會被包裝起來並標示為不受信任的資料，避免頁面中埋藏的指示被誤認為使用者的指示。高風險的點擊仰賴使用者確認，而不是 agent 的判斷 |
| 工作階段記錄 | 記錄在裝置上，從不主動傳送到任何地方：讀取它和其他讀取操作一樣需要 `observe`，失敗請求的標頭和內容則需要 `advanced`。遮蔽規則在記錄時就會套用，被遮蔽欄位的值會直接存成 `••••`，而不是事後才遮蔽。專案可以關閉這份記錄，並刪除已儲存的內容 |
| 稽核 | 登入、金鑰和成員變更、連線請求和使用者的決定、每個 RPC（方法、頁面、耗時、結果）、使用者的接管和結束，以及被拒絕的呼叫。從不記錄頁面內容或參數值 |

哪些資料會離開手機：從呼叫 `run()` 那一刻起，`hello` 裡的裝置資訊（user agent、頁面有提供的 `userId`、App 名稱和版本、頁面網址和標題）以及簡短的時間軸摘要；其他內容只有在已連線的 agent 要求時才會送出。閘道不保存頁面內容：快照、截圖和記錄只是轉交給 agent，時間軸則只存在記憶體中。工作階段記錄會依同樣的遮蔽規則記錄在裝置上，並一直留在那裡，直到已連線的 agent 讀取它（請見下方的**儲存**）。

值得直接說清楚的已知限制：

- 輸入是合成的：事件的 `isTrusted: false`，會檢查這個屬性的頁面不會有反應。
- `interact` 允許 agent 跳轉到任何 `http(s)` 網址，不限於專案的來源。
- `advanced` 可以在頁面中執行任意 JavaScript。這類指令碼的回傳值無法遮蔽，所以除非真的需要，請把 `maxLevel` 維持在 `interact`。
- 網路記錄只涵蓋 SDK 載入後頁面以 JavaScript 發出的請求（fetch、XHR、WebSocket、sendBeacon、EventSource），看不到圖片、指令碼、樣式表以及原生程式碼發出的請求。iframe 內的內容不會出現在快照裡。
- App 切到背景時，作業系統會暫停它的 WebView，裝置在回到前景之前都會是離線狀態。
- 中斷點、逐步執行、效能分析和堆積快照不在範圍內；需要這些功能時，請使用 Safari Web Inspector 或搭配可除錯 WebView 的 `chrome://inspect`。

## 儲存

閘道預設使用 **SQLite**（純 Go，不需要 CGO；檔案位置由 `RWD_DATA` 設定），當 `RWD_DATABASE_URL` 是 `postgres://` 網址時則使用 **Postgres**。資料表結構會在啟動時自動建立和遷移。

| 持久保存（資料庫） | 只在記憶體中（重新啟動後遺失） |
|---|---|
| 專案及其策略、接入金鑰 | 已連線的頁面及其編號 |
| 成員（密碼以 PBKDF2-SHA256 保存）、待接受的成員邀請 | 控制狀態、待處理的核准、已連線的 agent |
| API 金鑰（HMAC-SHA256 雜湊、等級、有效期限、IP 允許清單） | 裝置時間軸 |
| 出現過的裝置：id、裝置碼、userId、user agent、App、首次和最近一次出現時間、裝置權杖雜湊 | 速率限制計數器 |
| 裝置邀請（權杖雜湊）、稽核記錄 | |
| 設定：首次啟動時產生的金鑰 pepper 和工作階段簽章密鑰 | |

重新啟動後，頁面會自行重新連線（SDK 以退避方式重試），並保留原本的裝置碼；agent 則需要重新連線。即時狀態存放在單一程序中，所以每個資料庫只能執行**一個閘道執行個體**。

**存在手機上，而不是閘道上。** 有一份資料刻意不在上述範圍內：**工作階段記錄**，由頁面 SDK 寫入裝置上的 IndexedDB（資料庫 `rwd-log`）。從 App 啟動開始，它會記錄造訪過的頁面、使用者的點擊和輸入、agent 的操作、控制狀態變化、console 輸出以及每一個請求——失敗的請求連同標頭和內容——不論閘道連不連得上。正因如此，agent 即使在 bug 發生**之後**才連線，也能讀到完整的來龍去脈，而不是從空白的緩衝區開始。它保留最近三次啟動的記錄，每次最多 10 MB；除非已連線的 agent 以 `get_session_overview` / `get_session_log` 主動讀取（[protocol.zh-TW.md §5.4](protocol.zh-TW.md#54-工作階段記錄)），否則其中的內容不會送到閘道或任何人手上。專案可以關閉它（`policy.sessionLog`），同時也會刪除裝置上已儲存的內容；單一頁面也可以用 `run({ record: false })` 選擇不記錄。

## 給維運人員的安全注意事項

- **透過 HTTPS 提供服務。** 頁面以 `wss://` 連線，在 HTTPS 下主控台的 cookie 會帶有 `Secure` 標記，API 金鑰則放在標頭中傳輸。[deploy/platform](../deploy/platform/README.zh-TW.md) 中的 Docker Compose 設定會由 Caddy 處理 TLS，也可以放在你自己的代理伺服器後面。
- **只在代理伺服器後面信任轉送標頭。** `--trust-proxy` 會讓閘道從 `X-Forwarded-For` / `X-Forwarded-Host` 取得用戶端 IP 和對外主機名稱。如果前面沒有代理伺服器，任何人都能偽造這些標頭，繞過 IP 允許清單和速率限制。
- **保護好資料庫及其備份。** 裡面有金鑰 pepper 和工作階段密鑰；拿到它們，就能離線比對 API 金鑰雜湊，並偽造主控台工作階段。
- **owner 密碼。** `RWD_ADMIN_PASSWORD` 每次啟動時都會重設 owner 的密碼，也可以當作帳號救援手段。如果在全新的資料庫上沒有設定它，系統會在記錄中印出一次隨機產生的密碼。
- **接入金鑰是公開的。** 它只能讓頁面上線。請用 `allowedOrigins` 防止其他網站使用你的金鑰；不過 `Origin` 是由瀏覽器強制填入的標頭，非瀏覽器用戶端可以送出任何值，這也是為什麼保護既有裝置的是裝置權杖，而不是接入金鑰。
- **把 API 金鑰當成密碼看待。** 每個 agent 或每個人都使用自己的金鑰，等級夠用就好，並設定有效期限；伺服器上使用的金鑰再加上 IP 允許清單。撤銷會立即生效。
- **固定 SDK 版本。** 對於 H5 頁面，主控台提供一段程式碼片段，以 Subresource Integrity 載入依內容定址的 SDK 網址。原生 App 可以把 `sdk.js` 打包進 App，而不是在執行時下載，這樣即使閘道遭到入侵，也無法向它們推送新程式碼。
- **保護指標端點。** 如果 `/v1/metrics` 可以從外部存取，請設定 `RWD_METRICS_TOKEN`。
- 主控台登入有速率限制（每個 IP 每分鐘 10 次），寫入請求必須帶自訂的 CSRF 標頭，而且主控台無法被嵌入框架中。

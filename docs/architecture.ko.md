# 아키텍처

Remote WebView Debugger는 다른 사람의 휴대폰에 열려 있는 웹 페이지를 AI 에이전트가 살펴보고 조작할 수 있게 해 줘요. 대상은 모바일 브라우저나 슈퍼 앱 안의 H5 페이지, 또는 자사 앱 안의 WebView예요. 에이전트는 셀프 호스팅 게이트웨이와 MCP로 통신하고, 게이트웨이는 페이지 안에서 동작하는 작은 SDK와 통신해요. 휴대폰 사용자는 접속을 승인하고, 에이전트가 하는 일을 보고, 언제든 직접 조작할 수 있어요.

이 문서는 구성 요소와 그것들이 따르는 규칙을 설명해요. 메시지와 엔드포인트의 세부 사항은 [protocol.ko.md](protocol.ko.md)에, 앱 연동은 [native-integration.ko.md](native-integration.ko.md)에, 배포는 [gateway/README.ko.md](../gateway/README.ko.md)와 [deploy/platform/README.ko.md](../deploy/platform/README.ko.md)에 있어요.

## 구성 요소

```
  AI agent (Claude Code, Cursor, any MCP client)
        │  MCP: Streamable HTTP + Bearer API key
        │  (or stdio through the `rwd mcp` bridge)
        ▼
┌──────────────────────────── Gateway (one Go binary) ────────────────────────────┐
│  /v1/mcp      MCP tools ─────┐                                                  │
│  /v1/api      REST + SSE ────┼──▶ hub: devices, pages, control state, approvals,│
│  /v1/page     page WebSocket ┘        timelines, RPC routing   (in memory)      │
│  /v1/sdk.js   embedded page SDK      store: SQLite or Postgres (persistent)     │
│  /            embedded web console                                              │
└───────────▲──────────────────────────────────────────────▲──────────────────────┘
            │ HTTPS, cookie session                        │ WebSocket (wss://…/v1/page)
       Web console                                         │ POST /v1/presence as a fallback
       (support staff, admins)                             │
                                  ┌──────────── phone ─────┴────────────────────┐
                                  │  H5 page / App WebView                      │
                                  │    page SDK: link to the gateway, UI        │
                                  │      (pill, dialogs, lock) in a Shadow DOM  │
                                  │    engine: snapshots, actions, console and  │
                                  │      network capture, masking, levels       │
                                  │  native host (optional): injects the SDK,   │
                                  │    real screenshots, native dialogs/buttons │
                                  └─────────────────────────────────────────────┘
```

| 구성 요소 | 경로 | 역할 |
|---|---|---|
| 게이트웨이 | [`gateway/`](../gateway) | Go 서버. 페이지 연결을 받고, 실시간 기기 상태를 메모리에 유지하고, 호스팅형 MCP 엔드포인트와 콘솔의 REST API 및 실시간 업데이트를 제공하고, 감사 로그를 기록해요. 콘솔과 SDK를 내장하므로 바이너리 하나가 서버 전체예요 |
| 페이지 SDK | [`sdk/`](../sdk) | 페이지가 불러오거나 앱이 주입하는 `sdk.js`. 연결, 신원, 페이지 내 UI, 동의 대화상자, 화면 잠금을 담당해요 |
| 엔진 | [`packages/chobitsu/src/engine/`](../packages/chobitsu/src/engine) | 모든 에이전트 작업의 페이지 쪽 절반: 접근성 스냅샷(Playwright의 aria snapshot 코드)과 그 위에 떠 있는 레이어, 조작 가능 여부 검사와 합성 입력, console과 네트워크 수집([chobitsu](https://github.com/liriliri/chobitsu) 기반), 스크린샷, 마스킹, 권한 수준 검사 |
| 콘솔 | [`console/`](../console) | React 단일 페이지 앱: 프로젝트와 연동 코드 조각, 기기와 그 타임라인, API 키, 멤버, 정책, 초대, 감사 로그 |
| 네이티브 호스트 | 여러분의 앱. 참고 구현은 [`examples/mock-app`](../examples/mock-app) | 모든 WebView에 문서 시작 시점에 SDK를 주입하고, 기기 ID와 토큰을 보관하고, 실제 스크린샷과 선택적으로 네이티브 승인 대화상자와 버튼을 제공해요 |

## 디버깅 세션의 흐름

1. **페이지가 온라인이 돼요.** 페이지가 `sdk.js`를 불러오면(또는 앱이 주입하면) console, 오류, 네트워크 수집이 곧바로 크기가 제한된 버퍼에서 시작돼요. 그래서 나중에 접속한 에이전트도 그 전에 일어난 일을 볼 수 있어요. `run()`은 게이트웨이로 WebSocket을 열고 `hello`를 보내요. 게이트웨이는 기기의 **기기 코드**(예: `K7Q2-9M4X`)와 프로젝트의 원격 설정으로 응답해요. 페이지의 배지에 그 코드가 표시돼요.
2. **누군가 에이전트에게 기기를 알려 줘요.** 사용자가 기기 코드를 불러 주거나, **지원 요청**을 탭하거나(그 기기가 모든 목록의 맨 위에 표시돼요), 지원 담당자가 보낸 **초대 링크**를 열어요. 초대 링크로 열면 기기가 처음부터 지원을 요청한 상태로 온라인이 돼요.
3. **에이전트가 접속해요.** 코드를 넣어 `connect_device`를 호출해요. 프로젝트에서 따로 설정하지 않았다면 사용자의 휴대폰에 *AI 접속 요청*이 뜨고, 사용자는 권한 수준(보기 전용, 보기 및 조작, 고급)을 고르거나 거부해요. 그 전에는 아무것도 읽을 수 없어요. 에이전트가 접속하면 화면이 잠겨 사용자 입력을 막고, 테두리가 빛나고, 하단 바에 접속 시간이 표시돼요.
4. **에이전트가 작업해요.** 스냅샷을 찍어 요소 ref를 얻은 뒤, ref로 클릭하고 채우고 스크롤해요. 스냅샷에는 페이지 위에 떠 있는 팝업과 배경도 각각 ref와 함께 나열되고, 레이어에 막힌 클릭은 무엇이 막았는지 이름과 ref를 담아 실패해요. 그래서 에이전트는 추측하지 않고 배경을 탭해 팝업을 닫을 수 있어요. 첫 작업이 기기를 *observe*에서 *agent*로 바꾸고, 에이전트 커서가 작업 위치를 보여 줘요. 권한 수준에 따라 console, 네트워크, 저장소, 스크린샷도 읽을 수 있어요.
5. **결정권은 사용자에게 있어요.** **직접 조작**을 누르면 페이지가 사용자에게 돌아가고 에이전트는 멈춰요(사용자가 **AI에 맡기기**를 탭할 때까지 에이전트의 작업은 `takeover`로 실패해요). **종료**는 에이전트의 접속을 끊어요. 민감하다고 표시된 요소(주문, 결제, 삭제)를 클릭하려면 휴대폰에서 사용자의 확인이 필요해요.
6. **에이전트가 떠나요.** `disconnect_device`로 떠나거나, 2분 동안 아무 작업이 없으면 기기가 *observe*로 돌아가고, 프로젝트의 최대 접속 시간(기본 60분)이 지나면 에이전트의 접속이 끊겨요.

작업 하나를 처음부터 끝까지 따라가 보면:

```
agent ─ click(ref=e12) ─▶ MCP handler
   gateway: API key valid? → attached? → level ≥ interact? → user hasn't taken over?
            observe (screen locked) → agent → RPC {"method":"rwd.click","params":{"ref":"e12"}}
   ─── WebSocket ──▶ SDK: level ≥ interact? not taken over? sensitive element → ask the user
                     engine: wait until visible, stable, enabled, hit-testable (≤ 5 s)
                             move the agent cursor, highlight, dispatch pointer/mouse/touch events
   ◀── {"id":…, "result":{}} ───
   gateway: audit "rpc" (method, page, latency; no payload)
agent ◀─ "Clicked e12 (page p2)." + [Session changes] (new pages, navigations, errors, takeovers)
```

작업은 모두 한 번의 왕복으로 끝나요. 조작 가능 여부 검사와 이벤트 발생은 네트워크를 거치지 않고 페이지 안에서 실행돼요.

## 기기, 페이지, 에이전트

**기기.** `deviceId` 하나: 브라우저 프로필 하나, 또는 네이티브 호스트가 자체 ID를 넘기는 경우 앱 설치 하나예요. 게이트웨이는 기기마다 영구적인 기기 코드를 부여해요. 기기는 프로젝트에 묶이지 않아요. 두 프로젝트(앱 키 두 개)의 페이지를 여는 휴대폰은 두 프로젝트의 페이지를 모두 가진 기기 하나예요. API 키도 프로젝트에 묶이지 않으므로 MCP 서버 하나로 모든 기기에 접근해요.

**페이지.** 탭이나 WebView 하나이고, 그 탭에서 새로고침이나 페이지 이동을 해도 유지되는 `pageId`로 식별해요. 게이트웨이는 기기별로 페이지에 `p1`, `p2`, … 라벨을 붙이고, 어느 페이지가 어느 페이지를 열었는지 기록하고, 어느 페이지가 포그라운드인지 추적해요. 연결이 끊긴 페이지는 페이지 이동 후 다시 연결될 수 있도록 2분 동안 라벨을 유지해요. 단, 같은 문서가 다른 곳에 다시 나타나면 그렇지 않아요. 새 `pageId`로 다시 만들어진 WebView는 이전 항목을 즉시 대체하고, 연결이 끊긴 페이지와 같은 URL을 다른 연결된 페이지가 보여 주고 있으면 끊긴 페이지는 1.5초 후 제거돼요. 그래서 다시 만들어진 WebView가 페이지 목록에 유령 항목을 남기지 않고, 에이전트는 실제로 있는 페이지로 옮겨져요.

**타임라인.** 기기마다 타임라인이 있어요(메모리에 최근 이벤트 300개). 페이지 열림, 이동, 새로고침, 포커스, 닫힘, 오류, 실패한 요청, 사용자의 탭, 지원 요청, 승인, 제어 상태 변경이 기록돼요. 모든 MCP 도구 결과의 끝에는 에이전트가 아직 보지 못한 타임라인 항목이 붙으므로, 에이전트는 폴링하지 않아도 새 페이지, 오류, 직접 조작 전환을 알아차려요. **팔로 모드**(기본값)에서는 에이전트가 선택한 페이지가 에이전트의 작업으로 열린 페이지나 사용자가 전환한 페이지로 옮겨 가요.

**에이전트.** 게이트웨이는 API 키마다 에이전트 상태 하나를 유지해요. 접속한 기기와 선택한 페이지예요. 에이전트는 한 번에 기기 하나에만 접속하고, 기기에는 에이전트가 최대 하나만 있어요. 새로 승인된 에이전트가 이전 에이전트를 대체해요.

**제어 상태.** 각 기기는 네 가지 상태 중 하나에 있고, 이 상태는 게이트웨이가 결정해 그 기기의 모든 페이지에 브로드캐스트해요.

```
                 agent attaches                first interactive action
       ┌──────┐ ───────────────▶ ┌─────────┐ ─────────────────────────▶ ┌───────┐
       │ none │                  │ observe │                            │ agent │
       └──────┘ ◀─────────────── └─────────┘ ◀───────────────────────── └───────┘
           ▲     agent leaves,        │        idle (default 2 min)        │
           │     End, time limit      │ Take over                Take over │
           │                          ▼                                    ▼
           │                        ┌──────┐ ◀─────────────────────────────┘
           └─────────── End ─────── │ user │ ────── Hand back ──────▶ agent
                                    └──────┘
```

`observe`와 `agent`에서는 사용자 입력이 막혀요(사용자는 플로팅 창에서 잠금을 끌 수 있어요). `user`에서는 에이전트가 여전히 읽을 수는 있지만 모든 조작 호출이 `takeover`로 실패하고, 에이전트는 `wait_for_control`을 호출해 다시 맡겨질 때까지 기다릴 수 있어요.

## 동의와 개인정보 보호

기본 원칙: **API 키를 갖고 있거나 기기 코드를 안다고 해서 사용자의 페이지를 볼 수 있는 건 절대 아니에요.** 에이전트와 페이지 사이에는 서로 독립적인 여러 검사가 있어요.

| 계층 | 하는 일 |
|---|---|
| API 키 | 모든 MCP 요청에 키가 하나씩 실려요. 키에는 최대 권한 수준, 만료일(기본 90일), 선택적 IP 허용 목록이 있고, 키를 폐기하면 그 에이전트의 접속이 즉시 끊겨요. 기기 조회 실패는 속도 제한이 걸려 있어 기기 코드를 추측할 수 없어요 |
| 기기 코드 | 기기를 *식별*할 뿐이에요. 아무 권한도 주지 않아요 |
| 프로젝트 정책 | `approval: prompt`(새 프로젝트의 기본값)는 사용자의 승인을 요구하고, `maxLevel`은 어떤 에이전트든 할 수 있는 일의 상한을 정해요. 기기에 여러 프로젝트의 페이지가 있으면 가장 엄격한 정책이 적용돼요 |
| 사용자 승인 | 휴대폰에 에이전트 이름, 키 힌트, 선택할 수 있는 권한 수준이 표시되고, 사용자는 하나를 고르거나 거부해요. 대화상자는 Shadow DOM 안에 있고 실제(신뢰할 수 있는) 탭에만 반응하므로, 에이전트가 스스로 승인할 수 없어요. 세 번 거부하면 그 키는 10분 동안 그 기기에 접속할 수 없어요. 사용자는 자기 기기에서 자동 허용을 켤 수 있어요. 에이전트가 스스로 기기를 놓은 경우(연결 해제, 기기 전환, 접속 시간 소진)에는 10분 안에 대화상자 없이 돌아올 수 있고, 권한 수준은 사용자가 이전에 허용한 수준을 넘지 않아요. 사용자가 **종료**를 탭하거나, 콘솔 멤버가 세션을 종료하거나, 거부하거나, 키를 폐기하면 이 예외는 사라져요 |
| 권한 수준 | `observe`(스냅샷, 스크린샷, console, 네트워크 목록), `interact`(+ 클릭, 입력, 스크롤, 페이지 이동…), `advanced`(+ JavaScript 실행, 요청 본문, 저장소). 실제 권한 수준은 에이전트가 요청한 수준, 키, 정책, 사용자의 선택 중 가장 낮은 값이에요. **SDK가 페이지 안에서 게이트웨이와 별개로 이를 다시 강제해요** |
| 눈에 보이는 제어 | 에이전트가 접속해 있는 동안 페이지에 그 사실이 표시돼요. 에이전트 상태를 보여 주는 배지, 계획을 보여 주는 작업 카드, 모든 작업에 표시되는 에이전트 커서와 강조, 조작 중에 빛나는 테두리. 직접 조작, AI에 맡기기, 종료는 사용자의 탭에만 반응하고, 네이티브 호스트는 페이지 스크립트(에이전트 자신의 스크립트 포함)가 읽을 수 없는 비밀 값(`nativeKey`)을 제시해야 해요 |
| 민감한 작업 | `data-rwd-confirm`이 표시된(또는 정책의 `confirmSelectors`와 일치하는) 요소를 클릭하거나, 그런 요소가 있는 폼을 제출하면 휴대폰에서 사용자의 확인을 기다려요 |
| 마스킹 | 비밀번호 입력란, `data-rwd-mask` 요소, 정책의 선택자와 텍스트 패턴(전화번호, 카드 번호, 신분증 번호…)은 **페이지 안에서** 기기 밖으로 나가기 전에 `••••`로 바뀌어요. 스냅샷, 스크린샷, console 텍스트, 네트워크 URL과 본문, 저장소 값, 타임라인 요약 모두 해당돼요. `Cookie`, `Set-Cookie`, `Authorization` 헤더는 항상 가려져요. 정책의 `networkExclude` 규칙은 별개예요. 잡음(항상 404가 나는 폰트, 분석용 비컨)을 에이전트가 읽는 목록에서 빼 줄 뿐이고, 에이전트가 숨겨진 요청을 요청할 수 있으므로 개인정보 보호 수단이 아니에요 |
| 신뢰할 수 없는 콘텐츠 | 에이전트에게 넘기는 페이지 내용은 신뢰할 수 없는 데이터로 감싸서 표시하므로, 페이지에 심어 둔 지시가 사용자의 지시로 오인되지 않아요. 위험도가 높은 클릭은 에이전트의 판단이 아니라 사용자의 확인에 맡겨요 |
| 세션 로그 | 기기에 기록되고 어디로도 스트리밍되지 않아요. 읽으려면 다른 읽기와 마찬가지로 `observe`가 필요하고, 실패한 요청의 헤더와 본문에는 `advanced`가 필요해요. 마스킹 규칙은 기록 시점에 적용되므로, 마스킹된 입력란의 값은 나중에 가리는 게 아니라 처음부터 `••••`로 저장돼요. 프로젝트에서 로그를 끄고 저장된 내용을 삭제할 수 있어요 |
| 감사 | 로그인, 키와 멤버 변경, 접속 요청과 그 결정, 모든 RPC(메서드, 페이지, 지연 시간, 결과), 사용자의 직접 조작 전환과 종료, 거부된 호출. 페이지 내용이나 매개변수 값은 절대 기록하지 않아요 |

휴대폰 밖으로 나가는 것: `run()`이 호출된 순간부터 `hello`에 담긴 기기 메타데이터(사용자 에이전트, 페이지가 제공한 경우 `userId`, 앱 이름과 버전, 페이지 URL과 제목)와 짧은 타임라인 요약이 나가요. 그 밖의 모든 것은 접속한 에이전트가 요청할 때만 나가요. 게이트웨이는 페이지 내용을 저장하지 않아요. 스냅샷, 스크린샷, 로그는 에이전트에게 그대로 전달되고, 타임라인은 메모리에만 있어요. 세션 로그는 같은 마스킹 규칙에 따라 기기에 기록되고, 접속한 에이전트가 읽을 때까지 기기에 머물러요(아래 **데이터 저장** 참고).

분명히 밝혀 둘 만한 알려진 한계:

- 입력은 합성 이벤트예요. 이벤트의 `isTrusted`가 `false`이므로 이를 검사하는 페이지는 반응하지 않아요.
- `interact`로 에이전트는 어떤 `http(s)` URL로든 이동할 수 있어요. 프로젝트의 출처로 제한되지 않아요.
- `advanced`는 페이지에서 임의의 JavaScript를 실행해요. 그런 스크립트가 반환하는 값에는 마스킹이 적용될 수 없으니, 꼭 필요하지 않다면 `maxLevel`을 `interact`로 두세요.
- 네트워크 수집은 SDK가 로드된 뒤 페이지가 JavaScript로 보내는 요청(fetch, XHR, WebSocket, sendBeacon, EventSource)을 다뤄요. 이미지, 스크립트, 스타일시트, 네이티브 코드가 보내는 요청은 보이지 않아요. iframe 안의 내용은 스냅샷에 포함되지 않아요.
- 앱이 백그라운드로 가면 OS가 WebView를 일시 중지하고, 기기는 앱이 돌아올 때까지 오프라인이 돼요.
- 중단점, 단계 실행, 프로파일링, 힙 스냅샷은 범위 밖이에요. 이런 작업에는 Safari Web Inspector나 디버깅 가능한 WebView와 `chrome://inspect`를 쓰세요.

## 데이터 저장

게이트웨이는 기본적으로 **SQLite**(순수 Go, CGO 없음. 파일 위치는 `RWD_DATA`로 지정)를 쓰고, `RWD_DATABASE_URL`이 `postgres://` URL이면 **Postgres**를 써요. 스키마는 시작할 때 생성되고 마이그레이션돼요.

| 영구 저장(데이터베이스) | 메모리에만 있음(재시작하면 사라짐) |
|---|---|
| 프로젝트와 그 정책, 앱 키 | 연결된 페이지와 그 라벨 |
| 멤버(비밀번호는 PBKDF2-SHA256), 대기 중인 멤버 초대 | 제어 상태, 대기 중인 승인, 접속한 에이전트 |
| API 키(HMAC-SHA256 해시, 권한 수준, 만료일, IP 허용 목록) | 기기 타임라인 |
| 알려진 기기: ID, 코드, userId, 사용자 에이전트, 앱, 처음과 마지막으로 본 시각, 기기 토큰 해시 | 속도 제한 카운터 |
| 기기 초대(토큰 해시), 감사 로그 | |
| 설정: 첫 시작 때 생성되는 키 페퍼와 세션 서명 비밀 값 | |

재시작 후 페이지는 스스로 다시 연결되고(SDK가 백오프하며 재시도해요) 기기 코드도 그대로예요. 에이전트는 다시 접속하면 돼요. 실시간 상태는 프로세스 하나에 있으므로, 데이터베이스 하나에는 **게이트웨이 인스턴스 하나**만 실행하세요.

**게이트웨이가 아니라 휴대폰에.** 저장소 하나는 일부러 이 모든 것의 바깥에 있어요. 바로 페이지 SDK가 기기의 IndexedDB(데이터베이스 `rwd-log`)에 쓰는 **세션 로그**예요. 앱이 실행된 순간부터 방문한 페이지, 사용자의 탭과 입력, 에이전트의 작업, 제어 상태 변경, console 출력, 그리고 모든 요청(실패한 요청은 헤더와 본문까지)을 게이트웨이에 연결되든 안 되든 기록해요. 덕분에 버그가 생긴 *뒤에* 접속한 에이전트도 빈 버퍼에서 시작하지 않고 버그에 이르기까지의 전 과정을 읽을 수 있어요. 최근 세 번의 실행분을 각각 최대 10 MB까지 보관하고, 접속한 에이전트가 `get_session_overview` / `get_session_log`로 요청하지 않는 한 그 안의 어떤 것도 게이트웨이나 다른 누구에게도 전달되지 않아요([protocol.ko.md §5.4](protocol.ko.md#54-세션-로그)). 프로젝트에서 끌 수 있고(`policy.sessionLog`), 끄면 이미 기기에 저장된 내용도 삭제돼요. 개별 페이지는 `run({ record: false })`로 기록하지 않도록 할 수 있어요.

## 운영자를 위한 보안 참고 사항

- **HTTPS로 제공하세요.** 페이지는 `wss://`로 연결하고, 콘솔 쿠키는 HTTPS에서 `Secure`로 표시되고, API 키는 헤더에 실려 오가요. [deploy/platform](../deploy/platform/README.ko.md)의 Docker Compose 구성은 Caddy로 TLS를 종료하거나 직접 운영하는 프록시 뒤에 놓여요.
- **전달된 헤더는 프록시 뒤에서만 신뢰하세요.** `--trust-proxy`를 켜면 게이트웨이가 클라이언트 IP와 공개 호스트를 `X-Forwarded-For` / `X-Forwarded-Host`에서 가져와요. 앞단에 프록시가 없으면 누구나 이를 위조해 IP 허용 목록과 속도 제한을 피해 갈 수 있어요.
- **데이터베이스와 그 백업을 보호하세요.** 여기에는 키 페퍼와 세션 비밀 값이 들어 있어요. 이것들이 있으면 API 키 해시를 오프라인에서 대조하고 콘솔 세션을 위조할 수 있어요.
- **소유자 비밀번호.** `RWD_ADMIN_PASSWORD`는 시작할 때마다 소유자의 비밀번호를 재설정하므로 계정 복구 수단도 돼요. 새 데이터베이스에서 이 값이 설정되지 않았으면 무작위 비밀번호가 로그에 한 번 출력돼요.
- **앱 키는 공개 값이에요.** 페이지를 온라인으로 만드는 일만 할 수 있어요. 다른 사이트가 여러분의 앱 키를 쓰지 못하게 하려면 `allowedOrigins`를 쓰세요. 단, `Origin`은 브라우저가 강제하는 헤더라서 브라우저가 아닌 클라이언트는 아무 값이나 보낼 수 있어요. 그래서 기존 기기는 앱 키가 아니라 기기 토큰으로 보호해요.
- **API 키는 비밀번호처럼 다루세요.** 에이전트나 사람마다 따로 키를 주고, 동작하는 가장 낮은 권한 수준과 만료일을, 서버라면 IP 허용 목록도 설정하세요. 폐기는 즉시 적용돼요.
- **SDK를 고정하세요.** H5 페이지용으로 콘솔은 콘텐츠 주소 기반 SDK URL을 Subresource Integrity와 함께 불러오는 코드 조각을 제공해요. 네이티브 앱은 실행 중에 다운로드하는 대신 `sdk.js`를 앱에 포함할 수 있어서, 게이트웨이가 침해되더라도 앱에 새 코드를 밀어 넣을 수 없어요.
- **메트릭을 보호하세요.** `/v1/metrics`에 외부에서 접근할 수 있다면 `RWD_METRICS_TOKEN`을 설정하세요.
- 콘솔 로그인에는 속도 제한(IP당 분당 10회)이 있고, 쓰기 요청에는 사용자 지정 CSRF 헤더가 필요하며, 콘솔은 프레임 안에 넣을 수 없어요.

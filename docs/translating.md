# Translating the docs

The README and the docs are written in English and translated into Simplified Chinese, Traditional Chinese, Japanese, Korean, Spanish, French, German, Brazilian Portuguese, Russian and Arabic, the languages the console and the phone UI speak. English is the source: change it first, then bring the translations along. The changelogs are generated by the release scripts and exist in English and Simplified Chinese only.

## Layout

Each translation sits next to its English file with the language code before `.md`:

| Language | Suffix | Example |
|---|---|---|
| English | | `docs/protocol.md` |
| 简体中文 | `.zh-CN` | `docs/protocol.zh-CN.md` |
| 繁體中文 | `.zh-TW` | `docs/protocol.zh-TW.md` |
| 日本語 | `.ja` | `docs/protocol.ja.md` |
| 한국어 | `.ko` | `docs/protocol.ko.md` |
| Español | `.es` | `docs/protocol.es.md` |
| Français | `.fr` | `docs/protocol.fr.md` |
| Deutsch | `.de` | `docs/protocol.de.md` |
| Português (Brasil) | `.pt-BR` | `docs/protocol.pt-BR.md` |
| Русский | `.ru` | `docs/protocol.ru.md` |
| العربية | `.ar` | `docs/protocol.ar.md` |

Same folder, so relative links to code, examples and images work unchanged in every language. The list of translated docs and languages lives in [`scripts/docs/i18n.mjs`](../scripts/docs/i18n.mjs).

Every translation:

- starts with `<!-- i18n-source: <id> -->`, the git blob id of the English file it was translated from;
- has the language switcher line the check expects (current language in plain text, the others linked);
- has the same headings (count, levels, order), code blocks (count and language) and tables as the English file;
- links to the same-language version of other translated docs, with anchors taken from that version's headings;
- in Arabic, wraps the text in `<div dir="rtl">` and each code block in `<div dir="ltr">`.

Code, commands, identifiers and environment variables stay in English. Use the words the console and the phone UI use in that language.

## After changing an English doc

1. Run the check. `make check` runs it too.

   ```bash
   node scripts/docs/i18n.mjs check
   ```

   Every translation of the file you changed is reported as out of date, with a `git diff <old> <new>` that shows what changed in the English file since it was translated (the old blob is there once the English change is committed).
2. Apply the same change to each translation. Translate the meaning, not word for word; a translation may be done by a person or by a model, but read it before committing.
3. Mark them as synced, and check again:

   ```bash
   node scripts/docs/i18n.mjs stamp docs/protocol.*.md
   node scripts/docs/i18n.mjs check
   ```

Out-of-date translations are warnings, so an English fix can land before its translations; `check --strict` turns them into errors. A missing translation, a wrong switcher, a structure that no longer matches the English file, a broken link or a missing anchor is always an error.

## Adding a doc or a language

- **A doc:** add its English path to `DOCS` in `scripts/docs/i18n.mjs`, write the translations, stamp them.
- **A language:** add it to `LANGS` (the order is the switcher order), translate every doc, then update the switcher line in every existing language; the check prints the line it expects for each file. The new switcher changes every English file, so stamp all existing translations again afterwards.

# 架构

Remote WebView Debugger 让 AI agent 查看和操作打开在别人手机上的网页：手机浏览器或超级 App 里的 H5 页面，或者你自己 App 里的 WebView。agent 通过 MCP 连接自建的网关，网关再连接运行在页面里的轻量 SDK。手机用户批准接入后，能看到 agent 在做什么，并且随时可以接管。

本文介绍各个组成部分以及它们遵循的规则。具体的消息和接口见 [protocol.zh-CN.md](protocol.zh-CN.md)；App 接入见 [native-integration.zh-CN.md](native-integration.zh-CN.md)；部署见 [gateway/README.zh-CN.md](../gateway/README.zh-CN.md) 和 [deploy/platform/README.zh-CN.md](../deploy/platform/README.zh-CN.md)。

## 组成

```
  AI agent（Claude Code、Cursor 或任意 MCP 客户端）
        │  MCP：Streamable HTTP + Bearer API Key
        │  （或通过 `rwd mcp` 桥接 stdio）
        ▼
┌──────────────────────────── 网关（一个 Go 二进制）────────────────────────────┐
│  /v1/mcp      MCP 工具 ──────┐                                               │
│  /v1/api      REST + SSE ────┼──▶ hub：设备、页面、控制状态、接入审批、       │
│  /v1/page     页面 WebSocket ┘        时间线、RPC 转发          （内存）      │
│  /v1/sdk.js   内嵌的页面 SDK          store：SQLite 或 Postgres （持久化）    │
│  /            内嵌的控制台                                                   │
└───────────▲────────────────────────────────────────────▲──────────────────────┘
            │ HTTPS，cookie 会话                         │ WebSocket（wss://…/v1/page）
         控制台                                          │ 连不上时用 POST /v1/presence 轮询
     （客服、管理员）                                     │
                                  ┌──────────── 手机 ────┴──────────────────────┐
                                  │  H5 页面 / App WebView                      │
                                  │    页面 SDK：与网关的连接、界面              │
                                  │      （胶囊、对话框、锁定），在 Shadow DOM 里 │
                                  │    引擎：快照、操作、console 和网络记录、     │
                                  │      遮盖、级别检查                          │
                                  │  原生宿主（可选）：注入 SDK、真实截图、       │
                                  │    原生对话框和按钮                          │
                                  └─────────────────────────────────────────────┘
```

| 组成部分 | 路径 | 职责 |
|---|---|---|
| 网关 | [`gateway/`](../gateway) | Go 服务。接收页面连接，在内存里维护设备的实时状态，提供托管 MCP、控制台 REST API 和实时推送，记录审计日志。控制台和 SDK 都内嵌在里面，一个二进制就是整个服务端 |
| 页面 SDK | [`sdk/`](../sdk) | `sdk.js`，由页面加载或由 App 注入。负责连接、身份、页面内的界面、授权对话框和屏幕锁定 |
| 引擎 | [`packages/chobitsu/src/engine/`](../packages/chobitsu/src/engine) | agent 每个动作在页面里的那一半：无障碍快照（采用 Playwright 的 aria snapshot 代码）及盖在它上面的浮层、可操作性检查和合成输入、console 与网络记录（基于 [chobitsu](https://github.com/liriliri/chobitsu)）、截图、遮盖、级别检查 |
| 控制台 | [`console/`](../console) | React 单页应用：项目和接入代码、设备及其时间线、API Key、成员、策略、邀请、审计日志 |
| 原生宿主 | 你的 App；参考 [`examples/mock-app`](../examples/mock-app) | 在每个 WebView 开始加载时注入 SDK，保存设备 id 和设备令牌，提供真实截图，并可选地提供原生审批对话框和按钮 |

## 一次调试的过程

1. **页面上线。** 页面加载 `sdk.js`（或由 App 注入）。console、错误和网络记录立即开始，存在有上限的缓冲里，所以 agent 后来接入时也能看到之前发生的事。`run()` 向网关建立 WebSocket 并发送 `hello`，网关回复这台设备的**设备码**（如 `K7Q2-9M4X`）和项目的远程配置，页面上的胶囊显示设备码。
2. **有人把设备告诉 agent。** 用户口头报出设备码，或者点「请求协助」（设备会排在所有列表的最前面），或者打开客服发来的**邀请链接**，设备一上线就已在请求协助。
3. **agent 接入。** agent 用设备码调用 `connect_device`。除非项目另有配置，手机上会弹出「AI 请求接入」，用户选择级别（仅查看、查看并操作、高级）或者拒绝。在此之前，agent 什么都读不到。agent 一接入，屏幕就锁定用户输入，边缘出现光圈，底部控制条显示已连接时长。
4. **agent 工作。** 先拍快照拿到元素的 ref，再按 ref 点击、填写、滚动。快照里还会列出盖在页面上的弹窗和遮罩，各自带一个 ref；点击被浮层挡住时，错误信息会说明是哪个元素挡的、它的 ref 是什么——agent 可以直接点遮罩关掉弹窗，不用瞎猜。第一次操作会把设备从 *observe* 切到 *agent*，AI 光标标出它操作的位置。按级别不同，它还能读取 console、网络、存储和截图。
5. **用户始终说了算。** 点「接管」，页面交回用户，agent 暂停（它的操作会以 `takeover` 失败，直到用户点「交还 AI」）。点「结束」，agent 被断开。点击标记为敏感的元素（提交订单、支付、删除）之前，需要用户在手机上确认。
6. **agent 离开。** agent 调用 `disconnect_device` 离开；两分钟没有操作，设备回到 *observe*；到达项目设定的最长接入时长（默认 60 分钟）时自动断开。

一次操作的完整路径：

```
agent ─ click(ref=e12) ─▶ MCP 处理
   网关：API Key 有效？→ 已接入？→ 级别 ≥ interact？→ 用户没有接管？
         observe（已锁屏）→ agent → RPC {"method":"rwd.click","params":{"ref":"e12"}}
   ─── WebSocket ──▶ SDK：级别 ≥ interact？没有接管？敏感元素 → 请用户确认
                     引擎：等待元素可见、稳定、可用、命中测试通过（最多 5 秒）
                           移动 AI 光标、高亮，派发 pointer/mouse/touch 事件
   ◀── {"id":…, "result":{}} ───
   网关：审计记一条 "rpc"（方法、页面、耗时；不记载荷）
agent ◀─ "已点击 e12（页面 p2）。" + [会话变化]（新页面、跳转、错误、用户接管）
```

每个操作只需一次往返：可操作性检查和事件派发都在页面里完成，不走网络。

## 设备、页面与 agent

**设备。** 一个 `deviceId`：一个浏览器配置，或者原生宿主自己传入 id 时的一次 App 安装。网关给每台设备分配一个永久不变的设备码。设备不属于某个项目：同一台手机打开两个项目（两个接入 Key）的页面，仍是一台设备，页面列表里同时有两边的页面。API Key 也不属于项目，所以一个 MCP 服务就能访问所有设备。

**页面。** 一个标签页或一个 WebView，用 `pageId` 标识，同一标签页内刷新、跳转都不变。网关按设备给页面编号 `p1`、`p2`…，记录谁打开了谁，并跟踪哪个页面在前台。页面断开后标签保留两分钟，足够页面跳转后重新连上——除非同一个文档在别处又出现了：WebView 被重建、带着新的 `pageId` 连上来时，旧条目立即被替换；已断开的页面，如果有另一个在线页面显示同一个 URL，1.5 秒后就被清掉。这样被重建的 WebView 不会在页面列表里留下幽灵，agent 也会被切到真正还在的那个页面。

**时间线。** 每台设备有一条时间线（在内存里，保留最近 300 条）：页面的打开、跳转、刷新、回到前台、关闭；错误、失败的请求、用户的点击；协助请求、审批和控制状态变化。每个 MCP 工具结果的末尾都附带 agent 还没看过的时间线条目，agent 不用轮询就能发现新页面、错误和用户接管。在**跟随模式**（默认）下，agent 的操作打开了新页面，或者用户切到了另一个页面，agent 的当前页面会自动切过去。

**agent。** 网关按 API Key 保存 agent 状态：接入的设备和当前页面。一个 agent 同时只接入一台设备，一台设备同时最多一个 agent；新批准的 agent 会顶替原来的。

**控制状态。** 每台设备处于四种状态之一，由网关决定并广播给它的所有页面：

```
                 agent 接入                    第一次交互操作
       ┌──────┐ ───────────────▶ ┌─────────┐ ─────────────────────────▶ ┌───────┐
       │ none │                  │ observe │                            │ agent │
       └──────┘ ◀─────────────── └─────────┘ ◀───────────────────────── └───────┘
           ▲     agent 离开、         │        空闲（默认 2 分钟）         │
           │     结束、时长上限       │ 接管                          接管 │
           │                          ▼                                    ▼
           │                        ┌──────┐ ◀─────────────────────────────┘
           └─────────── 结束 ────── │ user │ ────── 交还 AI ──────▶ agent
                                    └──────┘
```

`observe` 和 `agent` 状态下用户的输入被拦截（用户可以在悬浮窗里关掉锁定）；`user` 状态下 agent 仍然能读取，但所有交互类调用都会以 `takeover` 失败，agent 可以调用 `wait_for_control` 等待用户交还。

## 授权与隐私

核心原则：**持有 API Key 或者知道设备码，都不足以看到用户的页面。** agent 和页面之间隔着多道相互独立的关卡。

| 关卡 | 作用 |
|---|---|
| API Key | 每个 MCP 请求都要带。Key 有最高级别、有效期（默认 90 天）和可选的 IP 白名单；吊销后它的 agent 立即被断开。查找设备失败会被限流，防止猜设备码 |
| 设备码 | 只用来**指认**设备，不授予任何权限 |
| 项目策略 | `approval: prompt`（新项目的默认值）要求用户批准；`maxLevel` 限制任何 agent 的权限上限。一台设备上有多个项目的页面时，取最严格的策略 |
| 用户审批 | 手机上显示 agent 名称、Key 尾号和可选的级别，用户选一个或者拒绝。确认框在 Shadow DOM 里，只响应真实（可信）的点击，agent 无法替自己点「允许」。同一个 Key 被拒 3 次，10 分钟内不能再请求这台设备。用户可以在自己的设备上选择开启自动允许。agent 自己放开设备（断开、转去别的设备、接入时长到上限）后，10 分钟内同一把 Key 可以不再弹窗直接回来，级别不超过用户上次授予的；用户点「结束」、控制台成员结束调试、用户拒绝一次请求或 Key 被吊销，都会让这个资格作废 |
| 级别 | `observe`（快照、截图、console、网络列表）、`interact`（再加点击、输入、滚动、跳转等）、`advanced`（再加执行 JavaScript、读取请求正文和存储）。生效级别取 agent 申请的、Key 的、策略的和用户选择的最小值。**SDK 在页面里会再检查一次**，与网关相互独立 |
| 可见与可控 | agent 接入期间页面上一直有提示：显示 agent 状态的胶囊、带计划步骤的任务卡片、每次操作时的 AI 光标和高亮、操作期间的边缘光圈。「接管」「交还 AI」「结束」只响应用户的点击；原生宿主调用时必须出示页面脚本（包括 agent 自己执行的脚本）读不到的密钥 `nativeKey` |
| 敏感操作 | 点击带 `data-rwd-confirm`（或匹配策略 `confirmSelectors`）的元素，或者提交包含这类元素的表单，要等用户在手机上确认 |
| 遮盖 | 密码框、带 `data-rwd-mask` 的元素，以及策略配置的选择器和文字规则（手机号、银行卡号、证件号等）**在页面里**就被替换成 `••••`，在任何数据离开设备之前：快照、截图、console 文本、网络 URL 和正文、存储值、时间线摘要都是如此。`Cookie`、`Set-Cookie`、`Authorization` 请求头始终脱敏。策略里的 `networkExclude` 是另一回事：它只是把噪音（一直 404 的字体、埋点上报）从 agent 看到的列表里挡掉，agent 想看还是能看，算不上隐私手段 |
| 不可信内容 | 交给 agent 的页面内容会被包起来并标明是不可信数据，避免页面里埋的指令被当成用户的指令。高风险点击靠用户确认把关，而不是靠 agent 自觉 |
| 会话日志 | 记录在设备本地，不会主动上传到任何地方：读取它和其他读取操作一样需要 `observe`，失败请求的请求头和正文需要 `advanced`。遮盖规则在记录时就生效，被遮盖字段的值直接存成 `••••`，不是事后再遮。项目可以关掉会话日志，并连同已存的内容一起删除 |
| 审计 | 登录、Key 和成员变更、接入请求与用户的决定、每个 RPC（方法、页面、耗时、结果）、用户的接管和结束、被拒绝的调用。从不记录页面内容和参数值 |

哪些数据会离开手机：从调用 `run()` 起，`hello` 里的设备信息（UA、页面提供的 `userId`、App 名称和版本、页面地址和标题）以及简短的时间线摘要；其余内容只有在已接入的 agent 请求时才会发出。网关不保存页面内容：快照、截图和日志只是转交给 agent，时间线只在内存里。会话日志在设备上记录（遮盖规则同样生效），在已接入的 agent 读取之前一直留在本地，见下面的**存储**。

需要说清楚的已知限制：

- 输入是合成的：事件的 `isTrusted` 为 false，校验这个属性的页面不会响应。
- `interact` 级别下 agent 可以跳转到任意 `http(s)` 地址，不限于项目的来源。
- `advanced` 可以在页面里执行任意 JavaScript，脚本返回的内容无法遮盖。除非确实需要，把 `maxLevel` 保持在 `interact`。
- 网络记录只覆盖 SDK 加载之后页面用 JavaScript 发起的请求（fetch、XHR、WebSocket、sendBeacon、EventSource），看不到图片、脚本、样式表和原生代码发起的请求。iframe 里的内容不在快照里。
- App 切到后台后，系统会暂停它的 WebView，设备在回到前台之前处于离线状态。
- 断点、单步、性能分析和内存快照不在范围内；需要时请用 Safari Web Inspector 或 `chrome://inspect` 配合可调试的 WebView。

## 存储

网关默认使用 **SQLite**（纯 Go，无需 CGO；文件路径由 `RWD_DATA` 指定）；`RWD_DATABASE_URL` 是 `postgres://` 地址时使用 **Postgres**。启动时自动建表和迁移。

| 持久化（数据库） | 只在内存里（重启后丢失） |
|---|---|
| 项目及其策略、接入 Key | 已连接的页面及其标签 |
| 成员（密码用 PBKDF2-SHA256）、待接受的成员邀请 | 控制状态、待处理的接入审批、已接入的 agent |
| API Key（HMAC-SHA256 哈希、级别、有效期、IP 白名单） | 设备时间线 |
| 出现过的设备：id、设备码、userId、UA、App、首次和最近在线时间、设备令牌的哈希 | 限流计数 |
| 设备邀请（令牌哈希）、审计日志 | |
| 设置：首次启动时生成的 Key pepper 和会话签名密钥 | |

重启后，页面会自动重连（SDK 按退避重试），设备码不变；agent 需要重新接入。实时状态在单个进程里，所以一个数据库只运行**一个网关实例**。

**有一份数据在手机上，不在网关上。** 那就是**会话日志**：页面 SDK 把它写进设备本地的 IndexedDB（数据库 `rwd-log`）。从 App 启动起，它记录访问过的页面、用户的点击和输入、agent 的操作、控制状态变化、console 输出和所有请求——失败的请求连请求头和正文一起——网关连不上也照样记。正因为有它，agent 在 bug 发生**之后**才接入，也能把来路完整读出来，而不是面对一个空缓冲。它保留最近三次启动，每次最多 10 MB；除了已接入的 agent 用 `get_session_overview` / `get_session_log` 主动读取（[protocol.zh-CN.md §5.4](protocol.zh-CN.md#54-会话日志)），里面的内容不会到网关、也不会到别人手里。项目可以整体关掉它（`policy.sessionLog`），关掉时会连同设备上已存的日志一起删除；单个页面也可以用 `run({ record: false })` 退出。

## 运维安全提示

- **用 HTTPS 提供服务。** 页面通过 `wss://` 连接，HTTPS 下控制台 cookie 带 `Secure`，API Key 在请求头里传输。[deploy/platform](../deploy/platform/README.zh-CN.md) 里的 Docker Compose 方案可以由 Caddy 直接签发证书，也可以放在你已有的反向代理后面。
- **只在代理后面信任转发头。** `--trust-proxy` 让网关从 `X-Forwarded-For` / `X-Forwarded-Host` 取客户端 IP 和对外域名。前面没有代理时，任何人都能伪造这些头，绕过 IP 白名单和限流。
- **保护好数据库和备份。** 里面有 Key pepper 和会话密钥，拿到它们就能离线校验 API Key 哈希、伪造控制台会话。
- **owner 密码。** `RWD_ADMIN_PASSWORD` 每次启动都会重设 owner 的密码，也可以用来找回账号。全新数据库上没有设置它时，会在日志里打印一次随机生成的密码。
- **接入 Key 是公开的。** 它只能让页面上线。用 `allowedOrigins` 防止别的网站用你的 Key；但 `Origin` 是浏览器负责填写的请求头，非浏览器客户端可以随意伪造，所以保护已有设备靠的是设备令牌，而不是接入 Key。
- **像对待密码一样对待 API Key。** 每个 agent 或每个人用自己的 Key，级别够用就好，设置有效期；服务器上使用的 Key 再加 IP 白名单。吊销立即生效。
- **固定 SDK 版本。** H5 页面可以用控制台提供的固定版本接入代码，它加载按内容寻址的 SDK 地址并带 SRI 校验。原生 App 可以把 `sdk.js` 打包进安装包，而不是运行时下载，这样即使网关被攻破，也无法向 App 推送新代码。
- **保护指标接口。** `/v1/metrics` 能从外部访问时，设置 `RWD_METRICS_TOKEN`。
- 控制台登录有限流（每 IP 每分钟 10 次），写操作必须带自定义的 CSRF 请求头，控制台页面不能被嵌入 iframe。

# البنية

يتيح Remote WebView Debugger لوكيل ذكاء اصطناعي فحص صفحة ويب مفتوحة على هاتف شخص آخر وتشغيلها: صفحة H5 في متصفح جوّال أو تطبيق شامل (super app)، أو WebView داخل تطبيقك أنت. يتحدث الوكيل بـ MCP إلى بوابة ذات استضافة ذاتية؛ وتتحدث البوابة إلى SDK صغير يعمل داخل الصفحة. يوافق مستخدم الهاتف على الاتصال، ويرى ما يفعله الوكيل، ويستطيع تولّي التحكم في أي لحظة.

يشرح هذا المستند الأجزاء المتحركة والقواعد التي تتبعها. الرسائل ونقاط النهاية بالتفصيل في [protocol.ar.md](protocol.ar.md)؛ والتكامل مع التطبيقات في [native-integration.ar.md](native-integration.ar.md)؛ والنشر في [gateway/README.ar.md](../gateway/README.ar.md) و [deploy/platform/README.ar.md](../deploy/platform/README.ar.md).

## جلسة تصحيح

1. **تتصل الصفحة.** تحمّل الصفحة `sdk.js` (أو يحقنه التطبيق). يبدأ التقاط console والأخطاء والشبكة فورًا، في مخازن مؤقتة محدودة، فيرى الوكيل الذي يتصل لاحقًا ما حدث قبل ذلك أيضًا. يفتح `run()` اتصال WebSocket بالبوابة ويرسل `hello`؛ فتردّ البوابة بـ **رمز الجهاز** (مثل `K7Q2-9M4X`) والإعداد البعيد للمشروع. وتعرض الشارة على الصفحة هذا الرمز.
2. **يوجّه أحدهم الوكيل إلى الجهاز.** يقرأ المستخدم رمز الجهاز بصوت عالٍ، أو ينقر **طلب المساعدة** (فيظهر الجهاز أولًا في كل قائمة)، أو يفتح **رابط دعوة** من فريق الدعم، فيتصل الجهاز وهو يطلب المساعدة مسبقًا.
3. **يتصل الوكيل.** يستدعي `connect_device` مع الرمز. ما لم يقرر المشروع خلاف ذلك، يرى المستخدم على هاتفه *AI wants to join*، فيختار مستوى (العرض فقط، العرض والتفاعل، متقدّم) أو يرفض. لا يمكن قراءة أي شيء قبل ذلك. وما إن يدخل الوكيل حتى تُقفل الشاشة في وجه إدخال المستخدم، وتتوهج الحواف، ويعدّ الشريط السفلي مدة الاتصال.
4. **يعمل الوكيل.** يأخذ لقطة للحصول على مراجع العناصر (refs)، ثم ينقر ويملأ ويمرّر بحسب المرجع. وتسرد اللقطة أيضًا النوافذ المنبثقة والخلفيات المعتمة التي تطفو فوق الصفحة، لكلٍّ منها مرجع، والنقرة التي تحجبها طبقة تفشل مع اسم الحاجب ومرجعه — فيستطيع الوكيل النقر على خلفية معتمة لإغلاق نافذتها المنبثقة بدلًا من التخمين. أول إجراء له ينقل الجهاز من *observe* إلى *agent*، ويُظهر مؤشر الوكيل موضع عمله. ويمكنه أيضًا قراءة console والشبكة والتخزين ولقطات الشاشة، بحسب مستواه.
5. **يبقى المستخدم صاحب القرار.** **تولّي التحكم** يعيد الصفحة إلى المستخدم ويوقف الوكيل مؤقتًا (تفشل إجراءاته بـ `takeover` إلى أن ينقر المستخدم **إعادة التحكم**). و **إنهاء** يفصل الوكيل. والنقر على العناصر المعلَّمة بأنها حساسة (تقديم طلب شراء، الدفع، الحذف) يحتاج إلى موافقة المستخدم على الهاتف.
6. **يغادر الوكيل** عبر `disconnect_device`؛ وبعد دقيقتين دون إجراءات يعود الجهاز إلى *observe*، وبعد الحد الأقصى لمدة الربط في المشروع (60 دقيقة افتراضيًا) يُفصل الوكيل.

إجراء واحد، من البداية إلى النهاية:

<div dir="ltr">

```
agent ─ click(ref=e12) ─▶ MCP handler
   gateway: API key valid? → attached? → level ≥ interact? → user hasn't taken over?
            observe (screen locked) → agent → RPC {"method":"rwd.click","params":{"ref":"e12"}}
   ─── WebSocket ──▶ SDK: level ≥ interact? not taken over? sensitive element → ask the user
                     engine: wait until visible, stable, enabled, hit-testable (≤ 5 s)
                             move the agent cursor, highlight, dispatch pointer/mouse/touch events
   ◀── {"id":…, "result":{}} ───
   gateway: audit "rpc" (method, page, latency; no payload)
agent ◀─ "Clicked e12 (page p2)." + [Session changes] (new pages, navigations, errors, takeovers)
```

</div>

كل إجراء رحلة ذهاب وإياب واحدة: فحوص قابلية التنفيذ وإطلاق الأحداث تجري داخل الصفحة، لا عبر الشبكة.

## الأجهزة والصفحات والوكلاء

**الجهاز.** `deviceId` واحد: ملف تعريف متصفح واحد، أو تثبيت واحد للتطبيق حين يمرّر المضيف الأصلي معرّفه الخاص. تمنح البوابة كل جهاز رمز جهاز دائمًا. الأجهزة غير مرتبطة بالمشاريع: الهاتف الذي يفتح صفحات من مشروعين (بمفتاحَي تطبيق) جهاز واحد عليه صفحات من كليهما. ومفاتيح API غير مرتبطة بالمشاريع كذلك، فيصل خادم MCP واحد إلى كل الأجهزة.

**الصفحة.** تبويب واحد أو WebView واحد، يُعرَّف بـ `pageId` يصمد أمام إعادة التحميل والتنقل في ذلك التبويب. تسمّي البوابة الصفحات `p1` و `p2` و… لكل جهاز، وتسجّل مَن فتح مَن، وتتتبع أيّ صفحة في المقدّمة. الصفحة التي ينقطع اتصالها تحتفظ بتسميتها لدقيقتين، وهي مدة تكفي لأن يعيد التنقل الاتصال — لكن ليس حين يظهر المستند نفسه مجددًا في مكان آخر: فالـ WebView التي يُعاد إنشاؤها تحت `pageId` جديد تحلّ محل المدخل القديم فورًا، والصفحة المنقطعة التي يعرض عنوانها URL صفحةٌ أخرى متصلة تُحذف بعد 1.5 ثانية. وهكذا لا تترك WebView المُعاد إنشاؤها شبحًا في قائمة الصفحات، ويُنقل الوكيل إلى الصفحة الموجودة فعلًا.

**الخط الزمني.** لكل جهاز خط زمني (في الذاكرة، آخر 300 حدث): الصفحات التي فُتحت أو تنقّلت أو أُعيد تحميلها أو صارت في المقدّمة أو أُغلقت؛ والأخطاء، والطلبات الفاشلة، ونقرات المستخدم؛ وطلبات المساعدة، والموافقات، وتغييرات التحكم. تنتهي نتيجة كل أداة MCP بمدخلات الخط الزمني التي لم يرها الوكيل بعد، فيلاحظ الصفحات الجديدة والأخطاء وتولّي التحكم دون استطلاع. في **وضع المتابعة** (الافتراضي) تنتقل الصفحة المحددة للوكيل إلى صفحة فتحها إجراؤه، أو إلى الصفحة التي انتقل إليها المستخدم.

**الوكيل.** تحتفظ البوابة بحالة وكيل واحدة لكل مفتاح API: الجهاز المرتبط به والصفحة المحددة. يرتبط الوكيل بجهاز واحد في كل مرة، وللجهاز وكيل واحد على الأكثر؛ والوكيل الذي تجري الموافقة عليه حديثًا يحلّ محل السابق.

**حالة التحكم.** يكون كل جهاز في واحدة من أربع حالات، تقررها البوابة وتبثّها إلى كل صفحاته:

<div dir="ltr">

```
                 agent attaches                first interactive action
       ┌──────┐ ───────────────▶ ┌─────────┐ ─────────────────────────▶ ┌───────┐
       │ none │                  │ observe │                            │ agent │
       └──────┘ ◀─────────────── └─────────┘ ◀───────────────────────── └───────┘
           ▲     agent leaves,        │        idle (default 2 min)        │
           │     End, time limit      │ Take over                Take over │
           │                          ▼                                    ▼
           │                        ┌──────┐ ◀─────────────────────────────┘
           └─────────── End ─────── │ user │ ────── Hand back ──────▶ agent
                                    └──────┘
```

</div>

في `observe` و `agent` يُحجب إدخال المستخدم (ويستطيع المستخدم إيقاف القفل من النافذة العائمة)؛ وفي `user` يظل الوكيل قادرًا على القراءة لكن كل استدعاء تفاعلي يفشل بـ `takeover`، ويمكن للوكيل استدعاء `wait_for_control` لانتظار إعادة التحكم.

## الموافقة والخصوصية

القاعدة الحاكمة: **امتلاك مفتاح API أو معرفة رمز جهاز لا يكفيان أبدًا لرؤية صفحة مستخدم.** تقف عدة فحوص مستقلة بين الوكيل والصفحة.

| الطبقة | ما تفعله |
|---|---|
| مفتاح API | يحمله كل طلب MCP. للمفاتيح مستوى أقصى، وتاريخ انتهاء (90 يومًا افتراضيًا)، وقائمة سماح IP اختيارية؛ وإبطال المفتاح يفصل وكيله فورًا. عمليات البحث الفاشلة عن الأجهزة مقيّدة المعدل كي لا يمكن تخمين رموز الأجهزة |
| رمز الجهاز | *يعرّف* الجهاز فقط. ولا يمنح شيئًا |
| سياسة المشروع | `approval: prompt` (الافتراضي للمشاريع الجديدة) يستلزم موافقة المستخدم؛ و `maxLevel` يحدّ ما يجوز لأي وكيل فعله. حين يحمل الجهاز صفحات من عدة مشاريع، تُطبَّق السياسة الأشد |
| موافقة المستخدم | يعرض الهاتف اسم الوكيل وتلميح مفتاحه والمستويات المعروضة؛ فيختار المستخدم أحدها أو يرفض. يعيش مربع الحوار في Shadow DOM ولا يستجيب إلا للنقرات الحقيقية (الموثوقة)، فلا يستطيع الوكيل الموافقة على نفسه. ثلاث حالات رفض تحظر ذلك المفتاح عن الجهاز لمدة 10 دقائق. يمكن للمستخدمين اختيار السماح التلقائي على أجهزتهم. الوكيل الذي ترك الجهاز بنفسه (قطع الاتصال، تبديل الجهاز، نفاد مدة الربط) يمكنه العودة خلال 10 دقائق دون مربع حوار جديد، بمستوى لا يتجاوز ما منحه المستخدم سابقًا؛ ويلغي ذلك نقرُ المستخدم على **إنهاء**، أو إنهاءُ عضو في لوحة التحكم للجلسة، أو الرفض، أو إبطال المفتاح |
| المستويات | `observe` (اللقطة، لقطة الشاشة، console، قائمة الشبكة)، و `interact` (+ النقر، الكتابة، التمرير، التنقل…)، و `advanced` (+ تشغيل JavaScript، أجسام الطلبات، التخزين). المستوى الفعلي هو الأدنى بين ما طلبه الوكيل، والمفتاح، والسياسة، واختيار المستخدم. **ويفرضه SDK مرة أخرى داخل الصفحة**، باستقلال عن البوابة |
| التحكم المرئي | ما دام وكيل مرتبطًا، تُظهر الصفحة ذلك: شارة بحالة الوكيل، وبطاقة مهمة بخطته، ومؤشر للوكيل وإبراز عند كل إجراء، وحافة متوهجة أثناء عمله. لا تستجيب أزرار تولّي التحكم وإعادة التحكم والإنهاء إلا لنقرات المستخدم؛ وعلى المضيف الأصلي تقديم سرّ (`nativeKey`) لا تستطيع سكربتات الصفحة قراءته، بما فيها سكربتات الوكيل نفسه |
| الإجراءات الحساسة | النقر على عنصر معلَّم بـ `data-rwd-confirm` (أو مطابق لـ `confirmSelectors` في السياسة)، أو إرسال نموذج يحتوي على مثله، ينتظر موافقة المستخدم على الهاتف |
| الإخفاء | حقول كلمات المرور، وعناصر `data-rwd-mask`، ومحدِّدات السياسة وأنماطها النصية (الهاتف، البطاقة، أرقام الهوية…) تُستبدل بـ `••••` **داخل الصفحة**، قبل أن يغادر أي شيء الجهاز: في اللقطات، ولقطات الشاشة، ونص console، وعناوين URL للشبكة وأجسامها، وقيم التخزين، وملخصات الخط الزمني. وتُنقَّح دائمًا ترويسات `Cookie` و `Set-Cookie` و `Authorization`. أما قواعد `networkExclude` في السياسة فأمر مختلف: فهي لا تفعل سوى إبعاد الضجيج (خطوط تُرجع 404 دائمًا، منارات التحليلات) عن القوائم التي يقرؤها الوكيل، ويستطيع الوكيل طلب الطلبات المخفية، فهي ليست أداة للخصوصية |
| المحتوى غير الموثوق | يُغلَّف محتوى الصفحة المسلَّم إلى الوكيل ويوسَم بأنه بيانات غير موثوقة، كي لا تُحسب التعليمات المزروعة في صفحة تعليماتٍ من المستخدم. وتعتمد النقرات عالية الخطورة على تأكيد المستخدم، لا على تقدير الوكيل |
| سجل الجلسة | يُسجَّل على الجهاز، ولا يُبثّ إلى أي مكان: قراءته تحتاج إلى `observe` كأي قراءة أخرى، وترويسات الطلبات الفاشلة وأجسامها تحتاج إلى `advanced`. تُطبَّق قواعد الإخفاء لحظة التسجيل، فتُخزَّن قيمة الحقل المخفي بصورة `••••`، لا تُخفى لاحقًا. ويمكن للمشروع إيقاف السجل وحذف ما خُزِّن منه |
| التدقيق | عمليات تسجيل الدخول، وتغييرات المفاتيح والأعضاء، وطلبات الربط وقراراتها، وكل RPC (الطريقة، الصفحة، زمن الاستجابة، النتيجة)، وتولّي المستخدم التحكمَ وإنهاؤه، والاستدعاءات المرفوضة. ولا يتضمن أبدًا محتوى الصفحة أو قيم المعاملات |

ما يغادر الهاتف: بيانات الجهاز الوصفية في `hello` (وكيل المستخدم user agent، و `userId` إن وفّرته الصفحة، واسم التطبيق وإصداره، وعناوين URL للصفحات وعناوينها) وملخصات قصيرة للخط الزمني، منذ لحظة استدعاء `run()`؛ وكل ما عدا ذلك لا يغادر إلا حين يطلبه وكيل مرتبط. لا تخزّن البوابة محتوى الصفحات: فاللقطات ولقطات الشاشة والسجلات تمرّ إلى الوكيل، والخطوط الزمنية تعيش في الذاكرة. يُسجَّل سجل الجلسة على الجهاز، بقواعد الإخفاء نفسها، ويبقى هناك إلى أن يقرأه وكيل مرتبط (انظر **التخزين** أدناه).

حدود معروفة تستحق أن تُقال صراحة:

- الإدخال مُصطنَع: للأحداث `isTrusted: false`، والصفحات التي تتحقق من ذلك لن تستجيب.
- يتيح `interact` للوكيل التنقل إلى أي عنوان `http(s)`؛ ولا يقتصر على أصول (origins) المشروع.
- يشغّل `advanced` شيفرة JavaScript اعتباطية في الصفحة. ولا يمكن للإخفاء أن يُطبَّق على ما يعيده سكربت كهذا، فأبقِ `maxLevel` عند `interact` ما لم تكن بحاجة إليه.
- يغطي التقاط الشبكة الطلبات التي تُجريها الصفحة من JavaScript بعد تحميل SDK (fetch، XHR، WebSocket، sendBeacon، EventSource). أما الصور والسكربتات وأوراق الأنماط والطلبات التي تُجريها الشيفرة الأصلية فلا تُرى. والمحتوى داخل iframes ليس جزءًا من اللقطات.
- حين ينتقل التطبيق إلى الخلفية يوقف نظام التشغيل الـ WebViews الخاصة به مؤقتًا، فيصبح الجهاز غير متصل حتى يعود.
- نقاط التوقف، والتنفيذ خطوة بخطوة، والتحليل الأدائي (profiling)، ولقطات الكومة (heap snapshots) خارج النطاق؛ استخدم لها Safari Web Inspector أو `chrome://inspect` مع WebView قابلة للتصحيح.

## التخزين

تستخدم البوابة **SQLite** افتراضيًا (Go خالصة، دون CGO؛ ملف يحدده `RWD_DATA`) أو **Postgres** حين يكون `RWD_DATABASE_URL` عنوانًا من نوع `postgres://`. يُنشأ المخطط ويُرحَّل عند بدء التشغيل.

| دائم (قاعدة البيانات) | في الذاكرة فقط (يُفقد عند إعادة التشغيل) |
|---|---|
| المشاريع وسياساتها، ومفاتيح التطبيق | الصفحات المتصلة وتسمياتها |
| الأعضاء (كلمات المرور بـ PBKDF2-SHA256)، ودعوات الأعضاء المعلّقة | حالة التحكم، والموافقات المعلّقة، والوكلاء المرتبطون |
| مفاتيح API (تجزئات HMAC-SHA256، والمستويات، وتواريخ الانتهاء، وقوائم سماح IP) | الخطوط الزمنية للأجهزة |
| الأجهزة المعروفة: المعرّف، والرمز، و userId، ووكيل المستخدم، والتطبيق، وأول ظهور وآخره، وتجزئة توكن الجهاز | عدّادات تقييد المعدل |
| دعوات الأجهزة (تجزئات التوكنات)، وسجل التدقيق | |
| الإعدادات: الفلفل (pepper) الخاص بالمفاتيح وسرّ توقيع الجلسات، ويُولَّدان عند أول تشغيل | |

بعد إعادة التشغيل، تعيد الصفحات الاتصال من تلقاء نفسها (يعيد SDK المحاولة مع تراجع تدريجي) وتحتفظ برموز أجهزتها؛ ويتصل الوكلاء من جديد. الحالة الحيّة تعيش في عملية واحدة، لذا شغّل **نسخة واحدة من البوابة** لكل قاعدة بيانات.

**على الهاتف، لا على البوابة.** ثمة مخزن واحد يقع عمدًا خارج كل ما سبق: **سجل الجلسة**، الذي يكتبه SDK الصفحة في IndexedDB على الجهاز (قاعدة البيانات `rwd-log`). منذ تشغيل التطبيق يسجّل الصفحات التي زارها المستخدم، ونقرات المستخدم وإدخاله، وإجراءات الوكيل، وتغييرات التحكم، ومخرجات console، وكل طلب — والفاشلة منها مع ترويساتها وأجسامها — سواء أمكن الوصول إلى البوابة أم لا. وهذا ما يتيح للوكيل الذي يرتبط *بعد* وقوع خلل أن يقرأ كل ما أدى إليه، بدلًا من البدء من مخزن مؤقت فارغ. يحتفظ بآخر ثلاثة تشغيلات، حتى 10 MB لكلٍّ منها، ولا يصل شيء منه إلى البوابة أو إلى أي أحد آخر إلا إذا طلبه وكيل مرتبط عبر `get_session_overview` / `get_session_log` ([protocol.ar.md §5.4](protocol.ar.md#54-سجل-الجلسة)). يمكن للمشروع إيقافه (`policy.sessionLog`)، وهذا يحذف أيضًا ما خُزِّن منه على أجهزته، ويمكن لصفحة بعينها الانسحاب عبر `run({ record: false })`.

## ملاحظات أمنية للمشغّلين

- **قدّمها عبر HTTPS.** تتصل الصفحات عبر `wss://`، ويُعلَّم ملف تعريف ارتباط لوحة التحكم بـ `Secure` على HTTPS، وتنتقل مفاتيح API في الترويسات. يُنهي إعداد Docker Compose في [deploy/platform](../deploy/platform/README.ar.md) اتصال TLS عبر Caddy أو يعمل خلف وكيلك الخاص.
- **لا تثق بالترويسات المُمرَّرة إلا خلف وكيل.** يجعل `--trust-proxy` البوابة تأخذ عناوين IP للعملاء ومضيفها العام من `X-Forwarded-For` / `X-Forwarded-Host`. ودون وكيل أمامها، يستطيع أي أحد تزويرها والالتفاف على قوائم سماح IP وتقييد المعدل.
- **احمِ قاعدة البيانات ونسخها الاحتياطية.** فهي تحتوي على فلفل المفاتيح وسرّ الجلسات؛ ومن يملكهما يستطيع التحقق من تجزئات مفاتيح API دون اتصال وتزوير جلسات لوحة التحكم.
- **كلمة مرور المالك.** يعيد `RWD_ADMIN_PASSWORD` تعيين كلمة مرور المالك عند كل تشغيل، وهو ما يصلح أيضًا لاسترداد الحساب. إن لم يُضبط على قاعدة بيانات جديدة، تُطبع كلمة مرور عشوائية مرة واحدة في السجل.
- **مفاتيح التطبيق عامة.** فهي لا تتيح سوى اتصال الصفحات. استخدم `allowedOrigins` لمنع المواقع الأخرى من استخدام مفاتيحك؛ ولاحظ أن `Origin` ترويسة يفرضها المتصفح، وأن العملاء غير المتصفحات يستطيعون إرسال أي قيمة، ولهذا تحمي توكنات الأجهزة (لا مفاتيح التطبيق) الأجهزةَ الموجودة.
- **عامِل مفاتيح API معاملة كلمات المرور.** امنح كل وكيل أو شخص مفتاحه الخاص، بأدنى مستوى يفي بالغرض، وتاريخ انتهاء، وللخوادم قائمة سماح IP. والإبطال فوري.
- **ثبّت SDK.** لصفحات H5، تقدّم لوحة التحكم مقتطفًا يحمّل SDK من عنوان معنون بالمحتوى مع Subresource Integrity. ويمكن للتطبيقات الأصلية تضمين `sdk.js` بدلًا من تنزيله وقت التشغيل، فلا تستطيع بوابة مخترقة دفع شيفرة جديدة إليها.
- **احمِ المقاييس.** اضبط `RWD_METRICS_TOKEN` إن كان `/v1/metrics` قابلًا للوصول من الخارج.
- تسجيل الدخول إلى لوحة التحكم مقيّد المعدل (10 محاولات في الدقيقة لكل IP)، وطلبات الكتابة تستلزم ترويسة CSRF مخصصة، ولا يمكن تضمين لوحة التحكم في إطار (frame).

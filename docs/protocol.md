# RWD protocol (v1)

This is the contract between the gateway ([`gateway/`](../gateway)), the page SDK ([`sdk/`](../sdk), with its engine in [`packages/chobitsu/src/engine/`](../packages/chobitsu/src/engine)), the console ([`console/`](../console)) and MCP clients. When the protocol changes, this document changes first.

For the big picture (components, consent model, storage, security) see [architecture.md](architecture.md); for app integration see [native-integration.md](native-integration.md).

Conventions:

- The **gateway URL** is `https://<host>/v1`, for example `https://rwd.example.com/v1`. Every endpoint lives under it; the SDK derives all addresses from it.
- JSON everywhere. Timestamps are Unix epoch **milliseconds**.
- `Level` is `"observe" | "interact" | "advanced"` (see [§6](#6-access-levels)).
- Fields not listed here are ignored by the receiver. New fields are always optional, so an older SDK keeps working with a newer gateway.

## 1. Endpoints

| Path | Description |
|---|---|
| `GET /v1/sdk.js` | Page SDK (an IIFE exposing the global `RemoteWebviewDebugger`). `Cache-Control: max-age=300`, `Access-Control-Allow-Origin: *` |
| `GET /v1/sdk/<version>/sdk.js` | The same file at an immutable, content-addressed URL (cached for a year; usable with SRI). Any other `<version>` is a 404. See [§16](#16-operations) |
| `GET /v1/locales/<id>.js`, `GET /v1/sdk/<version>/locales/<id>.js` | The SDK's on-demand language packs, which `sdk.js` loads from next to itself ([§15](#15-languages)). `Cache-Control: max-age=300` |
| `GET /v1/healthz` | `{"ok":true,"version":"…","db":"sqlite"\|"postgres"}` |
| `GET /v1/metrics` | Prometheus metrics ([§16](#16-operations)) |
| `WS /v1/page?key=<appKey>` | Page connection ([§3](#3-page-connection-websocket)) |
| `POST /v1/presence` | Polling fallback when the WebSocket can't connect ([§9](#9-presence-polling-fallback)) |
| `/v1/api/…` | Console REST API ([§12](#12-console-rest-api)) |
| `/v1/mcp` | Hosted MCP server, Streamable HTTP, `Authorization: Bearer rwd_sk_live_…` ([§14](#14-mcp)) |
| `/demo/` | Static files from `--demo-dir`, only when configured |
| any other path | Console single-page app |

Unknown paths under `/v1/` return `404 {"error":{"code":"not_found",…}}`. All responses carry `X-Content-Type-Options: nosniff` and `Referrer-Policy: no-referrer`; everything except the SDK also carries `X-Frame-Options: DENY`.

## 2. Identifiers

| Name | Format | Origin |
|---|---|---|
| App key | `rwd_pk_` + 24 base62 characters | Created with a project. Public: it appears in page source and only lets a page come online |
| API key | `rwd_sk_live_` + 32 base62 characters | Created in the console, shown once. Stored as HMAC-SHA256 with a server-side pepper. The console shows its first 16 characters (`prefix`, e.g. `rwd_sk_live_ab12`); devices see `"…"` plus the last 4 characters of the prefix (`keyHint`) |
| `deviceId` | UUID v4 (any `[A-Za-z0-9_-]{1,64}` is accepted) | Generated by the SDK and kept in localStorage `rwd:device`, or passed by a native host with `run({ deviceId })` |
| Device code | `XXXX-XXXX` over `23456789ABCDEFGHJKMNPQRSTUVWXYZ` | Assigned by the gateway the first time it sees a `deviceId`; never changes. When an agent connects with one, case, dashes and spaces don't matter |
| `pageId` | 12 base62 characters (any `[A-Za-z0-9_-]{1,64}` is accepted) | Generated by the SDK, kept in sessionStorage `rwd:page`: stable across reloads and navigations in the same tab, new for each tab |
| Page label | `p1`, `p2`, … | Assigned by the gateway per device; kept while the page reconnects within the 2-minute grace period |
| Session (launch) id | The host app's own launch id (4–128 characters of `[A-Za-z0-9_.:-]`), else 16 hex characters from the SDK | One launch of the app, under which the page files its session log ([§5.4](#54-session-log)). Never sent to the gateway except in a `rwd.log` result |
| `ref` | `e12`, `o3`, … | `eN`: an element of the page's most recent snapshot, valid until the next snapshot of that page. `oN`: an element the snapshot has no node for — an overlay, or whatever covers a click point ([§5.3](#53-behavior-in-the-page)); it stays valid while that element is in the page |
| Device token | 64 hex characters | Issued once per `deviceId` ([§3.5](#35-device-token-resume-token-and-invites)); the gateway stores only a hash |
| Resume token | 32 hex characters | Rotated by every `welcome` ([§3.5](#35-device-token-resume-token-and-invites)); stored as a hash |

## 3. Page connection (WebSocket)

### 3.1 Lifecycle

1. The page opens `wss://<host>/v1/page?key=<appKey>`. Before the upgrade the gateway checks:
   - rate limit: 120 connections (and presence calls) per minute per client IP → `429 rate_limited`;
   - the app key exists and its project is not disabled → else `401 bad_key`;
   - if the project has `allowedOrigins`, the `Origin` header must match one → else `403 origin_not_allowed`.
2. Text frames only, one JSON object per frame. Inbound messages may be up to 16 MiB (screenshots arrive base64-encoded).
3. The page must send `hello` within **5 seconds**. A malformed `hello` (bad JSON, wrong `t`, invalid `deviceId` / `pageId`) is closed with `1008`.
4. The gateway answers with `welcome` ([§3.4](#34-welcome)), or closes with a protocol close code ([§3.6](#36-close-codes)).
5. The gateway sends `{"t":"hb"}` every **25 seconds**, plus a WebSocket ping that must be answered within 10 seconds. The SDK reconnects when it hears nothing for **60 seconds**.
6. SDK reconnects back off exponentially from 1 s to 30 s, each delay drawn at random from the upper half of the current step. After **3 consecutive attempts that end before a `welcome`**, the SDK switches to presence polling ([§9](#9-presence-polling-fallback)).
7. A second connection with the same `pageId` replaces the first one (closed with `1000 replaced`).
8. A page that disconnects keeps its label and place for a **2-minute grace period** (navigations reconnect well within it). After that it is `closed` on the timeline. Two cases cut the wait short, so a recreated WebView does not sit in the page list as *reconnecting*:
   - a page that connects with a **new `pageId`** drops every disconnected page showing the same URL (the `#` fragment is ignored) right away;
   - a disconnected page whose URL a **connected** page also shows is dropped after **1.5 s** instead.

   Either way, if the dropped page was the agent's selected page, the selection moves to the live page and the result says so ([§14.3](#143-tools)).
9. The SDK closes the socket on `pagehide` (so the page can enter the back/forward cache) and reconnects on `pageshow`.

Each connection has a 64-message send queue. A page that can't keep up is closed with `1013 slow consumer` rather than slowing down the gateway.

### 3.2 Page → gateway

```jsonc
{"t":"hello","v":1,"sdk":"<SDK version>",
 "deviceId":"…","pageId":"…","openerId":"<pageId>"|null,
 "userId":"<string>"|null,
 "page":{"url":"…","title":"…","visibility":"visible"|"hidden"},
 "device":{"ua":"…","platform":"ios"|"android"|"web",
           "screen":{"w":393,"h":852,"dpr":3},
           "app":{"name":"…","version":"…"}|null},
 "help":false,
 "deviceToken":"<token>"|null,   // always present in current SDKs, see §3.5
 "resume":"<token>"|null,        // the last resume token this pageId received
 "invite":"<token>"|null}        // from ?rwd_invite=…

{"t":"page","url":"…","title":"…","visibility":"visible"|"hidden"}   // on change
{"t":"event","kind":"error"|"console_error"|"net_fail"|"user_tap","summary":"…","at":1730000000000}
{"t":"help","on":true}                                              // the user asks for help / cancels
{"t":"control","action":"takeover"|"handback"|"end"}                // the user's buttons, §4
{"t":"attach_decision","requestId":"…","level":"interact"|null}     // §7
{"id":17,"result":{…}}                                              // RPC success, §5
{"id":17,"error":{"code":"not_found","message":"…"}}                // RPC failure, §5
```

- `hello`: the gateway keeps `userId` (up to 128 characters), `ua` (512), `platform` (16), `app`, `url` (2048) and `title` (256). `screen` is informational.
- `event.summary` is one sentence for the agent, already scrubbed of masked values, e.g. `TypeError: Cannot read properties of undefined (reading 'orderId')`, `POST /api/order → 405`, `Tapped button "Place order"`. The gateway records each kind on the timeline (up to 300 bytes) and ignores unknown kinds. Navigations, in-page ones included, are not events: the gateway derives them from `page` messages (`navigated` on the timeline, [§12.9](#129-timeline-events)); the SDK keeps them in the session log ([§5.4](#54-session-log)).
- The SDK de-duplicates events (same kind and summary within 2 s) and sends at most 30 per 10 s. Events and control actions raised while offline wait in a queue (up to 100 messages) for the next `welcome`.
- `help` and `control` are only sent for taps by the user (or calls from the native host, [§10](#10-javascript-api-for-hosts)).

### 3.3 Gateway → page

```jsonc
{"t":"welcome", …}                                            // §3.4
{"t":"control","state":"none"|"observe"|"agent"|"user",
 "agent":{"name":"Support Bot"}|null,"level":"interact"|null,
 "attachedMs":83000|null}                                     // §4, to every page of the device
{"t":"help","on":false}                                       // help cleared: an agent attached, a console member ended the session, or the user ended it on the device
{"t":"task","task":{"title":"…","steps":["…"],"current":0,"agent":"Support Bot"}|null}  // §14.3 set_task
{"t":"attach_request", …}                                     // §7, to the foreground page
{"t":"attach_cancel","requestId":"…"}                         // §7, to every page
{"t":"hb"}
{"t":"reconnect","afterMs":1000}                              // reserved: the SDK reconnects after afterMs
{"id":17,"method":"rwd.snapshot","params":{}}                 // RPC request, §5
```

`reconnect` is understood by the SDK; the gateway does not send it today.

### 3.4 `welcome`

```jsonc
{"t":"welcome",
 "deviceCode":"K7Q2-9M4X",
 "label":"p1",
 "help":false,
 "control":{"state":"none","agent":null,"level":null,"attachedMs":null},
 "level":null,                       // same as control.level
 "resume":"<new resume token>",
 "deviceToken":"<token>",            // only when issued by this welcome
 "config":{"helpButton":false,"maskSelectors":[],"maskPatterns":[],
           "confirmSelectors":[],"networkExclude":[],"sessionLog":true,
           "eruda":{"dock":false,"load":false}},   // or null, see below
 "agentLang":"en",                   // the gateway's language: "en", "zh", "zh-TW", "fr"…, §15
 "task":{…}}                         // only while the attached agent has set one
```

`config` is the remote configuration from the policy of the project whose app key the page used ([§11](#11-project-policy)). `config.helpButton` is already resolved for this page's `userId` (`all`, or `listed` and the user is listed). `config.networkExclude` is added to the rules the page itself passed to `run({ networkExclude })` ([§10](#10-javascript-api-for-hosts)). `config.sessionLog` is the project's switch for the session log; `false` stops the recording and deletes what this origin already kept ([§5.4](#54-session-log)). `config.eruda` is the project's eruda policy ([§11](#11-project-policy)); it may also be `null` or absent (a gateway or a stored `config` from before the field existed), which the SDK reads as `{"dock":false,"load":false}`, and the page's own `run({ eruda })` still wins field by field ([§10](#10-javascript-api-for-hosts)). The SDK keeps the last `config` in localStorage `rwd:cfg` and applies it on the next page until its `welcome` arrives.

If an attach request is pending and the reconnecting page is the device's foreground page, the gateway sends the `attach_request` again right after the `welcome`.

### 3.5 Device token, resume token and invites

**Device token.** The first time the gateway sees a `deviceId` from a token-aware SDK, it issues a device token in `welcome.deviceToken` (32 random bytes, hex; only a hash is stored). From then on every page of that device must present it in `hello.deviceToken`; a missing or wrong token is closed with **4401**. Knowing a `deviceId` and the public app key is therefore not enough to join someone's device.

- The SDK stores the token in localStorage `rwd:dtoken` and exposes it as `status().deviceToken`. localStorage is per origin, so a native host that loads several domains keeps the token itself and passes it back with `run({ deviceToken })` ([native-integration.md](native-integration.md)).
- A hello that has a `deviceToken` field (even `null`) is token-aware. A hello without the field comes from an SDK that can't keep a token; the gateway doesn't issue one to it (that would lock the device's later pages out), but once a device has a token, every page must present it.

**Resume token.** Every `welcome` carries a new `resume` token bound to the `pageId`. When a page with a known `pageId` reconnects, its `hello.resume` must match the last one issued, else the connection is closed with **4409** and the SDK starts over with a new `pageId`. Knowing a `pageId` is therefore not enough to impersonate a page.

**Invite.** When the page URL carries `?rwd_invite=<token>`, the SDK removes the parameter from the address bar (`history.replaceState`), keeps the token in sessionStorage and sends it in `hello.invite` until a `welcome` arrives. The gateway accepts it if the invite belongs to the same project, is unused and unexpired: the device is marked `invited` and asking for help, the timeline records which invite it came from, and the invite is used up. Invalid invites are ignored silently. See [§12.6](#126-device-invites).

### 3.6 Close codes

| Code | Meaning | SDK reaction |
|---|---|---|
| `1008` | Malformed `hello` | Reconnect with backoff |
| `1013` | The page couldn't keep up with its send queue | Reconnect with backoff |
| `4401` | Device token missing or wrong | If the stored token changed meanwhile (another tab just received it), retry at once; else state `rejected`, retry in about 10 minutes |
| `4409` | Resume token mismatch | New `pageId`, reconnect |
| `4429` | The project's online device quota (`maxOnlineDevices`) is reached | State `quota`, retry in about 5 minutes |

## 4. Control state

Each device has one control state, which the gateway decides and broadcasts to all of the device's pages with a `control` message.

| State | Meaning | Page UI |
|---|---|---|
| `none` | No agent attached | Collapsed pill with the device code (plus the help button when enabled) |
| `observe` | An agent is attached and only looking | "AI is viewing", user input is blocked (unless the user turned the lock off), glowing screen edge, **Take over** and **End** buttons |
| `agent` | The agent is operating the page | "AI working", the same lock, edge, and buttons, plus the agent's cursor |
| `user` | The user took over | No lock, a static edge, **Hand back** and **End** buttons |

Transitions:

| Trigger | Change |
|---|---|
| An agent attaches ([§7](#7-attach-approval)) | `none` → `observe` |
| The agent calls an interactive tool (click, fill, type, press, select, hover, scroll, drag, navigate, back, reload) | `observe` → `agent`. In `user` the gateway refuses with error `takeover` without contacting the page |
| No interaction for `policy.agentIdleMinutes` (default 2; checked every 10 s) | `agent` → `observe` |
| The page sends `control: takeover` | `observe` / `agent` → `user` |
| The page sends `control: handback` | `user` → `agent` (or `none` if no agent is attached) |
| The page sends `control: end` | The agent is detached and help is cleared → `none` |
| The agent disconnects or is replaced, its key is revoked, `policy.attachMaxMinutes` (default 60) runs out, or a console member ends the session | → `none` |

The page locks from the moment an agent attaches (`observe`), not only once it acts, and stays locked through `agent` → `observe` on idle until the user takes over or the state goes back to `none`.

`attachedMs` is how long the attached agent has been attached, in milliseconds, at the moment the gateway sent the message (`null` without an agent). It is a duration so the page needs no clock in common with the gateway; the bottom bar shows it as a running "Connected · 01:23" timer in `observe`, `agent` and `user`, and "Connecting…" while the page's own link is down. A gateway without the field leaves the SDK counting from when the page first saw the agent.

The SDK also refuses interactive RPCs with `takeover` while the user holds control, as a second check. It remembers the state (and when the agent attached) for 2 minutes in localStorage `rwd:ctl`, so the next page after a navigation locks immediately, with the timer running, instead of waiting for its `welcome`. Take over, hand back and end only respond to the user's trusted taps; an agent can't press them, and a native host must present the `nativeKey` ([§10](#10-javascript-api-for-hosts)).

## 5. Page RPC

### 5.1 Envelope

The gateway sends `{"id":<n>,"method":"rwd.…","params":{…}}` to one page; the page replies with `{"id":<n>,"result":{…}}` or `{"id":<n>,"error":{"code":"…","message":"…"}}`. Ids are unique per connection. If the connection drops, pending calls fail at once.

Timeouts on the gateway side: 20 s for MCP calls, 45 s for `rwd.click`, `rwd.press` and `rwd.type` with `submit: true` (the user may be asked to confirm, [§8](#8-sensitive-action-confirmation)), 15 s for the console's connection test.

Error codes:

| Code | Meaning |
|---|---|
| `not_found` | Stale `ref` or element gone, unknown option, unknown request id |
| `not_interactable` | Not visible, disabled, covered, read-only, or not stable within 5 s |
| `timeout` | A wait ran out (in the page or at the gateway) |
| `takeover` | The user holds control |
| `forbidden` | Above the granted level ([§6](#6-access-levels)), or the user denied a confirmation |
| `bad_request` | Missing or invalid parameter, unknown method |
| `internal` | Anything else (the message carries the JavaScript error) |

Messages written by the SDK are in the agent's language (`welcome.agentLang`, [§15](#15-languages)).

### 5.2 Methods

Every method acts on the page that receives it.

| Method | Level | params | result |
|---|---|---|---|
| `rwd.ping` | observe | `{}` | `{"at":<ms>}` |
| `rwd.snapshot` | observe | `{}` | `{"url","title","snapshot"}`: an accessibility snapshot in Playwright's AI format (YAML, elements tagged `[ref=eN]`), followed by an overlays section when something floats over the page ([§5.3](#53-behavior-in-the-page)) |
| `rwd.query` | observe | `{"text"?,"role"?,"name"?,"limit"?:20}` (at least one criterion; `limit` 1–100) | `{"matches":[{"ref","role","name","text"}],"total"}` |
| `rwd.screenshot` | observe | `{"format"?:"jpeg"\|"png"\|"webp","quality"?:80,"fullPage"?:false,"ref"?}` | `{"data":"<base64>","mimeType","source":"native"\|"dom","width","height"}` |
| `rwd.console` | observe | `{"sinceId"?,"limit"?:100,"types"?:["error","warn"]}` | `{"messages":[{"id","type","text","at","source"?}],"dropped"}` |
| `rwd.network` | observe | `{"sinceId"?,"limit"?:100,"failedOnly"?:false,"exclude"?:[],"includeExcluded"?:false}` | `{"requests":[{"id","method","url","status","type","durationMs","size","error"?,"at"}],"dropped","hidden"}` |
| `rwd.waitFor` | observe | `{"text"?,"textGone"?,"timeMs"?,"timeoutMs"?:10000}` | `{}` |
| `rwd.log` | observe | `{"op":"sessions"\|"overview"\|"records", …}`, see [§5.4](#54-session-log) | Depends on `op` |
| `rwd.click` | interact | `{"ref","button"?:"left","clickCount"?:1}` | `{}` |
| `rwd.hover` | interact | `{"ref"}` | `{}` |
| `rwd.fill` | interact | `{"ref","value"}` | `{}` |
| `rwd.type` | interact | `{"text","ref"?,"submit"?:false}` | `{}` |
| `rwd.press` | interact | `{"key"}`: Playwright key names, combinations such as `Control+A` | `{}` |
| `rwd.select` | interact | `{"ref","values":["…"]}` | `{"selected":["…"]}` |
| `rwd.scroll` | interact | `{"ref"?,"dx"?:0,"dy"?:0}` | `{}` |
| `rwd.drag` | interact | `{"fromRef","toRef"}` | `{}` |
| `rwd.navigate` | interact | `{"url"}` | `{}` (the page then reconnects) |
| `rwd.back` / `rwd.reload` | interact | `{}` | `{}` |
| `rwd.evaluate` | advanced | `{"function":"() => …","args"?:[]}` | `{"value":<JSON>}` |
| `rwd.networkDetail` | advanced | `{"id"}` | `{"request":{"headers","body"?},"response":{"headers","body"?}}` |
| `rwd.storage` | advanced | `{"area":"local"\|"session"\|"cookie"}` | `{"entries":[{"key","value"}]}` |
| `rwd.logDetail` | advanced | `{"seq"}` | One session-log record in full: `{"seq","session","at","kind","page","imp","size","data"}`, headers and bodies included ([§5.4](#54-session-log)) |

Details:

- `rwd.query` matches `role` exactly (ignoring case) and `name` / `text` as case-insensitive substrings; `text` covers an element's own and its descendants' text, and only the innermost match is returned.
- `rwd.fill` works on text inputs, textareas and `contenteditable` elements (a `<label>` is retargeted to its control). It sets the value through the native setter and dispatches `input` and `change`, so React and Vue controlled inputs see the change. A `<select>` needs `rwd.select`.
- `rwd.type` focuses `ref` (caret at the end) if given, else types into the focused element; `submit: true` presses Enter afterwards.
- `rwd.select` matches each value against an option's value, label or text. Several values need a `multiple` select.
- `rwd.scroll` without `ref` scrolls the page; with `ref` it dispatches a wheel event at the element and scrolls its scrollable ancestor. Scrolls are animated over about 0.3 s so the user can follow.
- `rwd.navigate` accepts absolute or relative `http(s)` URLs only. Navigation, back and reload happen 50 ms after the reply is sent.
- `rwd.waitFor` first sleeps `timeMs` (at most 60 s), then polls the visible text (`document.body.innerText`) every 100 ms until `text` appears and `textGone` disappears, or fails with `timeout` after `timeoutMs`.
- `rwd.screenshot` uses the host app's native capture when one is registered and the region is inside the viewport (`source: "native"`), else re-renders the DOM (`source: "dom"`; canvas, video and cross-origin images may be blank). `ref` crops to the element; `fullPage` captures the whole document. See [§10](#10-javascript-api-for-hosts).
- `rwd.console` / `rwd.network` with `sinceId` return the oldest `limit` entries after it; without, the latest `limit`. Requests in flight have `status: 0` and `durationMs: null`; `type` is `xhr`, `fetch`, `websocket`, `beacon` or `eventsource`.
- `rwd.network` leaves out the requests the exclude rules match — the project's `networkExclude` plus `run({ networkExclude })` ([§11](#11-project-policy)), plus `exclude` for this call only — and `hidden` counts them. `includeExcluded: true` returns them all and leaves `hidden` at 0. Excluded requests are still recorded, and `rwd.networkDetail` still returns them by id.
- `rwd.networkDetail` redacts the `Cookie`, `Set-Cookie`, `Authorization` and `Proxy-Authorization` headers; bodies are masked and cut at 64 KB.
- `rwd.storage` returns at most 500 entries with values cut at 4000 characters. Cookies are those visible to scripts (not HttpOnly). The SDK's own `rwd:dtoken` and `rwd:resume` are always masked.
- `rwd.evaluate` evaluates the function source in the page's global scope and calls it with `this = window`; it may return a promise. The result is made JSON-safe: `undefined` and functions become `null`, elements a short tag description, dates ISO strings, cycles `"[Circular]"`.

### 5.3 Behavior in the page

- **Actionability.** Pointer actions wait (up to 5 s) until the element is connected, visible, stable across two animation frames, enabled and scrolled into view, and a hit test at the target point lands on the element or a descendant. The point tried first is the element's visible centre, as a finger would; if something covers it, the other spots of a 3×3 grid inside its visible box are tried, so a badge over a button doesn't block the click. When every spot is covered, the call fails with `not_interactable` and a message naming the obscuring element and its `ref` (*the click point is covered by `<div.popup-mask>` (ref=o1; click it directly…)*), which the agent can click instead. The hit test skips the SDK's own UI and other debugging tools (`.__chobitsu-hide__`, `#eruda`, `#__pageSpy`, `#__vconsole`).
- **Overlays.** A snapshot ends with an `[Overlays]` section when layers float over the page: a popup's backdrop, a modal, a bottom sheet. They are found by hit-testing a few points of the viewport and keeping whatever sits in a fixed (or viewport-sized absolute) box that covers at least 15% of the viewport and does not itself contain half of the snapshot's elements (that would be the app's own root, not a layer over it). Each line gives the element's tag, a few words of its (scrubbed) text, the share of the viewport it covers and a `ref`; a layer with no text and no media is listed as a backdrop. An empty backdrop has no node in the aria snapshot, so it gets an `oN` ref — that is what lets an agent tap a backdrop to close its popup.
- **Synthetic input.** A click dispatches `pointerover/enter → pointerdown → mousedown → focus → pointerup → mouseup → click`, plus touch events on touch devices. These events have `isTrusted: false`; pages that check it won't react.
- **Feedback.** The target is briefly highlighted, and an on-page agent cursor moves to it before input is dispatched.
- **Masking.** Values of `input[type=password]`, elements with `data-rwd-mask` and the project's `maskSelectors` are replaced with `••••` in snapshots and screenshots (native screenshots get grey boxes over them). Those values, and text matching `maskPatterns`, are also replaced in console text, network URLs and bodies, storage values and event summaries.
- **Snapshot scope.** The snapshot is rooted at `<body>`. The SDK's UI lives in a Shadow DOM under `<html>`, outside `<body>`; eruda, PageSpy and vConsole nodes are removed from the snapshot.
- **Buffers.** Console, uncaught errors and network (XHR, fetch, WebSocket, sendBeacon, EventSource) are recorded from the moment the SDK loads, in ring buffers of 500 entries each. When full, plain logs and successful requests are dropped first; `dropped` counts them. Response bodies are cached up to 5 MB in total, 64 KB each.

### 5.4 Session log

The buffers of [§5.3](#53-behavior-in-the-page) live in one page's memory. The **session log** is the long version: everything that happened on this origin since the app was launched, written to **IndexedDB** (database `rwd-log`) by every page of the origin, whether or not the gateway is reachable. An agent that attaches after the fact can therefore read the whole way to a bug, across reloads and pages. It never leaves the device unless an attached agent asks for it.

**A session is one launch of the app.** The id is resolved in this order:

1. `run({ launchId })` — the host app's own launch id, generated at every cold start and the same for every WebView of that process;
2. `window.RWDLaunchId`, which the host or the integration snippet may define: a string, or a function returning a string (or a promise of one, awaited for at most 300 ms);
3. inferred by the SDK: a session cookie `rwd_launch` (no expiry, so it dies with the app process) plus a heartbeat every 10 s. A cookie session that has been silent for more than **1 hour** is treated as an earlier launch and a new id is started, which catches WebViews that keep session cookies across launches.

The `source` of a session says which it was: `app` for 1 and 2, `cookie` for 3.

**What is recorded.** Each record has `seq` (the key, increasing), `at`, `kind`, `page` (the writing page's `pageId`) and `data`:

| `kind` | `data` |
|---|---|
| `page` | `event: "open"` (url, title, referrer), `"nav"` (from, url, title — in-page navigations included), `"visibility"` (foreground / background), `"hide"` (the page went away) |
| `action` | The user's own (trusted) input: `"tap"` (the element's description), `"input"` (field description and value), `"submit"`, `"scroll"` (where the scrolling came to rest). The value of a password field, a `data-rwd-mask` element or a `maskSelectors` match is stored as `••••`, never in the clear; other values are scrubbed with `maskPatterns` and cut at 200 characters |
| `agent` | The agent's interactive calls and `rwd.evaluate`: method, `ref`, key, url, values, text, and the error if it failed. Reads (snapshots, lists) are left out |
| `control` | Control-state changes with the agent's name ([§4](#4-control-state)) |
| `console` | Every level, with `type`, `text` and `source` |
| `net` | Every finished request: method, url, status, type, duration, size, error. A **failed** one also carries `reqHeaders` / `resHeaders` (redacted as in `rwd.networkDetail`) and `reqBody` / `resBody`, each cut at 64 KB |

Console errors and warnings, failed requests, the user's taps, input and submits, agent actions and control changes are marked important and kept longest. *Problems*, which `problems` and `overview` select, are console errors and failed requests.

**Limits.** The last **3** launches are kept, each within **10 MB**. Over that, the oldest unimportant records (plain console logs, successful requests) are dropped first, then the oldest of all, down to 80% of the cap; `trimmed` counts them. If `navigator.storage.estimate()` reports a quota below 64 MB, only the current launch is kept. Without IndexedDB (some private modes) nothing is recorded and `rwd.log` fails with `internal`.

**Reading it.** `rwd.log` takes an `op`:

```jsonc
// op: "sessions" → every launch still stored, newest first
{"sessions":[{"id","source":"app"|"cookie","startedAt","lastAt","bytes","trimmed",
              "counts":{"page","action","agent","control","console","error","net","netFail"},
              "current":true}]}

// op: "overview", params {"session"?} → one launch at a glance
{"session":{…meta…,"current":true},"first":<ms>,"last":<ms>,
 "pages":[{"at","page","data"}],      // page open / nav records, last 60
 "problems":[…records…]}              // console errors and failed requests, last 20

// op: "records", params {"session"?,"kinds"?:["page","action","agent","control","console","net"],
//                       "problems"?:false,"page"?:"<pageId>","text"?,"after"?:<seq>,
//                       "from"?,"to"?,"limit"?:100,"exclude"?:[],"includeExcluded"?:false}
{"session":"…","records":[{"seq","at","kind","page","data"}],
 "next":<seq>|null,                   // pass as `after` for the next page
 "hidden":0}                          // requests the network exclude rules hid (§11)
```

- `session` defaults to the current launch (`"current"` means the same); an unknown id fails with `not_found`. With no launch recording, the newest stored one is used.
- `problems: true` keeps only console errors and failed requests. `text` is a case-insensitive substring of the record's `data`. `limit` is 1–500, default 100.
- Records come back **without** headers and bodies; `data.hasBody` is `true` where a body exists. `rwd.logDetail` returns that one record in full and needs `advanced` ([§6](#6-access-levels)), like `rwd.networkDetail`.
- The network exclude rules apply here too, so a `net` record the rules match is left out of `records` and counted in `hidden` unless `includeExcluded` is set.

**Turning it off.** `run({ record: false })` keeps a single page from writing. `policy.sessionLog: false` ([§11](#11-project-policy)) reaches pages as `welcome.config.sessionLog` and stops the recording **and deletes the logs already kept for the origin**. `status().logSession` is the session id a page is writing to, or `null` when it is not recording.

## 6. Access levels

| Level | Allowed methods |
|---|---|
| `observe` | `rwd.ping`, `rwd.snapshot`, `rwd.query`, `rwd.screenshot`, `rwd.console`, `rwd.network`, `rwd.waitFor`, `rwd.log` |
| `interact` | `observe` + `rwd.click`, `rwd.fill`, `rwd.type`, `rwd.press`, `rwd.select`, `rwd.hover`, `rwd.scroll`, `rwd.drag`, `rwd.navigate`, `rwd.back`, `rwd.reload` |
| `advanced` | `interact` + `rwd.evaluate`, `rwd.networkDetail`, `rwd.storage`, `rwd.logDetail` |

The level of an attachment is

```
min(level requested by the agent (default interact),
    the API key's maxLevel,
    the merged project policy's maxLevel,
    the level the user picked on the device)
```

Both sides enforce it: the gateway refuses calls above the level (error `forbidden`, audit `policy.denied`), and the SDK checks again against `welcome.level` / `control.level` before running anything. The gateway treats unknown methods as `advanced`. If a gateway sends no level while an agent is attached, the SDK assumes `interact`.

## 7. Attach approval

When an agent calls `connect_device`, the gateway merges the policies of the projects whose pages are open on the device ([§11](#11-project-policy)). If the merged `approval` is `prompt`, the user must approve on the device:

```jsonc
← {"t":"attach_request","requestId":"…",
   "agent":{"name":"Support Bot","keyHint":"…a91f"},
   "levels":["observe","interact"],   // offered levels, capped by key and policy; the last is what the agent asked for
   "expiresInSec":30}
→ {"t":"attach_decision","requestId":"…","level":"interact"}   // or "level": null to deny
← {"t":"attach_cancel","requestId":"…"}                         // timed out, or the agent gave up
```

- The request goes to the device's **foreground page**; `attach_cancel` goes to every page.
- No answer within **30 seconds** counts as a timeout. The MCP call waits for the answer.
- If the same API key is denied **3 times** on the same device within 10 minutes, its requests to that device are refused without asking for **10 minutes**.
- Only one request can be pending per device.
- The SDK's dialog lives in a Shadow DOM, accepts trusted taps only and arms 0.4 s after it appears, so an agent can't approve itself. Same-origin tabs share the decision over BroadcastChannel.
- The user can turn on **auto-allow** with a maximum level in the SDK's floating window; the SDK then answers at once with the highest offered level within it and shows a notice.
- With `run({ nativeApproval: true })` the SDK shows no dialog. Instead `status().pending` becomes `{kind:"attach", requestId, agent:{name, keyHint}, levels, expiresAt}` and the native host answers with `nativeDecide(nativeKey, requestId, level | null)`.
- After approval the gateway attaches the agent (replacing any other agent on the device), clears help (`{"t":"help","on":false}`) and broadcasts `{"t":"control","state":"observe","agent":{…},"level":"interact","attachedMs":0}`; the page locks right away ([§4](#4-control-state)).

With `approval: none` the agent attaches right away at the computed level.

**Coming back without asking again.** An agent that lets go of the device itself — `disconnect_device`, connecting to another device, or `policy.attachMaxMinutes` running out — leaves a grant behind: for **10 minutes** the same API key may attach to that device again with no dialog on the phone, at **no more than the level the user granted before** (so asking for `advanced` after an `observe` approval still gets `observe`). Nothing else is relaxed: the key, the policy and the agent's own request still cap the level, and the device must have a connected page. Such an attachment is audited as `attach.resume` next to the usual `attach.start` ([§12.7](#127-audit-log)), and the page sees the ordinary `control` message, not an `attach_request`.

Coming back does not use the grant up: letting go again starts a fresh 10-minute window. The grant is dropped when the session ends for any other reason: the user taps **End** on the device, a console member ends it (`POST /devices/:id/end`), the API key is revoked, another agent attaches to the device and replaces this one, or the user denies a request. It also expires with the gateway process, since it is kept in memory.

## 8. Sensitive-action confirmation

Before acting, the SDK asks the user when the agent:

- clicks (`rwd.click`) an element that matches `[data-rwd-confirm]` or the policy's `confirmSelectors`, or sits inside one;
- presses Enter (`rwd.press`, or `rwd.type` with `submit: true`) on such an element, or in a form that contains one (not in a textarea or rich-text editor).

The dialog reads like *AI wants to click "Place order". Allow?*, accepts trusted taps only and expires after **30 seconds**. A denial or timeout fails the RPC with `{"code":"forbidden","message":"The user denied this action"}`. Only one confirmation can be open at a time; it is cancelled when the user takes over, the agent leaves or the connection drops.

With `nativeApproval: true`, `status().pending` becomes `{kind:"confirm", requestId, action:'click "Place order"', expiresAt}` and the host answers with `nativeDecide(nativeKey, requestId, "allow" | null)`. A pending confirmation takes precedence over a pending attach request in `status().pending`.

## 9. Presence polling fallback

When the WebSocket fails 3 times in a row, the SDK calls `POST /v1/presence` every 60 seconds instead. It sends `Content-Type: text/plain` with a JSON body, so no CORS preflight is needed; the gateway answers with `Access-Control-Allow-Origin: *`.

```jsonc
// request
{"key":"rwd_pk_…","deviceId":"…","pageId":"…","page":{…},"device":{…},
 "userId":null,"help":false,"deviceToken":"…"}
// response
{"deviceCode":"K7Q2-9M4X","connect":false}
```

- The gateway uses `key`, `deviceId`, `userId`, `device.{ua, platform, app}`, `deviceToken` and `help`; `pageId` and `page` are informational. App key and origin are checked as for the WebSocket, with the same rate limit.
- A device that has been issued a device token ([§3.5](#35-device-token-resume-token-and-invites)) must send it here too; otherwise the call fails with `401 bad_token` and nothing about the device is updated. A device without a token (an older SDK) keeps polling without one.
- `help: true` marks the device as asking for help, as `hello.help` does, unless an agent is already attached.
- A polling device counts as online for 90 seconds after each call.
- `connect: true` tells the page to open the WebSocket now. The gateway sets it when an agent calls `connect_device` or `wait_for_device` for the device.
- As a safety net the SDK also retries the WebSocket on every 5th poll.

## 10. JavaScript API for hosts

The SDK exposes `window.RemoteWebviewDebugger`. Pages call `run()`; native hosts inject the SDK and call `run()` with extra options (see [native-integration.md](native-integration.md)).

```js
RemoteWebviewDebugger.run(gatewayUrl, appKey, {
  userId,                // string | null: the signed-in user, shown to agents and the console
  helpButton,            // show the "Get help" button (OR-ed with the policy's helpButton)
  app,                   // { name, version } of the host app
  lang,                  // a language tag for the phone user's UI; default from navigator.languages (§15)
  locales,               // extra language packs; messages: per-language overrides (§15)
  theme,                 // 'auto' (default) | 'system' | 'light' | 'dark'
  style,                 // colors, fonts, radii, z-index, positions as --rwd-* CSS properties (sdk/README.md)
  lockScreen,            // block input while an agent is attached (default true; the user can change it)
  eruda,                 // true | { dock, load, src, name }: show as a tab inside eruda
  networkExclude,        // requests to keep out of what the agent reads (§11)
  record,                // keep the session log (default true; the policy can turn it off, §5.4)
  // native hosts
  deviceId,              // one id per install, shared by every WebView and domain
  deviceToken,           // the token from status().deviceToken, kept by the host
  launchId,              // this launch of the app, shared by every WebView of the process (§5.4)
  nativeKey,             // a secret only the host knows; enables nativeControl / nativeDecide
  nativeApproval,        // the host shows attach / confirm questions itself
}) // → Promise<{ deviceCode, status }>
```

| Function | Description |
|---|---|
| `run(gatewayUrl, appKey, options?)` | Brings the page online. Resolves once the gateway has answered, or after 8 s with what is known. Calling it again returns the same promise |
| `status()` | `{deviceCode, status, control, help, label, deviceId, pageId, version, lang, deviceToken, level, config, pending, logSession}`. `status` is `idle`, `connecting`, `online`, `polling`, `rejected`, `quota` or `stopped`; `logSession` is the session log this page writes to, `null` when it is not recording ([§5.4](#54-session-log)) |
| `help(on = true)` | Ask for help, or cancel |
| `setUser(userId)` | Change the signed-in user (the SDK reconnects with a new `hello`) |
| `stop()` | Disconnect and remove the UI; console and network capture continue, bounded |
| `nativeControl(nativeKey, 'takeover' \| 'handback' \| 'end')` | The native host's own control buttons. Returns `false` if the key doesn't match |
| `nativeDecide(nativeKey, requestId, value)` | Answer `status().pending`: a level or `null` for `attach`, `'allow'` or `null` for `confirm`. Returns `false` if the key, request or value is wrong |

**Launch id.** Besides `run({ launchId })`, a host may define `window.RWDLaunchId` before the SDK runs: a string, or a function returning a string or a promise of one (awaited for at most 300 ms). It must be 4–128 characters of `[A-Za-z0-9_.:-]`; anything else is ignored and the SDK infers the launch itself ([§5.4](#54-session-log)).

`nativeKey` is written only into the injected script and compared in constant time. Page scripts, including an agent's `evaluate_script`, can't read it, so they can't hand control back or approve themselves.

**Native screenshot bridges.** If the host registers one of these, `rwd.screenshot` uses it for real pixels (video, canvas, cross-origin images and native overlays included). Each returns a PNG or JPEG data URL, or bare base64, of the visible WebView:

| Bridge | Platform |
|---|---|
| `window.RWDNativeScreenshot()` | Any host; returns `string` or `Promise<string>` |
| `webkit.messageHandlers.rwdScreenshot` | iOS / macOS `WKWebView`, registered as a `WKScriptMessageHandlerWithReply`; receives `{type:"screenshot"}` |
| `window.RWDAndroid.screenshot()` | Android, a `@JavascriptInterface` method |

Reference implementation: [`examples/mock-app/Sources/RWDMockApp/RWDNative.swift`](../examples/mock-app/Sources/RWDMockApp/RWDNative.swift).

## 11. Project policy

```ts
type Policy = {
  approval: 'none' | 'prompt'      // prompt: the user approves each attach on the device (default prompt)
  maxLevel: Level                  // highest level for this project (default interact)
  maskSelectors: string[]          // extra CSS selectors to mask (besides password fields and [data-rwd-mask])
  maskPatterns: { name: string; regex: string }[]  // text patterns to mask, e.g. phone or ID numbers (JavaScript regex)
  confirmSelectors: string[]       // clicking these needs the user's OK (besides [data-rwd-confirm])
  networkExclude: string[]         // requests kept out of what agents read (§5.2)
  sessionLog: boolean              // pages keep a session log (default true, §5.4)
  helpButton: 'off' | 'all' | 'listed'   // who sees the "Get help" button (default off)
  helpUsers: string[]              // userIds for helpButton = listed
  agentIdleMinutes: number         // agent → observe after this much inactivity (default 2, max 120)
  attachMaxMinutes: number         // an attachment ends after this long (default 60, max 1440)
  maxOnlineDevices: number         // 0 = unlimited; over it, new devices are closed with 4429
  maxAgents: number                // agents attached at once to this project's devices; 0 = unlimited
  eruda: { dock: boolean; load: boolean }  // remote default for run({ eruda }); local options win field by field.
                                           // In welcome.config it may be null or absent (= both false), §3.4
}
```

- Values are normalized on save: an `approval` other than `none` becomes `prompt`, an invalid `maxLevel` becomes `interact`, numbers are clamped. `maskPatterns` must compile, else `400 bad_policy`. `maskSelectors`, `confirmSelectors`, `networkExclude` and `helpUsers` are trimmed of blank entries and cut at 50 each, `maskPatterns` at 20.
- **`networkExclude`** is the noise an agent should not have to wade through: fonts that always 404, analytics beacons. Each rule is matched against the request URL as a case-insensitive substring, as a `*` wildcard pattern (`*/404/*`), or as a regular expression when it is written `/…/` (with optional flags; the default is `i`). A rule that doesn't compile matches nothing. Matching requests are left out of the network list and of `net_fail` timeline events, but the page still records them, so an agent can ask for them with `includeExcluded` ([§5.2](#52-methods), [§14.3](#143-tools)). They are a convenience, not a privacy control — use `maskSelectors` / `maskPatterns` for data that must not leave the page.
- **`sessionLog`** is on unless it is set to `false`, including for projects saved before the field existed. Turning it off stops every page of the project from recording and deletes the logs already on those devices for that origin; a single page can opt out on its own with `run({ record: false })` ([§5.4](#54-session-log)).
- The masking, confirmation, network-exclude, session-log, help and eruda fields reach pages in `welcome.config` ([§3.4](#34-welcome)); a page's own `run({ networkExclude })` rules are added to the project's.
- **Several projects on one device.** A device is identified by its `deviceId`, not by project: pages loaded with different app keys on the same phone are pages of one device. When an agent attaches, the gateway merges the policies of the projects whose pages are connected, keeping the strictest value: `prompt` if any project asks, the smallest `maxLevel`, `agentIdleMinutes` and `attachMaxMinutes`, and the smallest non-zero `maxAgents`.

## 12. Console REST API

### 12.1 Conventions

- Base path `/v1/api`. Sign in with `POST /auth/login`; the session is an HttpOnly cookie `rwd_session` (12 hours, `SameSite=Lax`, `Secure` over HTTPS). The account is re-read on every request, so disabling or deleting a member takes effect at once.
- Every request other than `GET` / `HEAD` to an endpoint that needs a session must carry `X-RWD-CSRF: 1`, else `403 csrf`.
- Errors are `{"error":{"code":"…","message":"…"}}` with a 4xx/5xx status. Messages follow the request's language ([§15](#15-languages)).
- Common codes: `401 unauthorized` (not signed in), `403 forbidden` (role too low), `403 csrf`, `404 not_found`, `400 bad_request`, `429 rate_limited`, `500 internal`.

Roles: `owner` (everything, including members), `admin` (projects, keys, policies, devices, invites, audit), `member` (read projects and devices, test connections, end sessions, create device invites, read the audit log). In the tables below, *member* means any signed-in account.

### 12.2 Accounts and members

| Method | Path | Role | Request | Response |
|---|---|---|---|---|
| POST | `/auth/login` | — | `{"email","password"}` | `{"ok":true}` and the cookie. `401 bad_password`; `429 rate_limited` after 10 attempts per minute per IP. An empty `email` means `admin` |
| POST | `/auth/logout` | — | — | `{"ok":true}` |
| GET | `/me` | member | — | `Member` |
| POST | `/me/password` | member | `{"oldPassword","newPassword"}` | `{"ok":true}`. The new password must be 8–256 characters; `400 bad_password` if the old one is wrong |
| GET | `/config` | — | — | `{"gatewayUrl","version","sdkVersion","sdkIntegrity"}` |
| GET | `/members` | admin | — | `{"members":[Member]}` |
| POST | `/members` | owner | `{"email","name","role"}` | `Member & {"inviteUrl":"https://<host>/invite/<token>"}` (valid for 7 days, once). `409 conflict` if the email exists |
| PATCH | `/members/:id` | owner | `{"name"?,"role"?,"disabled"?}` | `Member`. `409 last_owner` if no active owner would be left |
| DELETE | `/members/:id` | owner | — | `{"ok":true}`. `409 self`, `409 last_owner` |
| GET | `/invites/:token` | — | — | `{"email","name"}` |
| POST | `/invites/:token/accept` | — | `{"password","name"?}` | `{"ok":true}` and signs in. Rate-limited like login |

The first owner is created at startup from `RWD_ADMIN_EMAIL` (default `admin`) and `RWD_ADMIN_PASSWORD` (see [gateway/README.md](../gateway/README.md)). The console page `/invite/:token` accepts a member invite.

### 12.7 Audit log

`GET /audit?project=&device=<device code>&actor=&action=&from=&to=&limit=50&before=<id>` (member) → `{"events":[AuditEvent],"nextBefore":<id>|null}`, newest first. `limit` ≤ 200; `action` is a prefix match (`attach.` matches every attach event); `actor` matches an actor id or name.

| Action | When |
|---|---|
| `auth.login`, `auth.login_failed` | Console sign-in |
| `member.invite`, `member.accept`, `member.update`, `member.delete` | Member management |
| `project.create`, `project.update`, `project.delete`, `project.rotate_app_key` | Projects |
| `key.create`, `key.revoke` | API keys |
| `invite.create`, `invite.delete`, `invite.use` | Device invites |
| `attach.request`, `attach.approve`, `attach.deny`, `attach.timeout`, `attach.resume`, `attach.start`, `attach.end` | Agent attachments. `attach.resume` means the key came back within the grace period instead of asking again ([§7](#7-attach-approval)); `detail: {level}` |

Events never contain page content or parameter values. They are kept for 180 days by default (`RWD_AUDIT_RETENTION_DAYS`).

### 12.9 Timeline events

Each device keeps its last 300 timeline events in memory; the console shows the latest 100, MCP the latest 50 by default.

| `kind` | Meaning |
|---|---|
| `opened` / `closed` | A page connected for the first time / disappeared after its grace period ([§3.1](#31-lifecycle)) |
| `navigated` / `reloaded` | A page moved to a new URL / reconnected at the same URL |
| `focus` | A page came to the foreground |
| `error` / `console_error` / `net_fail` / `user_tap` | Events reported by the page ([§3.2](#32-page--gateway)) |
| `help` | The user asked for help or cancelled, or arrived through an invite |
| `agent` | Attach requests, denials, timeouts, attachments, task changes |
| `control` | Control state changes; the summary gives the reason (user took over, AI idle, user ended, …) |
| `offline` | The device's last page went away while an agent was attached |

## 13. Live updates (SSE)

`GET /v1/api/stream[?project=<id>][&lang=<tag>]` (member, cookie auth) streams `text/event-stream`:

```
retry: 3000

event: device     data: Device                               a device changed (online, help, control, approval, task…)
event: timeline   data: {"deviceId", "event": TimelineEvent}
event: ping       data: {}                                   every 25 s
```

Without `project`, events of every project are streamed. `EventSource` can't set headers, so the language goes in `?lang=`. A slow subscriber misses events rather than holding up the gateway; the console re-fetches when it reconnects and falls back to polling if the stream fails.

## 14. MCP

### 14.1 Sessions

- Endpoint `/v1/mcp` (Streamable HTTP). Every request must carry `Authorization: Bearer <API key>`. The key is checked on every request, so a revoked or expired key, or an address outside its `ipAllowlist`, gets 401 at once.
- The gateway keeps one agent state per API key: the attached device and the selected page. MCP sessions that use the same key share it. An agent is attached to at most one device at a time; connecting to another device detaches it from the first. A key reaches every device on the gateway.
- More than 5 failed device lookups per minute with one key are refused for the rest of the minute, which stops device codes from being guessed.

### 14.2 Results

Every tool result ends with what changed on the device since the agent's previous call (at most 20 lines), so the agent notices new pages, navigations, errors and takeovers without polling:

```
[Session changes]
- p3 "Checkout" opened (opened by p2)
- p3 TypeError: Cannot read properties of undefined (reading 'orderId')
- The user took over
```

Content that comes from the page (snapshots, console, network, storage, evaluate results, timeline) is wrapped in a tag and labelled as untrusted data, so the agent doesn't follow instructions found in it.

## 15. Languages

Supported languages: English (`en`), Simplified Chinese (`zh`), Traditional Chinese (`zh-TW`), French (`fr`), Spanish (`es`), Russian (`ru`), Arabic (`ar`, right to left), Japanese (`ja`), Korean (`ko`), German (`de`) and Portuguese (`pt`). Any BCP 47 tag is accepted and maps to the closest one: `en-US` → `en`; `zh-CN`, `zh_CN`, `zh-Hans` → `zh`; `zh-HK`, `zh-MO`, `zh-Hant` → `zh-TW`; `fr-CA` → `fr`; `pt-BR`, `pt-PT` → `pt`. `Accept-Language` picks the supported language with the highest weight.

| Audience | What | Chosen by |
|---|---|---|
| Agent | MCP server instructions, tool and parameter descriptions, tool results, `[Session changes]`, errors | The gateway's `RWD_LANG` / `--lang` (default `en`) |
| Agent, from the page | RPC error messages and event summaries written by the SDK | `welcome.agentLang`, which carries the gateway's language. The SDK keeps the last value in localStorage `rwd:alang` for events raised before the next `welcome`, and uses English until it hears otherwise |
| Console | Error messages, timeline summaries and system labels in REST and SSE responses | `?lang=` on the request, then `Accept-Language`, then the gateway's language |
| Phone user | The SDK's pill, bars, dialogs and notices | `run({ lang })`, else the first of `navigator.languages` the SDK has a pack for (built-in or registered by the page), else English. Packs other than `en` and `zh` load on demand from `locales/<id>.js` next to `sdk.js`, or from the gateway (`/v1/locales/<id>.js`) |

So a Chinese-speaking user can work with an English-speaking agent: the dialog says *AI 想要点击「提交订单」，允许吗？* and, if refused, the agent reads *The user denied this action*.

## 16. Operations

- **Metrics.** `GET /v1/metrics` returns Prometheus text. With `RWD_METRICS_TOKEN` set it requires `Authorization: Bearer <token>`. Series: `rwd_online_devices{project}`, `rwd_connected_pages`, `rwd_attached_agents`, `rwd_ws_connections`, `rwd_rpc_total{method,result}`, `rwd_rpc_duration_seconds{method}` (histogram), `rwd_http_requests_total{code}`.
- **SDK versions.** The SDK version used for caching is the first 12 hex characters of the SHA-256 of the `sdk.js` embedded in the gateway, so `/v1/sdk/<version>/sdk.js` changes whenever the file does. `GET /v1/api/config` returns it as `sdkVersion`, together with `sdkIntegrity` (`sha384-…`, for the `integrity` attribute). The console offers a snippet that pins it.
- **Database.** `RWD_DATABASE_URL=postgres://…` (or `postgresql://`) selects Postgres; otherwise `RWD_DATA` (default `rwd.db`) is a SQLite file. The schema is created and migrated at startup.
- **Rate limits.** Console sign-in and invite acceptance: 10 per minute per client IP. Page connections and presence calls: 120 per minute per client IP. Client IPs come from `X-Forwarded-For` only with `--trust-proxy`; the same switch governs `X-Forwarded-Proto` and `X-Forwarded-Host`, which decide whether the session cookie is `Secure` and the scheme and host of the inferred `gatewayUrl` when `--public-url` is unset.
- **Audit retention.** `RWD_AUDIT_RETENTION_DAYS` (default 180); old events are purged every 6 hours.

All gateway settings are listed in [gateway/README.md](../gateway/README.md).

# Архитектура

Remote WebView Debugger позволяет ИИ-агенту изучать веб-страницу, открытую на чужом телефоне, и работать с ней: H5-страницу в мобильном браузере или суперприложении либо WebView внутри вашего собственного приложения. Агент общается по MCP с шлюзом, развёрнутым на вашем сервере; шлюз — с небольшим SDK, работающим внутри страницы. Пользователь телефона одобряет подключение, видит, что делает агент, и может в любой момент взять управление.

В этом документе описаны составные части системы и правила, по которым они работают. Точные сообщения и эндпоинты — в [protocol.ru.md](protocol.ru.md); интеграция с приложением — в [native-integration.ru.md](native-integration.ru.md); развёртывание — в [gateway/README.ru.md](../gateway/README.ru.md) и [deploy/platform/README.ru.md](../deploy/platform/README.ru.md).

## Компоненты

```

        │  MCP: Streamable HTTP + Bearer API key
        │  (or stdio through the `rwd mcp` bridge)
        ▼
┌──────────────────────────── Gateway (one Go binary) ────────────────────────────┐
│  /v1/mcp      MCP tools ─────┐                                                  │
│  /v1/api      REST + SSE ────┼──▶ hub: devices, pages, control state, approvals,│
│  /v1/page     page WebSocket ┘        timelines, RPC routing   (in memory)      │
│  /v1/sdk.js   embedded page SDK      store: SQLite or Postgres (persistent)     │
│  /            embedded web console                                              │
└───────────▲──────────────────────────────────────────────▲──────────────────────┘
            │ HTTPS, cookie session                        │ WebSocket (wss://…/v1/page)
       Web console                                         │ POST /v1/presence as a fallback
       (support staff, admins)                             │
                                  ┌──────────── phone ─────┴────────────────────┐
                                  │  H5 page / App WebView                      │
                                  │    page SDK: link to the gateway, UI        │
                                  │      (pill, dialogs, lock) in a Shadow DOM  │
                                  │    engine: snapshots, actions, console and  │
                                  │      network capture, masking, levels       │
                                  │  native host (optional): injects the SDK,   │
                                  │    real screenshots, native dialogs/buttons │
                                  └─────────────────────────────────────────────┘
```

| Компонент | Путь | Роль |
|---|---|---|
| Шлюз | [`gateway/`](../gateway) | Сервер на Go. Принимает подключения страниц, держит живое состояние устройств в памяти, обслуживает MCP-эндпоинт, REST API веб-консоли и её обновления в реальном времени, ведёт журнал аудита. Веб-консоль и SDK встроены в него, так что весь сервер — это один бинарный файл |
| SDK страницы | [`sdk/`](../sdk) | `sdk.js`, который загружает страница или внедряет приложение. Отвечает за соединение, идентификацию, интерфейс на странице, диалоги согласия и блокировку экрана |
| Движок | [`packages/chobitsu/src/engine/`](../packages/chobitsu/src/engine) | Часть каждого действия агента, выполняемая на стороне страницы: снимки доступности (код aria snapshot из Playwright) и слои, перекрывающие страницу, проверки готовности элемента к действию и синтетический ввод, перехват console и сетевых запросов (на основе [chobitsu](https://github.com/liriliri/chobitsu)), скриншоты, маскирование, проверка уровней доступа |
| Веб-консоль | [`console/`](../console) | Одностраничное приложение на React: проекты и фрагменты кода для интеграции, устройства и их хронологии, API-ключи, участники, политики, приглашения, журнал аудита |
| Нативный хост | ваше приложение; эталонная реализация — в [`examples/mock-app`](../examples/mock-app) | Внедряет SDK в каждый WebView в начале загрузки документа, хранит идентификатор и токен устройства, делает настоящие скриншоты и, при желании, показывает нативные диалоги одобрения и кнопки |

## Сеанс отладки

1. **Страница выходит в сеть.** Страница загружает `sdk.js` (или приложение его внедряет). Перехват console, ошибок и сетевых запросов начинается сразу, в буферы ограниченного размера, поэтому агент, подключившийся позже, всё равно видит, что происходило до него. `run()` открывает WebSocket к шлюзу и отправляет `hello`; шлюз отвечает **кодом устройства** (например, `K7Q2-9M4X`) и удалённой конфигурацией проекта. Плашка на странице показывает этот код.
2. **Кто-то направляет агента на устройство.** Пользователь диктует код устройства, нажимает **Попросить помощь** (устройство тогда показывается первым во всех списках) или открывает **ссылку-приглашение** от поддержки — устройство выходит в сеть уже с запросом помощи.
3. **Агент подключается.** Он вызывает `connect_device` с кодом. Если в проекте не настроено иначе, пользователь видит на телефоне *ИИ хочет подключиться* и выбирает уровень доступа (только просмотр, просмотр и управление, расширенный) или отказывает. До этого ничего прочитать нельзя. Как только агент подключён, экран блокируется от ввода пользователя, края светятся, а нижняя панель показывает, сколько длится подключение.
4. **Агент работает.** Он делает снимок, чтобы получить ссылки (ref) на элементы, и затем кликает, заполняет поля и прокручивает по ref. В снимке перечислены и всплывающие окна и подложки, перекрывающие страницу, — у каждой свой ref, — а клик, который перекрыт каким-то слоем, завершается ошибкой с названием и ref того, что мешает. Поэтому агент может нажать на подложку, чтобы закрыть всплывающее окно, а не гадать. Первое же действие агента переводит устройство из режима *observe* в *agent*, а курсор агента показывает, где он действует. В зависимости от уровня доступа агент может также читать console, сетевые запросы, хранилище и скриншоты.
5. **Решает пользователь.** **Перехватить** возвращает страницу пользователю и приостанавливает агента (его действия завершаются ошибкой `takeover`, пока пользователь не нажмёт **Вернуть ИИ**). **Завершить** отключает агента. Клики по элементам, помеченным как чувствительные (оформить заказ, оплатить, удалить), требуют подтверждения пользователя на телефоне.
6. **Агент уходит** через `disconnect_device`; после двух минут без действий устройство возвращается в режим *observe*, а по истечении максимального времени подключения, заданного в проекте (по умолчанию 60 минут), агент отключается.

Одно действие от начала до конца:

```
agent ─ click(ref=e12) ─▶ MCP handler
   gateway: API key valid? → attached? → level ≥ interact? → user hasn't taken over?
            observe (screen locked) → agent → RPC {"method":"rwd.click","params":{"ref":"e12"}}
   ─── WebSocket ──▶ SDK: level ≥ interact? not taken over? sensitive element → ask the user
                     engine: wait until visible, stable, enabled, hit-testable (≤ 5 s)
                             move the agent cursor, highlight, dispatch pointer/mouse/touch events
   ◀── {"id":…, "result":{}} ───
   gateway: audit "rpc" (method, page, latency; no payload)
agent ◀─ "Clicked e12 (page p2)." + [Session changes] (new pages, navigations, errors, takeovers)
```

Каждое действие — это один обмен сообщениями: проверки готовности элемента и отправка событий выполняются внутри страницы, а не по сети.

## Устройства, страницы и агенты

**Устройство.** Один `deviceId`: один профиль браузера или одна установка приложения, если нативный хост передаёт собственный идентификатор. Шлюз присваивает каждому устройству постоянный код устройства. Устройства не привязаны к проектам: телефон, открывающий страницы из двух проектов (с двумя ключами приложения), — это одно устройство со страницами из обоих. API-ключи тоже не привязаны к проектам, поэтому один MCP-сервер даёт доступ ко всем устройствам.

**Страница.** Одна вкладка или один WebView; она определяется по `pageId`, который сохраняется при перезагрузках и переходах в этой вкладке. Шлюз нумерует страницы каждого устройства как `p1`, `p2`, …, запоминает, какая страница какую открыла, и отслеживает, какая из них сейчас на переднем плане. Отключившаяся страница сохраняет свою метку две минуты — этого хватает, чтобы переподключиться после перехода, — но не в том случае, когда тот же документ появляется снова в другом месте: WebView, пересозданный с новым `pageId`, сразу заменяет старую запись, а отключённая страница, URL которой показывает другая подключённая страница, удаляется через 1,5 с. Так пересозданный WebView не оставляет «призрака» в списке страниц, а агент переходит на ту страницу, которая действительно существует.

**Хронология.** У каждого устройства есть хронология (в памяти, последние 300 событий): открытие, переходы, перезагрузка, получение фокуса и закрытие страниц; ошибки, неудачные запросы и нажатия пользователя; запросы помощи, одобрения и смены управления. В конце результата каждого MCP-инструмента приводятся записи хронологии, которых агент ещё не видел, поэтому он замечает новые страницы, ошибки и перехват управления без опроса. В **режиме следования** (по умолчанию) выбранная агентом страница переключается на ту, которую открыло его действие, или на ту, на которую перешёл пользователь.

**Агент.** Шлюз хранит одно состояние агента на каждый API-ключ: устройство, к которому он подключён, и выбранную страницу. Агент одновременно подключён только к одному устройству, а у устройства не больше одного агента; вновь одобренный агент заменяет предыдущего.

**Состояние управления.** Каждое устройство находится в одном из четырёх состояний; его определяет шлюз и рассылает всем страницам устройства:

```
                 agent attaches                first interactive action
       ┌──────┐ ───────────────▶ ┌─────────┐ ─────────────────────────▶ ┌───────┐
       │ none │                  │ observe │                            │ agent │
       └──────┘ ◀─────────────── └─────────┘ ◀───────────────────────── └───────┘
           ▲     agent leaves,        │        idle (default 2 min)        │
           │     End, time limit      │ Take over                Take over │
           │                          ▼                                    ▼
           │                        ┌──────┐ ◀─────────────────────────────┘
           └─────────── End ─────── │ user │ ────── Hand back ──────▶ agent
                                    └──────┘
```

В состояниях `observe` и `agent` ввод пользователя заблокирован (пользователь может снять блокировку в плавающем окне); в `user` агент по-прежнему может читать, но любой интерактивный вызов завершается ошибкой `takeover`, и агент может вызвать `wait_for_control`, чтобы дождаться возврата управления.

## Согласие и конфиденциальность

Главное правило: **наличия API-ключа или знания кода устройства никогда не достаточно, чтобы увидеть страницу пользователя.** Между агентом и страницей стоит несколько независимых проверок.

| Уровень защиты | Что делает |
|---|---|
| API-ключ | Передаётся в каждом MCP-запросе. У ключа есть максимальный уровень доступа, срок действия (по умолчанию 90 дней) и необязательный список разрешённых IP; отзыв ключа немедленно отключает его агента. Неудачные поиски устройства ограничены по частоте, чтобы коды устройств нельзя было подобрать |
| Код устройства | Только *идентифицирует* устройство. Никаких прав он не даёт |
| Политика проекта | `approval: prompt` (по умолчанию для новых проектов) требует одобрения пользователя; `maxLevel` ограничивает то, что может делать любой агент. Если на устройстве открыты страницы из нескольких проектов, действует самая строгая политика |
| Одобрение пользователя | Телефон показывает имя агента, подсказку ключа и доступные уровни; пользователь выбирает один из них или отказывает. Диалог находится в Shadow DOM и реагирует только на настоящие (доверенные) нажатия, поэтому агент не может одобрить себя сам. После трёх отказов этот ключ блокируется для устройства на 10 минут. Пользователь может включить автоматическое разрешение на своём устройстве. Агент, который сам отпустил устройство (отключился, переключился на другое устройство, исчерпал время подключения), может вернуться в течение 10 минут без нового диалога — с уровнем не выше того, что пользователь дал ранее; нажатие пользователем **Завершить**, завершение сеанса участником в веб-консоли, отказ или отзыв ключа это право сбрасывают |
| Уровни доступа | `observe` (снимок, скриншот, console, список сетевых запросов), `interact` (+ клик, ввод текста, прокрутка, навигация…), `advanced` (+ выполнение JavaScript, тела запросов, хранилище). Фактический уровень — минимум из запрошенного агентом, уровня ключа, политики и выбора пользователя. **SDK проверяет его ещё раз внутри страницы**, независимо от шлюза |
| Видимое управление | Пока агент подключён, страница это показывает: плашка с состоянием агента, карточка задачи с его планом, курсор агента и подсветка при каждом действии, светящаяся рамка, пока он действует. «Перехватить», «Вернуть ИИ» и «Завершить» реагируют только на нажатия пользователя; нативный хост должен предъявить секрет (`nativeKey`), который не могут прочитать скрипты страницы, в том числе скрипты самого агента |
| Чувствительные действия | Клик по элементу с пометкой `data-rwd-confirm` (или подходящему под `confirmSelectors` из политики) либо отправка формы, которая содержит такой элемент, ждёт подтверждения пользователя на телефоне |
| Маскирование | Поля паролей, элементы `data-rwd-mask`, а также селекторы и текстовые шаблоны из политики (номера телефонов, карт, документов…) заменяются на `••••` **внутри страницы**, до того как что-либо покинет устройство: в снимках, скриншотах, тексте console, URL и телах сетевых запросов, значениях хранилища и сводках хронологии. Заголовки `Cookie`, `Set-Cookie` и `Authorization` скрываются всегда. Правила `networkExclude` в политике — другое: они лишь убирают шум (шрифты, которые всегда отдают 404, аналитические маячки) из списков, которые читает агент, а агент может запросить скрытые запросы, поэтому средством защиты конфиденциальности они не являются |
| Недоверенный контент | Содержимое страницы, передаваемое агенту, оборачивается и помечается как недоверенные данные, чтобы подброшенные на страницу инструкции не принимались за слова пользователя. Рискованные клики опираются на подтверждение пользователя, а не на суждение агента |
| Журнал сеанса | Записывается на устройстве и никуда не транслируется: для чтения нужен уровень `observe`, как и для любого другого чтения, а для заголовков и тел неудачных запросов — `advanced`. Правила маскирования применяются при записи, так что значение замаскированного поля хранится как `••••`, а не маскируется потом. Проект может отключить журнал и удалить уже сохранённое |
| Аудит | Входы в систему, изменения ключей и участников, запросы на подключение и решения по ним, каждый RPC (метод, страница, задержка, результат), перехваты управления и завершения сеансов пользователем, отклонённые вызовы. Никогда — содержимое страниц или значения параметров |

Что покидает телефон: метаданные устройства в `hello` (user agent, `userId`, если страница его передаёт, название и версия приложения, URL и заголовки страниц) и короткие сводки хронологии — с момента вызова `run()`; всё остальное — только по запросу подключённого агента. Шлюз не хранит содержимое страниц: снимки, скриншоты и логи проходят к агенту транзитом, а хронологии живут в памяти. Журнал сеанса записывается на устройстве по тем же правилам маскирования и остаётся там, пока его не прочитает подключённый агент (см. **Хранение данных** ниже).

Известные ограничения, о которых стоит сказать прямо:

- Ввод синтетический: у событий `isTrusted: false`, и страницы, которые это проверяют, на них не реагируют.
- `interact` позволяет агенту перейти на любой URL `http(s)`; он не ограничен origin-ами проекта.
- `advanced` выполняет в странице произвольный JavaScript. Маскирование не может применяться к тому, что возвращает такой скрипт, поэтому оставляйте `maxLevel` на уровне `interact`, если это не нужно.
- Перехват сети охватывает запросы, которые страница делает из JavaScript после загрузки SDK (fetch, XHR, WebSocket, sendBeacon, EventSource). Изображения, скрипты, таблицы стилей и запросы из нативного кода не видны. Содержимое iframe в снимки не входит.
- Когда приложение уходит в фон, ОС приостанавливает его WebView, и устройство остаётся офлайн, пока приложение не вернётся.
- Точки останова, пошаговое выполнение, профилирование и снимки кучи не поддерживаются; для них используйте Safari Web Inspector или `chrome://inspect` с отлаживаемым WebView.

## Хранение данных

По умолчанию шлюз использует **SQLite** (чистый Go, без CGO; файл задаётся `RWD_DATA`) или **Postgres**, если `RWD_DATABASE_URL` — это URL вида `postgres://`. Схема создаётся и мигрируется при запуске.

| Постоянно (база данных) | Только в памяти (теряется при перезапуске) |
|---|---|
| Проекты и их политики, ключи приложений | Подключённые страницы и их метки |
| Участники (пароли в виде PBKDF2-SHA256), ожидающие приглашения участников | Состояние управления, ожидающие одобрения, подключённые агенты |
| API-ключи (хеши HMAC-SHA256, уровни, сроки действия, списки разрешённых IP) | Хронологии устройств |
| Известные устройства: id, код, userId, user agent, приложение, первое и последнее появление, хеш токена устройства | Счётчики ограничения частоты |
| Приглашения устройств (хеши токенов), журнал аудита | |
| Настройки: «перец» для ключей и секрет для подписи сессий, генерируются при первом запуске | |

После перезапуска страницы переподключаются сами (SDK повторяет попытки с нарастающей задержкой) и сохраняют свои коды устройств; агенты подключаются заново. Живое состояние находится в одном процессе, поэтому запускайте **один экземпляр шлюза** на одну базу данных.

**На телефоне, а не на шлюзе.** Одно хранилище намеренно стоит в стороне от всего этого: **журнал сеанса**, который SDK страницы пишет в IndexedDB на устройстве (база `rwd-log`). С момента запуска приложения он фиксирует посещённые страницы, нажатия и ввод пользователя, действия агента, смены управления, вывод console и каждый запрос — неудачные вместе с заголовками и телами, — независимо от того, доступен ли шлюз. Именно это позволяет агенту, подключившемуся *после* бага, прочитать весь путь к нему, а не начинать с пустого буфера. Хранятся три последних запуска, до 10 МБ каждый, и ничего из этого не попадает ни на шлюз, ни к кому-либо ещё, пока подключённый агент сам не запросит это через `get_session_overview` / `get_session_log` ([protocol.ru.md §5.4](protocol.ru.md#54-журнал-сеанса)). Проект может отключить журнал (`policy.sessionLog`) — при этом удаляется и то, что уже сохранено на его устройствах, — а отдельная страница может отказаться от записи с помощью `run({ record: false })`.

## Безопасность: заметки для администраторов

- **Используйте HTTPS.** Страницы подключаются по `wss://`, cookie веб-консоли при HTTPS помечается как `Secure`, а API-ключи передаются в заголовках. Конфигурация Docker Compose в [deploy/platform](../deploy/platform/README.ru.md) завершает TLS в Caddy или работает за вашим собственным прокси.
- **Доверяйте пересылаемым заголовкам только за прокси.** С `--trust-proxy` шлюз берёт IP клиентов и свой публичный хост из `X-Forwarded-For` / `X-Forwarded-Host`. Без прокси перед шлюзом их может подделать кто угодно и обойти списки разрешённых IP и ограничения частоты.
- **Защищайте базу данных и её резервные копии.** В них хранятся «перец» для ключей и секрет сессий; с ними хеши API-ключей можно проверять офлайн, а сессии веб-консоли — подделывать.
- **Пароль владельца.** `RWD_ADMIN_PASSWORD` сбрасывает пароль владельца при каждом запуске, что заодно служит способом восстановления доступа. Если на новой базе данных переменная не задана, случайный пароль один раз выводится в лог.
- **Ключи приложений публичны.** Они лишь позволяют страницам выходить в сеть. Используйте `allowedOrigins`, чтобы другие сайты не могли пользоваться вашим ключом; учтите, что `Origin` — заголовок, который контролирует браузер, а небраузерные клиенты могут отправить что угодно, поэтому существующие устройства защищают токены устройств, а не ключи приложений.
- **Обращайтесь с API-ключами как с паролями.** Выдавайте каждому агенту или человеку собственный ключ с минимально достаточным уровнем доступа, сроком действия и, для серверов, списком разрешённых IP. Отзыв действует немедленно.
- **Закрепляйте версию SDK.** Для H5-страниц веб-консоль предлагает фрагмент кода, который загружает SDK по адресу, зависящему от содержимого, с Subresource Integrity. Нативные приложения могут встраивать `sdk.js` в сборку, а не скачивать его во время работы, — тогда скомпрометированный шлюз не сможет подсунуть им новый код.
- **Защищайте метрики.** Задайте `RWD_METRICS_TOKEN`, если `/v1/metrics` доступен извне.
- Вход в веб-консоль ограничен по частоте (10 попыток в минуту с одного IP), запросы на запись требуют специального заголовка CSRF, а веб-консоль нельзя встроить во фрейм.

# アーキテクチャ

Remote WebView Debugger は、他人のスマートフォンで開かれている Web ページを AI エージェントが調べ、操作できるようにします。対象はモバイルブラウザやスーパーアプリ内の H5 ページ、あるいは自社アプリ内の WebView です。エージェントはセルフホストのゲートウェイと MCP で通信し、ゲートウェイはページ内で動く小さな SDK と通信します。端末のユーザーは接続を承認し、エージェントの操作を見ることができ、いつでも引き継げます。

このドキュメントでは、構成要素とそれらが従うルールを説明します。メッセージとエンドポイントの詳細は [protocol.ja.md](protocol.ja.md)、アプリへの組み込みは [native-integration.ja.md](native-integration.ja.md)、デプロイは [gateway/README.ja.md](../gateway/README.ja.md) と [deploy/platform/README.ja.md](../deploy/platform/README.ja.md) にあります。

## 構成要素

```
  AI agent (Claude Code, Cursor, any MCP client)
        │  MCP: Streamable HTTP + Bearer API key
        │  (or stdio through the `rwd mcp` bridge)
        ▼
┌──────────────────────────── Gateway (one Go binary) ────────────────────────────┐
│  /v1/mcp      MCP tools ─────┐                                                  │
│  /v1/api      REST + SSE ────┼──▶ hub: devices, pages, control state, approvals,│
│  /v1/page     page WebSocket ┘        timelines, RPC routing   (in memory)      │
│  /v1/sdk.js   embedded page SDK      store: SQLite or Postgres (persistent)     │
│  /            embedded web console                                              │
└───────────▲──────────────────────────────────────────────▲──────────────────────┘
            │ HTTPS, cookie session                        │ WebSocket (wss://…/v1/page)
       Web console                                         │ POST /v1/presence as a fallback
       (support staff, admins)                             │
                                  ┌──────────── phone ─────┴────────────────────┐
                                  │  H5 page / App WebView                      │
                                  │    page SDK: link to the gateway, UI        │
                                  │      (pill, dialogs, lock) in a Shadow DOM  │
                                  │    engine: snapshots, actions, console and  │
                                  │      network capture, masking, levels       │
                                  │  native host (optional): injects the SDK,   │
                                  │    real screenshots, native dialogs/buttons │
                                  └─────────────────────────────────────────────┘
```

| 構成要素 | パス | 役割 |
|---|---|---|
| ゲートウェイ | [`gateway/`](../gateway) | Go 製のサーバー。ページからの接続を受け付け、デバイスのライブ状態をメモリに保持し、ホスト型の MCP エンドポイント、管理コンソール用の REST API とリアルタイム更新を提供し、監査ログを記録します。管理コンソールと SDK を埋め込んでいるため、バイナリ 1 つでサーバー全体になります |
| ページ SDK | [`sdk/`](../sdk) | ページが読み込む、またはアプリが注入する `sdk.js`。接続、識別情報、ページ内 UI、同意ダイアログ、画面ロックを担当します |
| エンジン | [`packages/chobitsu/src/engine/`](../packages/chobitsu/src/engine) | あらゆるエージェント操作のページ側の半分：アクセシビリティスナップショット（Playwright の aria snapshot のコード）とその上に浮かぶレイヤー、操作可能性のチェックと合成入力、console とネットワークの取得（[chobitsu](https://github.com/liriliri/chobitsu) を土台に構築）、スクリーンショット、マスキング、レベルのチェック |
| 管理コンソール | [`console/`](../console) | React のシングルページアプリ：プロジェクトと組み込み用スニペット、デバイスとそのタイムライン、API キー、メンバー、ポリシー、招待、監査ログ |
| ネイティブホスト | 自社アプリ。参考実装は [`examples/mock-app`](../examples/mock-app) | ドキュメント開始時にすべての WebView へ SDK を注入し、デバイス ID とトークンを保持し、実際のスクリーンショットと、必要に応じてネイティブの承認ダイアログやボタンを提供します |

## デバッグセッションの流れ

1. **ページがオンラインになる。** ページが `sdk.js` を読み込みます（またはアプリが注入します）。console、エラー、ネットワークの取得は上限付きのバッファですぐに始まるため、後から接続したエージェントもそれ以前に起きたことを確認できます。`run()` はゲートウェイへの WebSocket を開いて `hello` を送り、ゲートウェイはデバイスの**デバイスコード**（例：`K7Q2-9M4X`）とプロジェクトのリモート設定を返します。ページ上のピルにそのコードが表示されます。
2. **誰かがエージェントにデバイスを伝える。** ユーザーがデバイスコードを読み上げるか、**ヘルプを求める** をタップする（そのデバイスはすべての一覧で先頭に表示されます）か、サポートから送られた**招待リンク**を開きます。招待リンクから開くと、デバイスは最初からヘルプ要請中の状態でオンラインになります。
3. **エージェントが接続する。** エージェントはコードを指定して `connect_device` を呼びます。プロジェクトで別の設定をしていない限り、端末には *AI が参加を求めています* と表示され、ユーザーはレベル（閲覧のみ、閲覧と操作、高度）を選ぶか拒否します。それまでは何も読み取れません。エージェントが接続すると、画面はユーザーの入力に対してロックされ、画面の縁が光り、下部バーに接続時間が表示されます。
4. **エージェントが作業する。** スナップショットを取得して要素 ref を得てから、ref を指定してクリック、入力、スクロールを行います。スナップショットにはページの上に浮かぶポップアップや背景幕もそれぞれ ref 付きで列挙され、レイヤーに遮られたクリックは、遮った要素の名前と ref を添えて失敗します。そのためエージェントは推測に頼らず、背景幕をタップしてポップアップを閉じられます。最初の操作でデバイスは *observe* から *agent* に切り替わり、エージェントのカーソルが操作位置を示します。レベルに応じて、console、ネットワーク、ストレージ、スクリーンショットも読み取れます。
5. **主導権はユーザーにある。** **引き継ぐ** でページはユーザーに戻り、エージェントは一時停止します（ユーザーが **AI に戻す** をタップするまで、エージェントの操作は `takeover` で失敗します）。**終了** でエージェントは切り離されます。センシティブとしてマークされた要素（注文確定、支払い、削除）のクリックには、端末上でのユーザーの許可が必要です。
6. **エージェントが離れる。** `disconnect_device` で離れるほか、操作がないまま 2 分経つとデバイスは *observe* に戻り、プロジェクトの最大接続時間（デフォルトは 60 分）を過ぎるとエージェントは切り離されます。

1 つの操作をエンドツーエンドで見ると：

```
agent ─ click(ref=e12) ─▶ MCP handler
   gateway: API key valid? → attached? → level ≥ interact? → user hasn't taken over?
            observe (screen locked) → agent → RPC {"method":"rwd.click","params":{"ref":"e12"}}
   ─── WebSocket ──▶ SDK: level ≥ interact? not taken over? sensitive element → ask the user
                     engine: wait until visible, stable, enabled, hit-testable (≤ 5 s)
                             move the agent cursor, highlight, dispatch pointer/mouse/touch events
   ◀── {"id":…, "result":{}} ───
   gateway: audit "rpc" (method, page, latency; no payload)
agent ◀─ "Clicked e12 (page p2)." + [Session changes] (new pages, navigations, errors, takeovers)
```

各操作は 1 往復で完結します。操作可能性のチェックとイベントの送出はネットワーク越しではなく、ページ内で実行されます。

## デバイス、ページ、エージェント

**デバイス。** 1 つの `deviceId` です。1 つのブラウザプロファイル、またはネイティブホストが独自の ID を渡す場合はアプリの 1 インストールに相当します。ゲートウェイは各デバイスに永続的なデバイスコードを割り当てます。デバイスはプロジェクトに紐付きません。2 つのプロジェクト（2 つのアプリキー）のページを開いたスマートフォンは、両方のページを持つ 1 台のデバイスです。API キーもプロジェクトに紐付かないため、1 つの MCP サーバーですべてのデバイスに届きます。

**ページ。** 1 つのタブまたは WebView で、そのタブ内のリロードや遷移をまたいで維持される `pageId` で識別されます。ゲートウェイはデバイスごとにページを `p1`、`p2`、… とラベル付けし、どのページがどのページを開いたかを記録し、どのページが前面にあるかを追跡します。切断されたページは、遷移後の再接続に間に合うよう 2 分間ラベルを保持します。ただし、同じドキュメントが別の場所に再び現れた場合は例外です。新しい `pageId` で作り直された WebView は古いエントリを即座に置き換え、切断されたページの URL を接続中の別のページも表示している場合、切断されたページは 1.5 秒後に削除されます。これにより、作り直された WebView がページ一覧に幽霊のように残ることはなく、エージェントは実際に存在するページへ移されます。

**タイムライン。** 各デバイスはタイムライン（メモリ上、直近 300 件のイベント）を持ちます。ページのオープン、遷移、リロード、フォーカス、クローズ、エラー、失敗したリクエスト、ユーザーのタップ、ヘルプ要請、承認、制御状態の変化が記録されます。すべての MCP ツールの結果の末尾には、エージェントがまだ見ていないタイムラインのエントリが付くため、エージェントはポーリングせずに新しいページ、エラー、引き継ぎに気付けます。**追従モード**（デフォルト）では、エージェントの操作で開いたページや、ユーザーが切り替えたページに、エージェントの選択ページが移ります。

**エージェント。** ゲートウェイは API キーごとに 1 つのエージェント状態を保持します。接続先のデバイスと選択中のページです。エージェントが同時に接続できるデバイスは 1 台で、1 台のデバイスに接続できるエージェントも最大 1 つです。新たに承認されたエージェントは前のエージェントを置き換えます。

**制御状態。** 各デバイスは 4 つの状態のいずれかにあります。状態はゲートウェイが決定し、そのデバイスのすべてのページに通知します：

```
                 agent attaches                first interactive action
       ┌──────┐ ───────────────▶ ┌─────────┐ ─────────────────────────▶ ┌───────┐
       │ none │                  │ observe │                            │ agent │
       └──────┘ ◀─────────────── └─────────┘ ◀───────────────────────── └───────┘
           ▲     agent leaves,        │        idle (default 2 min)        │
           │     End, time limit      │ Take over                Take over │
           │                          ▼                                    ▼
           │                        ┌──────┐ ◀─────────────────────────────┘
           └─────────── End ─────── │ user │ ────── Hand back ──────▶ agent
                                    └──────┘
```

`observe` と `agent` ではユーザーの入力がブロックされます（ユーザーはフローティングウィンドウでロックを解除できます）。`user` ではエージェントは読み取りはできますが、操作系の呼び出しはすべて `takeover` で失敗します。エージェントは `wait_for_control` を呼んで、主導権が戻るのを待てます。

## 同意とプライバシー

基本原則：**API キーを持っていても、デバイスコードを知っていても、それだけではユーザーのページは決して見られません。** エージェントとページの間には、互いに独立した複数のチェックがあります。

| レイヤー | 役割 |
|---|---|
| API キー | すべての MCP リクエストに付与されます。キーには最大レベル、有効期限（デフォルトは 90 日）、任意の IP 許可リストがあり、失効させると、そのキーのエージェントは即座に切り離されます。デバイスの検索失敗にはレート制限がかかるため、デバイスコードを推測することはできません |
| デバイスコード | デバイスを*識別*するだけで、何の権限も与えません |
| プロジェクトのポリシー | `approval: prompt`（新規プロジェクトのデフォルト）ではユーザーの承認が必要です。`maxLevel` はあらゆるエージェントにできることの上限を決めます。デバイスが複数のプロジェクトのページを持つ場合は、最も厳しいポリシーが適用されます |
| ユーザーの承認 | 端末にはエージェントの名前、キーのヒント、選択可能なレベルが表示され、ユーザーはいずれかを選ぶか拒否します。ダイアログは Shadow DOM 内にあり、実際の（信頼された）タップにしか反応しないため、エージェントが自分自身を承認することはできません。3 回拒否されると、そのキーはそのデバイスから 10 分間締め出されます。ユーザーは自分のデバイスで自動許可を選ぶこともできます。エージェントが自らデバイスを離れた場合（切断、デバイスの切り替え、接続時間の使い切り）、10 分以内であれば、以前ユーザーが許可したレベルを上限として、新たなダイアログなしに戻れます。ユーザーが **終了** をタップした場合、管理コンソールのメンバーがセッションを終了した場合、拒否された場合、キーが失効した場合は、この扱いは取り消されます |
| レベル | `observe`（スナップショット、スクリーンショット、console、ネットワーク一覧）、`interact`（＋クリック、入力、スクロール、ナビゲーション…）、`advanced`（＋JavaScript の実行、リクエストのボディ、ストレージ）。実効レベルは、エージェントが要求したレベル、キー、ポリシー、ユーザーの選択のうち最も低いものです。**SDK はゲートウェイとは独立して、ページ内でもう一度これを強制します** |
| 目に見える主導権 | エージェントが接続している間、ページにはそれが表示されます：エージェントの状態を示すピル、計画を示すタスクカード、すべての操作でのエージェントのカーソルとハイライト、操作中に光る画面の縁。引き継ぐ、AI に戻す、終了はユーザーのタップにしか反応しません。ネイティブホストは、ページのスクリプト（エージェント自身のスクリプトを含む）からは読めないシークレット（`nativeKey`）を提示する必要があります |
| センシティブな操作 | `data-rwd-confirm` が付いた要素（またはポリシーの `confirmSelectors` に一致する要素）のクリックや、そうした要素を含むフォームの送信は、端末上でのユーザーの許可を待ちます |
| マスキング | パスワード欄、`data-rwd-mask` 要素、ポリシーのセレクターとテキストパターン（電話番号、カード番号、ID 番号…）は、何かが端末から送られる前に**ページ内で** `••••` に置き換えられます。対象はスナップショット、スクリーンショット、console のテキスト、ネットワークの URL とボディ、ストレージの値、タイムラインの要約です。`Cookie`、`Set-Cookie`、`Authorization` ヘッダーは常に伏せられます。ポリシーの `networkExclude` ルールは別物で、ノイズ（常に 404 になるフォント、解析用ビーコン）をエージェントが読む一覧から除外するだけです。エージェントは隠されたリクエストを要求することもできるので、プライバシーを守る仕組みではありません |
| 信頼できないコンテンツ | エージェントに渡すページの内容は、信頼できないデータとして包んでラベル付けされるため、ページに仕込まれた指示がユーザーの指示と取り違えられることはありません。リスクの高いクリックは、エージェントの判断ではなくユーザーの確認に委ねられます |
| セッションログ | 端末上に記録され、どこにもストリーミングされません。読み取りには他の読み取りと同様に `observe` が、失敗したリクエストのヘッダーとボディには `advanced` が必要です。マスキングのルールは記録時に適用されるため、マスク対象の値は後からマスクされるのではなく `••••` として保存されます。プロジェクトはログを無効にし、保存済みの内容を削除させることができます |
| 監査 | ログイン、キーとメンバーの変更、接続要求とその判断、すべての RPC（メソッド、ページ、レイテンシ、結果）、ユーザーによる引き継ぎと終了、拒否された呼び出し。ページの内容やパラメーターの値は決して記録しません |

端末から送られるもの：`run()` が呼ばれた時点から、`hello` に含まれるデバイスのメタデータ（ユーザーエージェント、ページが提供する場合は `userId`、アプリ名とバージョン、ページの URL とタイトル）と、タイムラインの短い要約が送られます。それ以外は、接続中のエージェントが要求したときにだけ送られます。ゲートウェイはページの内容を保存しません。スナップショット、スクリーンショット、ログはエージェントへそのまま中継され、タイムラインはメモリ上にあります。セッションログは同じマスキングルールのもとで端末上に記録され、接続中のエージェントが読むまで端末に留まります（後述の**ストレージ**を参照）。

はっきり述べておくべき既知の制限：

- 入力は合成されたものです。イベントは `isTrusted: false` で、これをチェックするページは反応しません。
- `interact` ではエージェントは任意の `http(s)` URL に遷移できます。プロジェクトのオリジンには限定されません。
- `advanced` ではページ内で任意の JavaScript を実行できます。そうしたスクリプトが返す値にはマスキングが適用できないため、必要がない限り `maxLevel` は `interact` にしておいてください。
- ネットワークの取得対象は、SDK の読み込み後にページが JavaScript から行うリクエスト（fetch、XHR、WebSocket、sendBeacon、EventSource）です。画像、スクリプト、スタイルシート、ネイティブコードが行うリクエストは見えません。iframe 内のコンテンツはスナップショットに含まれません。
- アプリがバックグラウンドに回ると OS が WebView を一時停止するため、デバイスは復帰するまでオフラインになります。
- ブレークポイント、ステップ実行、プロファイリング、ヒープスナップショットは対象外です。これらには Safari Web Inspector か、デバッグ可能な WebView と `chrome://inspect` を使ってください。

## ストレージ

ゲートウェイはデフォルトで **SQLite**（純粋な Go、CGO 不要。ファイルは `RWD_DATA` で指定）を使い、`RWD_DATABASE_URL` が `postgres://` の URL の場合は **Postgres** を使います。スキーマは起動時に作成・マイグレーションされます。

| 永続（データベース） | メモリのみ（再起動で消える） |
|---|---|
| プロジェクトとそのポリシー、アプリキー | 接続中のページとそのラベル |
| メンバー（パスワードは PBKDF2-SHA256）、保留中のメンバー招待 | 制御状態、保留中の承認、接続中のエージェント |
| API キー（HMAC-SHA256 ハッシュ、レベル、有効期限、IP 許可リスト） | デバイスのタイムライン |
| 既知のデバイス：ID、コード、userId、ユーザーエージェント、アプリ、初回と最終の接続日時、デバイストークンのハッシュ | レート制限のカウンター |
| デバイスの招待（トークンのハッシュ）、監査ログ | |
| 設定：初回起動時に生成されるキーの pepper とセッション署名用のシークレット | |

再起動後、ページは自動的に再接続し（SDK がバックオフ付きで再試行します）、デバイスコードも維持されます。エージェントは改めて接続します。ライブ状態は 1 つのプロセス内にあるため、1 つのデータベースにつき**ゲートウェイのインスタンスは 1 つ**だけ動かしてください。

**ゲートウェイではなく端末上に。** ここまでのすべてから意図的に外れている保存先が 1 つあります。ページ SDK が端末の IndexedDB（データベース `rwd-log`）に書き込む**セッションログ**です。アプリの起動時から、訪れたページ、ユーザーのタップと入力、エージェントの操作、制御状態の変化、console の出力、そしてすべてのリクエスト（失敗したものはヘッダーとボディも）を、ゲートウェイに到達できるかどうかに関係なく記録します。これにより、バグが起きた*後*に接続したエージェントも、空のバッファから始めるのではなく、バグに至るまでの経緯をすべて読めます。直近 3 回の起動分を、それぞれ最大 10 MB まで保持します。接続中のエージェントが `get_session_overview` / `get_session_log` で要求しない限り（[protocol.ja.md §5.4](protocol.ja.md#54-セッションログ)）、その内容がゲートウェイや他の誰かに届くことはありません。プロジェクトはこれを無効にでき（`policy.sessionLog`）、その場合は端末に保存済みの内容も削除されます。個々のページは `run({ record: false })` で記録を止められます。

## 運用者向けのセキュリティ上の注意

- **HTTPS で提供してください。** ページは `wss://` で接続し、管理コンソールの Cookie は HTTPS では `Secure` が付き、API キーはヘッダーで送られます。[deploy/platform](../deploy/platform/README.ja.md) の Docker Compose 構成は、Caddy で TLS を終端するか、自前のプロキシの背後に置きます。
- **転送ヘッダーはプロキシの背後でのみ信頼してください。** `--trust-proxy` を指定すると、ゲートウェイはクライアント IP と自身の公開ホストを `X-Forwarded-For` / `X-Forwarded-Host` から取得します。前段にプロキシがなければ、誰でもこれを偽造して IP 許可リストやレート制限を回避できてしまいます。
- **データベースとそのバックアップを保護してください。** キーの pepper とセッションのシークレットが含まれており、これらがあれば API キーのハッシュをオフラインで照合したり、管理コンソールのセッションを偽造したりできます。
- **オーナーのパスワード。** `RWD_ADMIN_PASSWORD` は起動のたびにオーナーのパスワードをリセットするため、アカウント復旧の手段にもなります。新しいデータベースでこれが未設定の場合は、ランダムなパスワードがログに一度だけ出力されます。
- **アプリキーは公開情報です。** ページをオンラインにすることしかできません。`allowedOrigins` を使えば、他のサイトにあなたのアプリキーを使われるのを防げます。ただし `Origin` はブラウザが強制するヘッダーで、ブラウザ以外のクライアントは任意の値を送れます。既存のデバイスを守るのが（アプリキーではなく）デバイストークンなのはそのためです。
- **API キーはパスワードと同様に扱ってください。** エージェントや人ごとに専用のキーを発行し、機能する範囲で最も低いレベル、有効期限、そしてサーバー用には IP 許可リストを設定してください。失効は即座に反映されます。
- **SDK を固定してください。** H5 ページ向けに、管理コンソールはサブリソース完全性（SRI）付きでコンテンツアドレス方式の SDK URL を読み込むスニペットを提供しています。ネイティブアプリは実行時にダウンロードする代わりに `sdk.js` を同梱できるため、ゲートウェイが侵害されても新しいコードを送り込まれることはありません。
- **メトリクスを保護してください。** `/v1/metrics` に外部からアクセスできる場合は `RWD_METRICS_TOKEN` を設定してください。
- 管理コンソールのサインインにはレート制限（IP ごとに 1 分あたり 10 回）があり、書き込みリクエストには独自の CSRF ヘッダーが必要で、管理コンソールはフレーム内に埋め込めません。

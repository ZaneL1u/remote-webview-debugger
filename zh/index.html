03agent 能做什么

你熟悉的 DevTools 那一套，通过 MCP 用在别人的手机上

  • 无障碍快照

    Playwright 风格的 YAML，元素带 ref。agent 按结构理解页面，而不是盯着像素，再用 ref 精确操作。

  • 真实的交互

    点击、填写、输入、按键、下拉选择、悬停、滚动、拖拽，带可操作性检查，React、Vue 的受控组件也认。

  • console 与网络

    从页面加载起就记录在有上限的缓冲里，agent 接入之前的报错也查得到；需要时还能看请求和响应正文。

  • 跨页面会话

    列表页 → 详情页 → 结算页，或者新开的 WebView，同一台设备的所有页面组成一个会话，带跨页面时间线。

  • 变化自动推送

    每个工具结果末尾都会附上发生了什么：新页面、跳转、报错、用户接管。agent 不用轮询。

  • 手机上的任务卡片

    agent 把计划和进度显示在设备顶部，用户随时知道 AI 在做什么、做到哪一步。

  • 截图

    App 提供原生截图桥时是真实像素，否则用 DOM 重绘。两种方式都会遮盖敏感信息。

  • 设备端会话日志

    从 App 启动起，页面、点击、console 和每个请求都冷存在手机的 IndexedDB 里，事后也能回看。

  • 热修补丁

    advanced 级别下，agent 可以用 evaluate_script 给运行中的页面打补丁，当场验证修复。

  • 弱网也能用

    轻量心跳加指数退避；连续 3 次失败后改为每分钟轮询一次，需要时由网关唤醒页面。

  • 11 种语言

    手机端界面、控制台和 agent 看到的文字都有 11 种语言，含从右到左的阿拉伯语。也支持自定义语言包和措辞。

  • 任意 MCP 客户端

    /v1/mcp 是 Streamable HTTP，Claude Code、Codex、Cursor 直接可用；只支持 stdio 的客户端用一个很小的桥接命令。

04亮点

专为那些“只在用户那里出现”的 bug 而生

数据线、远程调试端口和录屏都给不了的三样东西。

会话日志 · 冷存在设备端

bug 已经发生过了？日志还在手机里。

从 App 启动那一刻起，SDK 就把会话日志写进设备的 IndexedDB：访问过的页面、用户的点击和输入、console 输出、每一个请求——失败的请求连请求头和正文一起留下。这些数据不会流向任何地方；它们按同样的遮盖规则留在手机上，直到用户批准的 agent 用 get_session_overview 和 get_session_log 来读。保留最近 3 次启动，每次最多 10 MB。

热修补丁 · evaluate_script

上线之前，先在用户手机上验证修复。

用户授予 advanced 级别后，evaluate_script 直接在页面里运行——agent 可以纠正错误的状态、覆盖一个函数、重新渲染视图，然后在真实设备上看结果：一个用来证明诊断的热修补丁。它只存在于那个页面的内存里，不会持久化；敏感点击仍然需要用户点头。

05隐私与控制

用户的手机，始终由用户做主

远程调试的前提是信任。每一次接入都看得见、要确认、能随时打断。

  • 先确认，再接入

    agent 申请接入时，用户在手机上看到是谁、要什么权限，自己选择级别。只认真实的点击，脚本没法替用户点「允许」。

  • 随时接管或结束

    AI 操作时页面边缘亮起光圈，用户输入被锁定。点一下「接管」AI 立刻暂停，点「结束」直接断开。

  • 默认遮盖敏感信息

    密码框和带 data-rwd-mask 的内容，在快照、截图、console、网络数据和会话日志里都显示为 ••••。还可以按项目配置选择器和正则。

  • 敏感操作要用户点头

    给「提交订单」「注销账号」这类按钮加上 data-rwd-confirm，agent 每次点击前都要用户确认。

  • 权限分级

    observe 只看，interact 可操作，advanced 还能执行脚本、读请求正文和存储。按 API Key 和项目分别设上限。

  • 审计日志

    每次接入、审批、RPC 调用和接管都会记录谁、做了什么、什么时候——但不记录页面内容和参数值。

  • observe快照、截图、console、网络列表、会话日志、查找元素、等待
  • interact+ 点击、填写、输入、按键、选择、悬停、滚动、拖拽、跳转
  • advanced+ evaluate_script（热修补丁）、请求 / 响应正文、存储

06App 原生接入

在 App 里，就是一个注入脚本

下载一次 SDK，在页面开始加载时注入：iOS 用 WKUserScript，Android 用 addDocumentStartJavaScript。网页本身一行都不用改。

  • 一台手机一个设备码

    传入固定的 deviceId（并保存 deviceToken），设备码跨 WebView、跨域名都不变。

  • 原生控制按钮

    用 nativeControl() 做自己的接管 / 交还 / 结束按钮，页面脚本调用不了。

  • 原生审批弹窗

    nativeApproval: true 把接入审批和敏感操作确认交给 App 自己的界面。

  • 真实像素截图

    一个很小的桥（WKWebView 快照、Android 位图），agent 拿到的是真实画面而不是 DOM 重绘。

RemoteDebugger.swift
import WebKit

/// 在 webView.load(…) 之前调用：下载一次 SDK，在 documentStart 注入。
func installRemoteDebugger(into controller: WKUserContentController,
                           userId: String?, done: @escaping () -> Void) {
    let gateway = "https://rwd.example.com/v1"
    URLSession.shared.dataTask(with: URL(string: gateway + "/sdk.js")!) { data, _, _ in
        DispatchQueue.main.async {
            defer { done() }
            guard let data, let sdk = String(data: data, encoding: .utf8) else { return }
            let options: [String: Any] = [
                "deviceId": stableDeviceId, // 存在 UserDefaults 里的 UUID
                "userId": userId ?? NSNull(),
                "helpButton": true,
            ]
            let json = String(data: try! JSONSerialization.data(withJSONObject: options), encoding: .utf8)!
            let boot = sdk + "\n;RemoteWebviewDebugger.run(\"\(gateway)\", \"rwd_pk_…\", \(json));"
            controller.addUserScript(WKUserScript(source: boot,
                                                  injectionTime: .atDocumentStart,
                                                  forMainFrameOnly: true))
        }
    }.resume()
}
RemoteDebugger.kt
// 依赖：androidx.webkit:webkit:1.12.0；需开启 javaScriptEnabled 和 domStorageEnabled
// 在 webView.loadUrl(…) 之前调用
fun installRemoteDebugger(webView: WebView, userId: String?, onReady: () -> Unit) = thread {
    val gateway = "https://rwd.example.com/v1"
    val sdk = runCatching { URL("$gateway/sdk.js").readText() }.getOrNull()
    webView.post {
        if (sdk != null && WebViewFeature.isFeatureSupported(WebViewFeature.DOCUMENT_START_SCRIPT)) {
            val options = JSONObject()
                .put("deviceId", stableDeviceId) // 存在 SharedPreferences 里的 UUID
                .put("userId", userId ?: JSONObject.NULL)
                .put("helpButton", true)
            val boot = "$sdk\n;RemoteWebviewDebugger.run(${JSONObject.quote(gateway)}, \"rwd_pk_…\", $options);"
            WebViewCompat.addDocumentStartJavaScript(webView, boot, setOf("https://m.example.com"))
        }
        onReady()
    }
}

07自建部署

一个 Go 二进制，部署在你自己的服务器上

网关内嵌了 Web 控制台和页面 SDK。默认用 SQLite，需要时换成 Postgres；Docker Compose 加 Caddy 负责 HTTPS。

  • 控制台

    设备、API Key、成员与角色、扫码邀请、安全策略、审计日志，还有一份填好你自己 Key 的接入指南。

  • 数据库

    默认是一个 SQLite 文件；设置 RWD_DATABASE_URL=postgres://… 即可改用 Postgres。

  • 运维

    /v1/metrics 提供 Prometheus 指标，SDK 有带版本号和 SRI 校验的地址，/v1/healthz 用于健康检查。

部署说明

快速开始
# 一个容器：控制台 + 网关 + SDK
docker run -d --name rwd -p 8080:8080 -v rwd-data:/data \
  -e RWD_ADMIN_PASSWORD='change-me' \
  ghcr.io/zanel1u/remote-webview-debugger:latest

# 或者自己构建、上传，由 Caddy 提供 HTTPS
git clone https://github.com/ZaneL1u/remote-webview-debugger
RWD_DOMAIN=rwd.example.com \
  remote-webview-debugger/deploy/platform/deploy.sh you@your-server amd64
# → 控制台  https://rwd.example.com
# → 网关    https://rwd.example.com/v1（MCP 在 /v1/mcp）

服务器上只需要 Docker；从源码构建需要 Go 和 Node。

08常见问题

大家常问的问题

用户需要安装什么吗？

不需要。H5 页面里 SDK 就是页面的一部分；App 里由原生代码注入。用户只会看到一个显示设备码的小胶囊，以及 agent 申请接入时的确认框。

agent 能看到什么、做什么？

只限用户批准的范围：这台设备上的 WebView 页面，按授予的权限级别。WebView 之外的 App 界面和系统一概碰不到。遮盖的字段始终是遮盖的，页面内容也会作为不可信数据交给模型。

bug 在 agent 接入之前就发生了，还查得到吗？

查得到。SDK 从 App 启动起就在设备上记录会话日志——页面、点击、console 和请求——之后接入的 agent 用 get_session_log 就能把通往 bug 的整条路径读出来。除此之外，日志不会离开手机。

agent 能直接在手机上把 bug 修好吗？

它能验证修复：在 advanced 级别下，evaluate_script 在内存里给运行中的页面打补丁——纠正状态、覆盖函数、重新渲染——agent 就能看到问题是否消失。真正的修复仍然走你正常的发布流程；设备上不会持久化任何东西。

支持哪些 agent？

任何 MCP 客户端。Claude Code、Codex、Cursor 直接连托管的 Streamable HTTP 地址；只支持 stdio 的客户端用 rwd mcp，它只是把 stdio 转发到同一个地址。

支持哪些平台？

主流的移动端 WebView 和浏览器都可以：iOS 的 WKWebView、Android System WebView、各类 App 内置浏览器，以及手机上的 Safari、Chrome。桌面浏览器也能用。

网络差或者 WebSocket 被拦截怎么办？

页面只维持一条轻量的心跳 WebSocket，断开后指数退避重连。连续 3 次连不上，就改成每分钟轮询一次；agent 要接入时，网关会通知它立即重连。

会拖慢页面吗？

只是一个脚本。console 和网络记录放在有上限的环形缓冲里（各 500 条，响应正文总共不超过 5MB），会话日志在后台写入，空闲时连接上只有心跳。

能和 eruda、vConsole、PageSpy 一起用吗？

可以。快照和命中测试会跳过它们的节点，SDK 自己的流量也不会出现在它们的网络面板里，甚至可以作为一个 tab 收进 eruda。

SDK 是真实的，没有任何改动；只有网关是在你浏览器里模拟的。一个 WebSocket 垫片通过 postMessage 把 SDK 的连接转给它，再由脚本化的 agent 发出和真实网关一样的 RPC。想完整体验真实链路，可以用你自己的 agent 试一次。
